# 300 英雄交互表现

- Canonical Path: `mods/THK95Mod/docs/03_英雄/300_交互表现.md`
- Document Type: PRD / Module Interaction UX
- Upstream: `200_基本系统/00_索引.md`

## 1. UX 目标

- 让玩家看清英雄的 tag、文武韬与五维性格，做出笼络、任用与流放的判断。
- 避免玩家忽略 tag 重合带来的关系关联与结党风险。

## 2. 入口与信息架构

- 入口：势力面板的英雄列表，或地图上的英雄标记。
- 页面结构：英雄详情卡，含 tag、三能力条、五维性格图、关系列表。
- 回看入口：英雄列表常驻可查。

## 3. 核心操作路径

- 路径 A：打开英雄详情 → 查看 tag 与能力 → 笼络 → 确认 → 查看关系变化。
- 路径 B：查看官职槽 → 选英雄 → 任用 → 确认总文武韬重算。

## 4. 关键流程时序

1. 选中英雄 → 详情卡展开。
2. 查看 tag 与性格 → 判断关系与任用。
3. 笼络或任用 → 结果反馈。

异常时序：流放确认 → 弹出同派系关系下降预警 → 确认或取消。

## 5. 关键节点信息需求

- tag 与能力必须前置显示。
- 五维性格对关系与忠诚的影响必须可见。
- 同派系关联必须提示，避免流放引发连锁反应。

## 6. 提示、警示与阻断反馈

- 普通提示：英雄能力成长、关系进度。
- 风险警示：流放引发结党连锁、笼络失败风险。
- 硬阻断：官位已满时任命置灰。

## 7. 状态反馈与可回看性

- 执行中：笼络进度、英雄移动在列表可见。
- 完成后：能力成长、关系变化在日志留痕。
- 历史记录：登场、流放、叛变事件写入日志。

## 9. 验收关注点

- 玩家能否数秒内读懂英雄的 tag 与能力。
- 流放的连锁风险是否在确认前充分暴露。
