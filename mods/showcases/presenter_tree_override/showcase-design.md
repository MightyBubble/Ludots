# 外观树与覆盖演示（presenter_tree_override）

## 1 概述

同一个外观定义摆多份，每一份能单独挪位置、换颜色、换部件、多挂一个挂件；车动起来，挂在上面的东西不掉队。

给谁看：要用外观树（presenter children）和地图摆放搭场景的作者。他们不读 `PresenterEntityRuntime`，只想知道“我在这一处写的覆盖，画面认不认”。

启动：`launch presenter_tree_override_showcase --adapter raylib`（预设 `presenter_tree_override_showcase_raylib`）。不需要操作，镜头会自己逐站巡游。

## 2 结构

场景在一块 64×44 米的地面上，镜头从南往北斜俯视（yaw 180），分三排：

| 位置 | 内容 | 覆盖的案例 |
|------|------|------------|
| 远处一排（画面上方） | A1–A5 五个静止展台 | 一棵树成套出现、位姿覆盖、参数覆盖、换子树、单份加吸附 |
| 中间 | 两辆绕圈的巡逻车、一个乘客、一个挥剑的骑士 | B1 吸附、B3 吸附叠覆盖、C1 车动时子物体保留覆盖、D1 地图整组件覆盖、D6 上下车、B2 骨骼挂载 |
| 近处一排（画面下方） | 两座营地、三座信号塔 | D2 按路径给模板子件写标题、D4 批量摆放的参数覆盖 |

程序集只做配置表达不了的三件事，其余全部是 assets 数据：

- `PresenterTreeOrbitMotionSystem`：按 `PresenterTreeOrbitMotion` 组件让车绕圈，放在输入收集组，挂载同步读到的是当帧车位。
- `PresenterTreeRiderShuttleSystem`：按地图 metadata 的时间表，用 `AttachmentOps.Attach / Detach` 让乘客上下车。
- `PresenterTreeCameraTourSystem`：按地图 metadata 的 `cameraTour`，镜头依次停在全景和 9 个站点，每站 5 秒，只在换站那一帧发一次姿态请求。

## 3 详情

### 3.1 每个展台看什么

每个展台都是“左边原版，右边这一份改过”，两份用的是同一个定义，画面差异只来自这一处写的覆盖。

| 展台 | 左边（原版） | 右边（这一份的改动） | 写在哪 |
|------|--------------|----------------------|--------|
| A1 整棵树一起出现 | — | 房子、熔炉、旗子同时出现；熔炉缩小挪到房子右前方，旗子在左边 | `ptree.a1.root` 的 children |
| A2 右灯柱放大挪位 | 0.7 倍小灯柱 | 1.4 倍，离得更开 | children 条目的 `overrides.transform` |
| A3 右水晶改成红色 | 蓝色（定义默认参数） | 红色 | children 条目的 `overrides.params` |
| A4 右塔换了塔顶 | 塔顶是球 | 塔顶换成红旗 | `childrenMode: Instance` + `instanceChildren` |
| A5 右宝珠多个吸附 | 宝珠贴着底座 | 宝珠飘在底座上方 1.5 米 | children 条目的 `instanceBehaviors` |
| D1 第二辆换了轨道 | 内圈半径 4.5 米、14 秒一圈 | 外圈半径 8.5 米、10 秒一圈 | 地图摆放的 `Overrides.PresenterTreeOrbitMotion` |
| D2 两座营地 | 北营指挥帐 | 港口指挥帐 | 地图摆放的 `overridePaths[{path: "hq", entityInfo}]` |
| D4 三座信号塔 | 同一个模板 | 红、绿、蓝 | 地图摆放的 `PresenterParamOverrides` |

巡逻车上的挂件：

- 车顶黄灯（B1）：灯定义自带吸附，偏移 [0, 1.55, 0]。
- 车尾红灯（B3）：同一个灯定义，在这一处多写了位姿覆盖 [-1.2, 0, 0] 和红色参数。位姿覆盖叠在吸附结果之后，沿车头朝向转。
- 两面小旗（C1）：位姿覆盖 [-0.6, 0, ±0.85]，缩放 0.8。

### 3.2 解释层

- 每个展台头顶一行世界文字，写案例编号和一句话。文字来自摆放上的 `entityInfo.titleToken`。
- D2 帐篷上的标题由 `overridePaths` 写进模板子件，所以这行字本身就是 D2 的证据。
- 颜色约定：定义默认值用冷色（蓝、灰），这一份的覆盖用暖色（红、橙），挂件和灯用黄、红。

### 3.3 旋钮

全部是数据，改了重启即可：

| 旋钮 | 位置 | 回答什么问题 |
|------|------|--------------|
| `PresenterTreeOrbitMotion.RadiusCm` / `PeriodSeconds` | 模板或地图摆放 | 车更快、弯更急时，挂件跟不跟得上 |
| `riderBoardAtSeconds` / `riderAlightAtSeconds` / `riderAlightRadiusCm` | 地图 `Metadata.presenterTreeShowcase` | 什么时候上下车、下车散多远 |
| `cameraTour.stopSeconds` / `stops[]` | 同上 | 镜头每站停多久、停在哪 |
| `PresenterParamOverrides` 颜色 | 地图摆放 | 同一个模板能不能每座不同色 |

## 4 场景

镜头巡游顺序：全景 → A1 → A2 → A3 → A4 → A5 → 巡逻车 → 骑士 → 营地 → 信号塔 → 回到全景。

- 全景：三排一屏看全，认识场地。
- 静止展台：近景 9 米，左右对照一眼看出差别。
- 巡逻车：17 米俯视，能看到车转弯时旗和两盏灯的位置；乘客 2–8 秒在车上，8 秒后落到车旁。
- 骑士：7 米近景，剑跟着右手骨骼动。
- 营地、信号塔：18–19 米，一屏看全同模板的几份。

## 5 边界

本演示顺带暴露的使用门槛和问题，按处理状态列出：

| 现象 | 状态 |
|------|------|
| 父节点移动时，子物体的位姿覆盖和锚点偏移丢失（C1） | 已修 |
| 吸附结果整个覆写掉子物体的位姿覆盖（B3） | 已修 |
| 写了 `boneId` 没写 `target` 时静默按挂父节点处理（B2） | 已修，改为加载报错 |
| `instanceChildren` / `instanceBehaviors` 的冲突校验漏查 | 已修 |
| 静止父节点（带 `PresentationStaticTransform`）下，子定义自带的吸附偏移不生效，名牌贴在地上（S1） | 修复中 |
| A1 熔炉（`InstancedStaticMesh`）丢了位姿覆盖（S2） | 修复中 |
| 不配本地座位（`startupLocalSeats` + 地图 `Players`）时，Raylib 实机不做可见性裁剪，画面里一个外观都不画，也不报错 | 使用门槛，待评估是否该报错 |
| 模板子件没有 `WorldPositionCm` 时不会有画面变换组件，`SourceHasVisualTransform` 条件把它静默跳过，子件不出外观 | 使用门槛，待评估是否该报错 |
| 走批量摆放路径（D4 的 `PresenterParamOverrides` 只能走这条）时模板必须自带 `WorldPositionCm`，于是 `PositionXCm` 不生效，坐标只能写在 `Overrides.WorldPositionCm` | 使用门槛 |
| 骑士身体的渲染路径写成 `SkinnedMesh` 时，身体按静止姿势画、不播动画，挂在手骨上的剑却跟着动画走，剑看起来离了手，也不报错。只有 `GpuSkinnedInstance` 会让身体播动画，本演示用它 | 待评估：`SkinnedMesh` 配了动画时该报错还是补上动画 |
| 软件渲染（llvmpipe）下，场景里有 `GpuSkinnedInstance` 时整帧 3D 画面全黑，只剩名牌文字 | 环境限制；沙箱截图时临时把骑士改成 `SkinnedMesh`，所以截图里剑不在手上，B2 以自动化验收为准 |
| 大块地面只按属主中心参与裁剪，近景时会被整块裁掉；核心层没有数据入口声明包围盒 | 本演示把地面拆成 12 块绕开 |
| 地图上给某一座建筑里的某个外观子物体单独覆盖（E1）、按路径增删子件（D3）、`attach:false` 的独立实体（D5）、骨骼按名字引用 | 后续 |

## 6 UAT

```gherkin
功能: 同一个定义摆多份，这一份单独改

  场景: 一棵树成套出现
    假如 镜头停在 A1 展台
    那么 我同时看到房子、熔炉和旗子
    而且 熔炉比房子小，站在房子右前方，旗子在房子左边
    而且 头顶飘着“A1 整棵树一起出现”

  场景: 同一个灯柱，右边那根更大
    假如 镜头停在 A2 展台
    那么 左边那根矮小，右边那根明显更高更粗，而且离得更开

  场景: 同一个水晶，只有这一颗是红的
    假如 镜头停在 A3 展台
    那么 左边那颗是蓝的，右边那颗是红的

  场景: 同一座塔，这一座换了塔顶
    假如 镜头停在 A4 展台
    那么 左边塔顶是一个球，右边塔顶换成了一面红旗

  场景: 同一个宝珠，这一颗飘在上面
    假如 镜头停在 A5 展台
    那么 左边的宝珠贴着底座，右边的宝珠飘在右边底座上方

功能: 东西动起来，挂件不掉队

  场景: 巡逻车上的小旗和灯
    假如 镜头停在巡逻车上方
    当 内圈巡逻车绕圈转弯
    那么 两面小旗一直插在车尾左右两角，大小不变
    而且 黄灯一直在车顶，红灯一直在车尾，两盏灯不重叠

  场景: 第二辆车换了轨道
    假如 两辆车来自同一个模板
    那么 第二辆车跑外圈，一圈比第一辆短

  场景: 剑挂在骑士右手上
    假如 镜头停在骑士面前
    那么 骑士原地转身挥剑，剑一直握在右手里

  场景: 乘客上车、散开下车
    假如 乘客站在场地中间
    当 到了上车时间
    那么 乘客出现在内圈巡逻车上，跟着车走
    当 到了下车时间
    那么 乘客落在车旁，不再跟车

功能: 地图摆放上的覆盖

  场景: 两座营地，帐篷名字不同
    假如 镜头停在营地
    那么 北营地的帐篷上写着“北营指挥帐”，港口营地的帐篷上写着“港口指挥帐”

  场景: 三座信号塔，颜色各不相同
    假如 镜头停在信号塔
    那么 我看到红、绿、蓝三座塔

  场景: 静止物体的名牌也飘在头顶
    假如 镜头停在任何一个静止展台、营地或信号塔
    那么 它的名牌飘在它头顶上方，不贴在地上

功能: 写错配置时直接报错

  场景: 只写骨骼编号不写挂载目标
    假如 作者在吸附里写了 boneId，但没写 target
    当 加载配置
    那么 加载失败，提示写了 boneId 时 target 必须是 Bone
```

自动化对应：
- 前三个功能由 `PresenterTreeOverrideShowcaseAcceptanceTests` 覆盖，每条用例对应一个场景，读的是外观实例的世界位姿和本帧提交给渲染的图元颜色；期望值按本文件第 3 节写死在测试里，配置改了要同步改测试。
- “写错配置时直接报错”由 `PresenterDefinitionConfigLoaderTests` 覆盖；车动时子物体保留覆盖、吸附叠覆盖的 Core 级回归在 `PresenterChildOverrideTransformRegressionTests`。
