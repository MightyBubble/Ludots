# 表现树“同一套，这里改一点” showcase 设计

## 一句话与目标用户

同一个模型摆多份，每一份能单独挪位置、换颜色、换部件、加挂件；车动起来，挂在上面的东西不掉队。

写给要拿表现树（presenter children）和地图摆放搭场景的作者：他们没读过 `PresenterEntityRuntime`，只想知道“我在这一处写的覆盖，画面上到底认不认”。

## 主循环

- **谁改变世界**：场景自己跑，不需要操作。
  - 两辆巡逻车一直绕圈。
  - 乘客每 12 秒上车一次、下车一次。
  - 骑士原地挥剑。
- **用户看到什么随之变化**：
  - 巡逻车走起来，左右小旗、车顶灯、车尾灯始终贴在车上的固定位置。
  - 乘客上车后跟着车走，下车时落在车旁一圈。
  - 骑士挥剑时，剑跟着右手转。
- **惊喜时刻**：盯住车尾灯。它和车顶灯用的是同一个灯的定义，只在这一处多写了“往车尾挪 1.6 米”。修复前这句配置被悄悄吃掉，两盏灯叠成一盏；修复后车尾多出一盏红灯，跟着车转弯。小旗同理：修复前车一动，两面旗都缩回车中心。

## 消融对照

每个展台都是“左边原版，右边这一份改过”。用的是同一个定义，画面差异只来自这一处写的覆盖：

| 展台 | 左边（原版） | 右边（这一份的改动） |
|------|--------------|----------------------|
| A2 同一个灯柱摆两份 | 小灯柱 | 位姿覆盖：放大、挪开 |
| A3 同一个水晶 | 蓝色（定义默认值） | 参数覆盖：红色 |
| A4 同一座塔 | 塔顶是球 | 换子树：塔顶换成旗 |
| A5 同一个神龛 | 宝珠贴在底座上 | 单份加行为：宝珠吸附到上方 |
| D1 同一个巡逻车模板 | 内圈小半径 | 地图整组件覆盖：外圈大半径、更快 |
| D2 同一个营地模板 | 北营地·指挥帐 | 按路径给子件改名：港口指挥帐 |
| D4 同一个信号塔模板 | 三座塔 | 地图参数覆盖：红、绿、蓝 |

修复前后的消融放在验收证据里：同一帧截图，C1 和 B3 修复前后各一张。

## 解释层

- 每个展台头顶有一行世界文字，写着案例编号和一句话说明。文字来自摆放上的 `entityInfo.titleToken`。D2 的营地子件标题由 `overridePaths` 写进去，所以文字本身就是 D2 的证据。
- 颜色约定：
  - 定义默认值用冷色：蓝、灰。
  - 这一份的覆盖用暖色：红、橙。
  - 挂件和灯用黄、红。

## 旋钮清单

全部写在地图的 `Metadata.presenterTreeShowcase` 和摆放数据里，改数据就能改行为，不需要改代码。

| 旋钮 | 范围 | 回答什么问题 |
|------|------|--------------|
| 巡逻车 `PresenterTreeOrbitMotion.RadiusCm` | 200–1200 | 圈越大车越快，挂件会不会甩出去？ |
| 巡逻车 `PeriodSeconds` | 4–30 | 转弯越急，子物体朝向跟不跟得上？ |
| `riderBoardAtSeconds` / `riderAlightAtSeconds` | 0–周期 | 什么时候上车、什么时候下车 |
| `riderAlightRadiusCm` | 100–600 | 下车散开有多远 |
| 地图 `PresenterParamOverrides` 颜色 | 任意 RGBA | 同一个模板能不能每座不同色 |

不足 4 个运行时（不重启）旋钮。原因：这个能力是“配置怎么写”，最直观的调法就是改配置。键盘旋钮留给后续的交互版。

## 场景结构

- **第一排（静态）**：展示一棵树里的覆盖，五个展台。
  - A1：一棵树成套出现。
  - A2：位姿覆盖。
  - A3：参数覆盖。
  - A4：换子树。
  - A5：单份加行为。
- **第二排（动起来）**：
  - 两辆巡逻车，覆盖 B1、B3、C1、D1。
  - 一个乘客，覆盖 D6。
  - 骑士，覆盖 B2 骨骼挂载。
- **第三排（地图摆放）**：
  - 两座营地，覆盖 D2。
  - 三座信号塔，覆盖 D4。
- **首屏**：相机从正前方斜俯视，三排一屏看全。每块展台的文字说明了“看哪里、哪边改过”。

## 门户资产

- 截图用沙箱真实运行的 Raylib 画面，按帧号截取。帧号取巡逻车走到侧面的时刻，这时小旗和车尾灯最容易看出差别。
- 证据目录：`artifacts/acceptance/presenter-tree-override/`。
- 同源：截图和无头验收测试读的是同一份 mod 配置。验收测试断言的位置量直接从这份配置里取（覆盖偏移、吸附偏移、半径），不在测试里另写一份数值。

## 反向 API 审计

| 需要的能力 | 现状 | 归属 |
|------------|------|------|
| 父节点移动后，子物体保留位姿覆盖 / 锚点偏移（C1） | 传播路径丢了覆盖 | 本次修复 |
| 挂件上的位姿覆盖生效（B3） | 吸附结果整个覆写掉覆盖 | 本次修复 |
| 写了 `boneId` 没写 `target` 时报错（B2） | 静默按挂父节点处理 | 本次修复 |
| `instanceChildren` / `instanceBehaviors` 的锚点冲突校验 | 漏查 | 本次修复 |
| 地图上给某一座建筑里的某个表现子物体单独覆盖（E1） | 没有入口 | 后续 |
| 按路径改子件字段、增删子件（D3） | 加载时报“未装载” | 后续 |
| `attach:false` 的独立实体（D5） | 仍然结构挂接 | 后续 |
| 骨骼按名字引用 | 只收整数编号 | 后续 |
| 带子实体的模板写 `PresenterParamOverrides`（D4 限制） | 明确报错 | 后续 |

## 验收用例

```gherkin
功能: 同一个定义摆多份，这一份单独改

  场景: 一棵树成套出现
    假如 场景里摆着 A1 展台的小屋
    当 关卡开始
    那么 我同时看到小屋、熔炉和屋顶的旗子
    而且 头顶写着“A1 一棵树成套出现”

  场景: 同一个灯柱，右边那根更大
    假如 A2 展台用同一个灯柱定义摆了两根
    那么 左边那根矮小，右边那根明显更高更粗，而且离得更开

  场景: 同一个水晶，只有这一颗是红的
    假如 A3 展台用同一个水晶定义摆了两颗
    那么 左边那颗是蓝的，右边那颗是红的

  场景: 同一座塔，这一座换了塔顶
    假如 A4 展台用同一个塔定义摆了两座
    那么 左边塔顶是一个球，右边塔顶换成了一面红旗

  场景: 同一个神龛，这一个的宝珠飘在上面
    假如 A5 展台用同一个神龛定义摆了两个
    那么 左边的宝珠贴着底座，右边的宝珠飘在底座上方

功能: 东西动起来，挂件不掉队

  场景: 巡逻车上的小旗和灯
    假如 巡逻车左右各插一面小旗，车顶一盏黄灯，车尾一盏红灯
    当 巡逻车绕圈行驶
    那么 两面小旗一直在车身左右两侧，大小不变
    而且 黄灯一直在车顶，红灯一直在车尾，两盏灯不重叠

  场景: 第二辆车这一份换了绕圈参数
    假如 两辆车来自同一个模板，第二辆在地图上整组件覆盖了绕圈参数
    那么 第二辆车跑外圈，比第一辆跑得快

  场景: 剑挂在骑士右手上
    假如 骑士在原地反复挥剑
    那么 剑一直握在右手里，跟着手臂转动

  场景: 乘客上车、散开下车
    假如 乘客站在站台上
    当 到了上车时间
    那么 乘客出现在内圈巡逻车上，跟着车走
    当 到了下车时间
    那么 乘客落在车旁一圈，不再跟车

功能: 地图摆放上的覆盖

  场景: 两座营地，指挥帐名字不同
    假如 两座营地来自同一个模板
    那么 北营地的帐篷写着“北营地·指挥帐”，港口营地的帐篷写着“港口指挥帐”

  场景: 三座信号塔，颜色各不相同
    假如 三座信号塔来自同一个模板，地图上各写了一个颜色参数
    那么 我看到红、绿、蓝三座塔

功能: 写错配置时直接报错

  场景: 只写骨骼编号不写挂载目标
    假如 作者在吸附里写了 boneId，但没写 target
    当 加载配置
    那么 加载失败，提示写了 boneId 时 target 必须是 Bone
```
