Case E · 配置结构 · D15 现行合同

框选：矩形单源 · 一张命中函数 · 生命周期函数化

本文是 Case E 框选链路的现行配置合同（D15 落地后）。输入更新回到输入域（PointerMoved 边沿，不设帧时钟）； context 生命周期是 profile 上的瞬时边界槽（onActivated / onDeactivated，取代被废止的 whileActive 周期字段）； 手势与落定解耦：手势出口只写交接单，落定是一张全手势通用的 Script 函数体。

和旧文档的关系：历史 case-e-config-report.html 与更早的「结构修订」保留对照；以本文为准。 本文落到 D15 合入后的真实资产上；「函数愿景」（graph-callable-function-vision）中还没落地的部分单列在 §09。

00第一性：可复用的图体是函数；挂载是带监听的宿主

合同立场 合同

可复用的图体都是函数：有入参、有返回，或写明副作用。打分返回分、校验返回是否通过、命中返回名单——同一套调用模型。
函数用 Script（能挂起、能写、能读集合）或 Query（纯读、给表现层取数、作者面禁写）表达；二者是同一函数族的两种许可面，不是两种物种。
边沿动作（按下 / 抬起 / 存活期指针变化）由带事件入口的 TriggerGraph 承载；它是调度宿主，不是另一种「函数物种」。宿主调函数；函数不回头调宿主。

四个名词（先对齐）

候选集合case_e.selectable——能被框的人。battle 挂载的 roster_sync 图随 MapHeartbeat 维护，开框前就位。
预览集合case_e.box_hover——拖拽时框里是谁，黄环。

03profile：两类字段——监听的入口 + 生命周期的边界

InteractionContext profile（D15 真实字段） 配置

battle（常驻）
inputContextIdstringCaseE.Controls（键位随实体投影，多 seat 各投影各的）
bindingsstring[]按住即成立的语义动作（BoxSelectBegin/End + 修饰键）
triggers[]mountroster_sync（MapHeartbeat）+ box_begin（CaseE.BoxSelectBegin）
boxing（按下时激活的衍生 context）
triggers[]mountbox_hover_tick（action=PointerMoved）+ box_commit（action=CaseE.BoxSelectEnd）——框选活着时听的输入边沿
onActivatedgraph 数组本用例留空；对称保留
onDeactivatedgraph 数组box_hover_clear + selection_commit（Script 函数体，框选结束时的清场与落定；全手势复用）
为什么是槽不是周期：旧 whileActive 是「存活期每帧空耗周期」的野鸡字段，承载不了其他监听、还占帧。D15 把生命周期改成两个瞬间边界钩子——onActivated 跑在 boxing 的 triggers[] 开启之前，onDeactivated 跑在它们关闭之后（显式停用或主体死亡都走这里）。引擎只在边界调用命名图体，不做任何清理动作。

05命中函数（唯一）与拖拽：输入更新回输入域

一张纯函数，拖拽与松手共用 配置

命中链只剩一张：box_hit（Query 纯函数，入参=候选集合 + 起角黑扳 + 活指针）返回命中集；拖拽与松手都调它，不写第二套命中算法。

  "id": "graph.case_e.box_hit",
  "kind": "Query",
  "入参": {
    "candidates": "QueryFromCollection(case_e.selectable)",
    "press":    "ReadBlackboardFloat(case_e.press.px/py)",
    "live":     "LoadPointerScreenX/Y"
  },
  "side effect": "无（Query 作者面禁写集合；命中结果留在 TargetList 交给调用方）"
}

拖拽中：PointerMoved 输入边沿，不是帧时钟

boxing 活着时挂 box_hover_tick（TriggerGraph，条目 action: PointerMoved）。 指针位置一变，输入绑定系统按 seat 派发一次；图中 InvokeGraph(box_hit) → 尾节点 WriteCollection(case_e.box_hover, replace)。 指针不动就不派发、不重算。
曾考虑 MapTick 每帧事件——那是把「输入更新」错当成模拟时钟，无人订阅时还空转；不用。

06框结束：出口图 + 通用落定槽

松手 Trigger：box_commit（手势出口图） 配置图体

box_commit（瘦身为出口：只交接，不落定）
1. 读修饰LoadEntryPayloadIntMapTrigger.Modifiers
2. 写修饰WriteBlackboardIntcase_e.select.modifiers ← 1：修饰键落 rep 黑板（落定槽读这里）
3. 终局命中InvokeGraph调 box_hit（同一张命中函数）
4. 写交接单WriteCollectionselection.pending（replace）——手势产物归档，等落定
5. 停用DeactivateContext宣布框选结束；boxing 监听卸载走门控下帧扫描

onDeactivated 槽：清场 + 落定（Script 函数体） 图体

两张槽图（都在 boxing 的 onDeactivated 里，顺序执行）
box_hover_clearScriptWriteCollection(case_e.box_hover, replace 空)——黄环灭
selection_commitScript读黑扳修饰 → 读交接单 selection.pending → SwitchInt（无/Precision→replace，Queue→add，Subtract→subtract）→ WriteCollection(selected) → 交接单集合减法消费成空
交接单消费：落定尾段用 WriteCollection(selection.pending, subtract=2) 把刚读出的名单从交接单里减去——M⊆pending 恒成立，减完必空。语义即「消费」，不需要额外的清除 op。

06b生命周期与结算的边界（D15 定稿）

三件事按结构保证，不靠约定
开启前 / 关闭后结构顺序onActivated 在 boxing 的 triggers[] 注册之前跑；onDeactivated 在它们卸载之后跑。挂 / 拆是门控的唯一汇点，槽贴在这两侧——顺序是结构事实，不是两个系统之间的时序约定。
死亡补发destroy 边界主体带着 context 被销毁（拖拽半途被击杀、未走显式停用）时，门控在 destroy 回调里对携带的每个 context 跑 onDeactivated 槽——结算与清场不会因死亡漏掉。
结算延迟1 tickselected 在「停用后的下一 tick」更新（帧 N 松手写交接单，帧 N+1 槽结算）。原因是槽执行点固定在门控拆监听之后，而门控每帧扫一次世界。玩家不可见（隔 1 tick）；对读 selected 的逻辑是契约窗口：停用后 1 tick 内读到的还是旧值。当前 selected 无并发读者；「同拍即时结算」需把槽挂到 DeactivateContext 同帧，会引入同帧嵌套执行，暂不采用。

08换手柄意味着什么（设计的验收思想实验）

不用框选了、插上手柄：新手势 = 一个新 context + 自己的命中图 + 自己的 box_commit 出口，照旧写同一张交接单 selection.pending 与修饰键黑扳，然后在 onDeactivated 里列出 selection_commit。 落定层（读交接单、写 selected、消费交接单）零改动；清场层 box_hover_clear 各手势按需换自己的预览 key。

09相对历史：D15 已落地 / 远景还欠

D15 已落地（真实资产）

· whileActive 四层删除；生命周期 = onActivated / onDeactivated 边界槽
· 拖拽预览 = PointerMoved 输入边沿（输入域，无帧时钟）
· 手势/落定解耦：交接单 + 通用 selection_commit（Script 函数体）
· 落定/清场槽图 = Script 函数体；集合查询读面对齐 Script（修「能写不能读」不对称）
· 死亡补发：destroy 边界跑 Deactivated 槽
· 起角与修饰键黑扳随按下同批建立
· 修复既有缺陷：未声明动作绑定别名到 index 0 槽（PlayerInputHandler.CompileBinding）

远景还欠（先出方案，见 graph-callable-function-vision）

· 图顶层入参表 inputs[]（出参表 outputs[] 已有）
· InvokeGraph 命名演进（InvokeFunc）与 FuncLib 划界
· 预览写入 S1（图内副作用）/ S2（纯返回再写入）二选一收口
· Query 作者面与「函数等价」的长期对齐
