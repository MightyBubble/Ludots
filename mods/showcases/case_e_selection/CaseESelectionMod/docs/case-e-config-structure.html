Case E · 配置结构修订（落地合同）

框选：矩形单源 · 一张命中 Query · 预览/已选中同面

本文是 Case E 框选链路的现行配置合同，粒度对齐旧版宪法 HTML（每步：事件 / 透传 / 字段表 / 配置还是代码 / 流图）。 相对旧版，修正四件事：矩形只留起角 + 活指针；命中只配一张 Query，Trigger 与拖拽调度都调用它；候选不必进重型集合仓库；废弃临时字段名 continuousQuery，改成 context 的 whileActive。 01–03 与旧版同构，从 04 起按修订写。

和旧文档的关系：旧 case-e-config-report.html 保留作对照；以本文为准落地与验收。文中标 缺口 的项是引擎尚缺、必须先补再建 Case E 资产的能力。

00全链路概览

01 进图实体出生
02 挂默认模板 initialInteractionContext → 战斗 context
03 启用边沿profile.triggers[] 挂抬起/点选 TriggerGraph
04 框开始记下起角（一个变量）→ 激活「正在框选」→ 可选刷新候选名单
05 拖拽中whileActive 每帧：起角 + 当前指针 → 调同一张命中 Query → 写预览集
06 框结束Trigger：再调同一张命中 Query（或读当帧预览）+ 修饰语义 → 写已选中 → 停用框选 → 预览清空
07 高亮预览集 / 已选中集都走「集合成员变化」事件；presenter 只换订阅 key

三层语义（玩家侧）

不是三个同等重量的仓库对象——只有「谁会被画环」才必须进成员事件面
候选命中入参能被框的人。默认在命中 Query 图内用过滤算出来（临时名单）。不必写入 EntityCollectionStore。若作者要缓存可写，但是可选优化，不是合同。
预览collection key拖拽时框里现在是谁。写入轻量预览集合（如 case_e.box_hover），驱动黄环。离开「正在框选」必须清空。
已选中collection key松手后正式结果（如 selected），驱动蓝环；支持 replace / add / subtract。

03Definition：边沿 trigger + 存活期 whileActive

配置：InteractionContext profile 配置

不要使用已落地的临时字段名 continuousQuery。合同字段是 whileActive：context 活着时每仿真 tick 跑哪些 Query。边沿图仍走 triggers[]。
配置结构：Input/interaction_context_profiles.json · 一条 profile
idstring如 interaction.context.case_e.boxing
activeCollectionKeystring该 context 下施法/指令路由用的集合 key（与框选预览无关）
activeEntityViewKeystring对外视图 key

triggers[]mount边沿 TriggerGraph 挂载（按下/抬起/点选完成）。结构同现网：trigger / 可选 event / 可选 filters
whileActive[]mount · 新存活期：context 已挂载的每个逻辑 tick，对 subject 执行列出的 Query。不是边沿，不监听 action。
whileActive[] 每一项
querystring · GraphKind.Query id必填。必须是已注册 Query；安装时校验 kind=Query，且至少有一个 EntityCollection 类 output（预览集物化）。

谁跑 whileActive

代码：context 存活期调度系统（可从现有 ContinuousQuery 脚手架改名/改字段）。每 tick：有 whileActive 的挂载实例 → 以 context subject 为 owner/caster 执行 Query → GraphReturnWriter 按 output schema 写集合。 离开 context → 按该 Query 的 EntityCollection outputs 清空（预览灭）。 没有「continuousQuery」这个产品概念；只有 whileActive 调度 + Query 资产。

05命中 Query（唯一）+ 拖拽中 whileActive

一张纯计算 Query：所有命中只配这一遍 配置 + 代码调度

① 矩形两个脚从哪来（调用方接线，不是图外第二套 API）

Query 只声明 data 入参：起角 x/y、活角 x/y、以及候选名单（图内算出或外部传入）。
拖拽 whileActive 调用方：起角 = ReadMapVar；活角 = 指针屏幕位置 helper（当前帧）。
松手 Trigger 调用方：起角 = 同一 map var；活角 = 抬起 payload 的指针（或同一 helper 在抬起帧的值）。
禁止：一边读属性、一边读 map var、一边读 payload 拼第三套角。
配置结构：graph.case_e.box_hit · kind=Query
kindQuery无事件入口、无世界副作用（除通过 output schema 物化集合——由 GraphReturnWriter 在调用方执行后写入）
候选段图内推荐：QueryAllMapEntities → FilterTeam → FilterTemplate（或标签）。产出临时 TargetList。不要求先有 case_e.selectable 集合。
矩形段data in四个 float：pressX/pressY/liveX/liveY（命名以图内端口为准），进 ScreenRegionToEntities
outputs[]EntityCollectioncollectionKey = 预览 key（如 case_e.box_hover）；role = AcquisitionPreview。whileActive / GraphReturnWriter 用它物化预览。
Query · 命中（示意）

② 拖拽中 = whileActive 调这张 Query

不是再听 action。boxing context 活着 → 调度每 tick 调 query → Replace 预览集。
高亮：集合成员变化才发事件（已有 EntityCollectionPresentationEventSystem），不是每帧打外观。
每帧 起角+活角 → Query 集变时 MemberAdded/Removed presenter 订预览 key → 黄环

③ 指针 helper（合同名，实现可演进）

调用方需要「当前指针的窗口像素」。合同名：指针屏幕位置 helper。
实现可以是：既有 Input 动作 → 属性绑定后的读口、Aim/Screen 运行时、或图内专用读 op——命中与框指示共用这一条活角来源。
旧 CaseE.PointerX/Y 属性绑定若仍存在，只应作为 helper 的一种实现，不得再当第二套「命中专用角」。

06框结束：Trigger 调用同一张 Query → 写已选中

事件：抬起 / 点选完成 配置图体 + 缺口：InvokeQuery

引擎缺口：今日 InvokeGraph 只能嵌 TriggerGraph。修订合同要求 TriggerGraph 可调用 Query（建议 op 名 InvokeQuery）：exec 流入、data 传入参、data 出 TargetList。未补齐前不得再手抄第二份 ScreenRegion 链冒充复用。
框结束图体（box_commit）步骤
1. 读修饰payloadMapTrigger.Modifiers → replace / add / subtract
2. 组矩形脚data起角 = map var；活角 = 抬起指针（payload 或 helper）
3. InvokeQueryop · 新functionName = graph.case_e.box_hit；把四个 float（及若需要的 source）传入；取出 TargetList
4. 透传写入DispatchCollectionEventevent + collectionKey=selected + op 语义；下游 EventKeyedCollectionWriter 写正式集
5. DeactivateContextop停用 boxing → whileActive 停 → 调度清空预览 outputs
可否松手直接读预览集？可以当作优化（少调一次 Query），但合同仍要求「命中算法只有 Query 这一份」。验收以 InvokeQuery 同一资产为准；读预览集不得变成第二套命中逻辑。

10相对旧实现：要删 / 要改 / 要补

删或停用

· profile.continuousQuery 字段名（改为 whileActive）
· 命中路径上的双写 Press 属性
· commit / tap 图内手抄的第二份 ScreenRegion 链（在 InvokeQuery 落地后）
· 「候选必须进 EntityCollectionStore」作为合同（可留作可选缓存）

补

· Trigger → Query：InvokeQuery（或等价）
· whileActive 安装校验 + 每 tick 调度 + 离开清空 outputs
· 指针屏幕位置 helper 作为活角唯一读口（可先复用现有通道，收口命名）
· 验收：拖拽预览与松手结果同一 Query；矩形单源
UAT 口径（玩家话）：按下后拖，框跟着走，框里的兵亮黄环；松手黄环灭、蓝环留在框过的兵上；加选/减选只改蓝环集合；敌人永远不进黄环也不进蓝环。换皮肤/scheme 时只改 Query 或修饰映射，不配第二套命中。
