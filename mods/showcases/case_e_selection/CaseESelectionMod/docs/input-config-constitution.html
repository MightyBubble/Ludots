输入与可调用函数系统 · 配置宪法

面向要从零搭一遍这套系统的作者。读完你能按 §13 的清单，从空仓库配出一个「按下 → 拖框 → 预览 → 抬起 → 落选」的完整 showcase，并且知道每个字段由谁在什么时机校验、错了会怎么失败。本页是配置面的宪法；概念面（scheme / context / intent / order 的语义分层）仍以 input-command-system.html 为准，其 §4.1 的 Tap/Drag 段由本页 §01 取代。

标注约定：已落地 = main 上现网可用；切N = 终态方案第 N 刀交付（见 gitbook/architecture/graph-callable-function-vision.md 的切片表）；退役 = 禁止再出现，装载即拒。

00. 总则：五层、三条不变量、一个判据全文规范

系统本质一句话：把设备事件流，折叠成对一组实体的集合运算。

层唯一职责对应配置不知道什么
L0 判定设备 → 语义动作边沿（press/release）；修饰快照解析成枚举default_input.json世界、实体、集合
L1 宿主context 门控动作；边沿 / 存活期调函数；把输出交给 L3interaction_context_profiles.json几何、集合运算
L2 函数纯计算：输入 → 名单GAS/graphs/*.json世界可变状态
L3 集合全引擎唯一集合写点：集合运算、成员事件、容量、生命周期（挂载声明里的 applyOutputs，无独立文件）输入设备、几何
L4 表现只订阅：环、框Presentation/presenters.json谁进框、何时清

三条不变量（本页所有规则由它们推出，冲突时以它们为准）：

  1. 集合只有一个写者。图不写集合，宿主不摸存储；写只发生在 L3 的 CollectionApplier，入口是挂载声明。
  2. 状态必有生命周期主人。context 退 → 宿主按声明清（clearOnExit）；owner 死 → L3 自己清并发成员移除事件。不存在孤儿集合。
  3. 每个数字/字符串要么是显式引脚输入，要么是装载期校验过的作者参数，不存在第三种。

假数据驱动判据（出现任何一条即违宪）：图内 case: 解释原始位掩码；靠扫程序字节码发现副作用；截断不报错；函数体内读宿主实体属性当输入；集合 key 魔法串埋在函数体；同一事实写两份。

01. 动作与绑定 · default_input.json已落地（#1447 形态）

定义「有哪些语义动作、绑在哪个物理输入上、在哪个边沿触发」。这是 L0 的全部配置。

{
  "actions": [
    { "id": "CaseE.BoxSelectBegin", "name": "CaseE_BoxSelectBegin", "type": "Button" },
    { "id": "CaseE.BoxSelectEnd",   "name": "CaseE_BoxSelectEnd",   "type": "Button", "firesOn": "release" },
    { "id": "CaseE.Pointer",        "name": "CaseE_Pointer",        "type": "Axis2D" },
    { "id": "QueueModifier",        "name": "CaseE_Queue",          "type": "Button" },
    { "id": "ModifierSubtract",     "name": "CaseE_Subtract",       "type": "Button" }
  ],
  "contexts": [
    { "id": "default", "bindings": [
      { "actionId": "CaseE.BoxSelectBegin", "path": "<Mouse>/leftButton" },
      { "actionId": "CaseE.BoxSelectEnd",   "path": "<Mouse>/leftButton" },
      { "actionId": "CaseE.Pointer",        "path": "<Mouse>/position" },
      { "actionId": "QueueModifier",        "path": "<Keyboard>/shift" },
      { "actionId": "ModifierSubtract",     "path": "<Keyboard>/ctrl" }
    ] }
  ]
}

字段合同

字段取值规则
actions[].id语义动作 id全仓库唯一 SSOT；context、profile、挂载、图 entry 都只引用它
typeButton / Axis2D / AxisButton 有边沿，Axis 没有边沿只有值
firesOnpress（默认）/ release裸边沿，仅此两种。同一 path 上多个 Button 动作必须以 firesOn 区分；不区分 → 装载即拒
bindings[].path设备路径属于设备层；换设备只改这里

不存在 interactions 字段。退役 Tap / Drag（阈值、MaxTravel、空隙合同）已整体退役——「单击 vs 拖拽」不是判定问题：按下开框、抬起落定，零位移就是点选，同一次边沿、同一张函数。装载遇到 interactions 字段即拒，不留壳。

修饰语义动作与位义 SSOT

修饰也是普通 Button 动作，但 id 必须取自下表的保留名（引擎按它解析意图）：

语义动作 id载荷位对集合运算的影响
QueueModifierbit0（值 1）解析为 Add
PrecisionModifierbit1（值 2）保留位——不改变集合运算，供产品自用
ModifierSubtractbit2（值 4）解析为 Subtract（压过 Add）

位义 SSOT 在代码 InputActionFiredModifiers，作者面只见语义 id；「减选压加选」这条优先级策略只活在引擎解析函数里，图和 profile 都不解释位。挂载声明 op: "modifierIntent" 时，装载器校验该 profile 的 bindings 已绑全上表动作，缺一即拒。

边沿载荷（payload 键 SSOT）

Button 动作触发时，事件载荷只携带以下保留键（EventSchemaRegistry 声明，MapTriggerEventPayloadKeys 定义）：

载荷键类型含义
MapTrigger.RepEntity触发玩家的 rep 实体（挂载 / 集合的 owner）
MapTrigger.PointerScreenX/YFloat触发时刻指针屏幕坐标
MapTrigger.ModifiersInt（位掩码）触发时刻按住的修饰位——只供引擎解析，作者面不读裸值

02. 动作 → 属性桥 · action_attribute_bindings.json已落地

把持续值动作投影到 rep 实体的属性上，供存活期挂载每 tick 读。唯一的用途就是「活角跟指针」这类连续量。

[
  { "id": "Input.CaseE.PointerX", "action": "CaseE.Pointer", "attribute": "CaseE.PointerX" },
  { "id": "Input.CaseE.PointerY", "action": "CaseE.Pointer", "attribute": "CaseE.PointerY" }
]

纪律：只做投影，不承载逻辑；边沿一次性数据（如按下时的起角）走 payload，不走属性；同一事实只写一份——起角写在按下边沿的图里（属性），禁止再写 map var 第二份切2。

03. 交互 context 与 profile · interaction_context_profiles.json骨架已落地；挂载字段切1/切2

profile = 一个交互状态的定义（Definition）；运行时哪个 rep 处于哪个 context 是实例（Instance，挂实体，可衍生子、可并存，见概念宪法 §8）。本文件只写定义。

{

        { "trigger": "graph.case_e.box_begin",

      ]
    },
    {
      "id": "interaction.context.case_e.boxing",
      "activeEntityViewKey": "case_e.boxing.view",
      "bindings": [ "CaseE.BoxSelectEnd", "CaseE.Pointer" ],
      "triggers": [
        { "trigger": "graph.case_e.box_commit",
          "applyOutputs": [ { "from": "hit", "collection": "selected", "op": "modifierIntent", "capacity": 256 } ] }
      ],
      "whileActive": {
        "function": "graph.case_e.box_hit",
        "bindInputs": { "pressX": "attr:CaseE.PressPx", "pressY": "attr:CaseE.PressPy", "liveX": "attr:CaseE.PointerX", "liveY": "attr:CaseE.PointerY" },

字段合同

字段规则
id全局唯一；命名惯例 interaction.context.<mod>.<状态>
activeCollectionKey（已退役，v2：意图自带成员集）「这个 context 的操作对象落在哪个集合」的 key——下令管线的唯一读接口（下单时按 rep 活跃 context 找到此集合，令下给成员，见 §12）。成员是运行时的；此处只声明 key 名。可下令的 context 必须声明；纯玩法 context（不下单）可省略。引擎不设任何默认键、默认 profile 或隐式回退——活跃 context 链上没有任何声明此字段的 context 时，下单具名拒绝
activeEntityViewKey上者集合的控制面视图 key（UI / 控制面投影名）。同为静态 key 名 + 动态成员
bindings动作门控表：只决定哪些动作在此 context 活，不含任何行为。所有挂载引用的动作必须 ⊆ 本表
triggers[]边沿挂载（§04）
whileActive存活期挂载（§04）。一 subject 同时至多一个 whileActive 函数，运行时冲突即抛错点名两个函数

动静分离（硬规则）：profile 只写「静」——定义一个 context 是什么（门控哪些动作、挂哪些函数、接口 key 叫什么）。context 的父子关系、scope 嵌套、谁在哪一刻处于哪个 context，全是「动」——由边沿包装图里的 ActivateContext(parentContext: ...) 在激活那一刻声明并校验（parent 当时必须真的活跃在该实体上，否则抛错；停用走 DeactivateContext，scope 随之整组清理）。定义文件里禁止出现任何激活边——出现即违宪。

退役 旧字段名 continuousQuery：装载即拒并提示改名（已落地）。

04. 挂载声明：bindInputs 与 applyOutputs切1/切2

挂载是 L1 的接线数据，只回答三个问题：调谁、输入从哪来、输出写到哪。挂载不做行为——行为在函数（L2）与编排 op（§05 包装图）里。

两种挂载形状（一个动作只有一个真相源）

包装图挂载 { trigger, applyOutputs }直挂 { action, function, bindInputs, applyOutputs }
调谁边沿包装图（带 entries，动作绑定在图内 entries[].action——动作的唯一真相在图里）纯函数图（无 entries）；动作绑定在挂载上——唯一真相在挂载里
何时用需要编排 op（切 context、写起角属性）或调多个函数不需要任何编排，边沿直接算+写
bindInputs不适用（包装图经 LoadEntryPayload* 读事件载荷，属合法入口读取）必填：签名每个参数一个来源表达式
applyOutputs两种形状都必填：把签名输出物质化

禁止同一动作在挂载与图内两处都写绑定——包装图挂载不写 action 字段，直挂不引用带 entries 的图。装载器按此校验，违者拒载。

bindInputs：输入来源表达式

表达式含义装载校验
payload:<载荷键>触发事件的载荷值键必须在该动作的事件 schema 里
attr:<rep 属性>rep 实体当前属性值属性 id 必须存在于属性约束表
const:<字面量>常量类型必须与参数一致
CollectionRef 参数不必绑定：按签名里的 key 取 owner=rep 的集合key 必须已注册

缺任何一个签名参数、类型不符、来源键不存在 → 装载即拒。没有迁移豁免。

applyOutputs：输出物质化

字段取值规则
from签名里的输出名不存在 → 装载即拒
collection目标集合 key必须已注册于集合 key 空间
opreplace / add / subtract / modifierIntentmodifierIntent = 运行时按 §01 解析表取 None/Add/Subtract；选它则 profile 必须绑全修饰动作
capacity正整数，默认 256上限 = 引擎目标寄存器上限；写入选集超限 → 运行时抛错，点名 key 与数量（不静默截断）。要更大走分页输出票，先声明先拒绝
clearOnExitbool，默认 falsetrue = context 退出时清空该集合并发成员移除事件。清空时 key 找不到 → 抛错

运行时序（一条帧内的顺序，不可调换）

① InputActionAttributeBindingSystem   活角属性先写（§02）
② whileActive 宿主                      绑输入 → 调函数 → 逐条 applyOutputs
③ 成员事件差分                          集合签名没变就不重发（表现不闪）
④ 表现系统                              按成员事件开关行为槽
边沿帧：触发动作 → 绑定 payload 输入 → 调函数（或包装图）→ applyOutputs
        → 图内 DeactivateContext → 下一帧 whileActive 清 clearOnExit 集合

05. 函数与签名 · GAS/graphs/*.json切1（签名）/ 切2（单门）

graph 是函数。凡被挂载（triggers / whileActive）或被调用（InvokeFunc）的图，必须声明签名；纯内部图（不被挂载不被调）不强制——签名范围是函数目录，不是全部图。

[
  {
    "id": "graph.case_e.box_hit",
    "kind": "Query",
    "entry": "filter_roster",
    "signature": {
      "inputs": [
        { "name": "candidates", "type": "CollectionRef", "key": "case_e.selectable" },
        { "name": "pressX", "type": "Float" },
        { "name": "pressY", "type": "Float" },
        { "name": "liveX",  "type": "Float" },
        { "name": "liveY",  "type": "Float" }
      ],
      "outputs": [ { "name": "hits", "type": "EntitySet", "capacity": 256 } ]
    },
    "nodes": [ ... ], "controlEdges": [ ... ], "valueEdges": [ ... ]
  }
]

类型表

类型含义来源 / 去向
Float / Int / Bool标量payload / attr / const / 上游输出
CollectionRef集合引用（带 key）按 key 取 owner=rep 的集合，不必绑定
EntitySet实体名单（带 capacity）只能作为输出，被 applyOutputs 物质化或被调用方按名路由

编译期强制（签名与事实双向锁死）

  • 函数体内出现任何集合写 op → 编译错。退役 DispatchCollectionEvent 可创作面整体退役（切2）；事件系统只留纯通知。
  • 读宿主实体属性不经 inputs → 编译错。LoadSelfAttribute / LoadCaster 标记为迁移桥，禁用于签名函数。
  • 输出没有对应物质化声明、或声明引用不存在的输出 → 装载即拒。
  • 声明了却做不到、做到了却没声明——两类都在编译期死，不存在「允许迁移期不一致」。

两种形态（照概念宪法 §7.5）

边沿包装图（TriggerGraph，带 entries）纯函数图（无 entries）
入口entries[]: { label, action, start, refire: "restart" }entry 单入口，被调用才跑
允许的 op计算 + 编排 op（ActivateContext / DeactivateContext / ModifyAttributeSet）仅计算 op（过滤、几何、集合运算）
签名必须有（被挂载）必须有（被挂载或被调用）

编排 op 留在包装图里、用既有 op 组合——挂载声明不做行为开关（GAS 组合门纪律）。其中 ActivateContext(parentContext: ...) 是激活边的唯一声明点：父子关系、scope 嵌套都在这一刻动态建立与校验（见 §03 动静分离）。kind（Query / Script / TriggerGraph…）只是编译与编辑器分组标签，永不作为挂载或调用的门闩切3。

06. 调用 · InvokeFunc 节点切1（改名）/ 切2（按名路由）

{ "id": "run_hit", "op": "InvokeFunc", "functionName": "graph.case_e.box_hit" }
  • 目标必须已登记签名且 yield:false（可挂起动作只有切片/叶子宿主可调，看登记表 hostAllowed）。
  • 输入按参数名经 valueEdges 绑定；返回按输出名路由进后续值边。位置式 TargetList 拷回特判删除。
  • 调用图 ↔ 被调图成环 → 登记时即拒。
  • 缺绑定、类型错、目标未登记 → 编译错。退役 旧名 InvokeGraph 装载即拒。

07. 函数登记表 · 一表两列一签名切3

不设 FuncLib / 业务函数 / ActionLib 三个目录——一张表，行为靠列：

{ "name": "graph.case_e.box_hit", "graphRef": "...", "signature": {...}, "yield": false, "hostAllowed": [...] }
视图筛选条件谁可调
FuncLib（纯函数库）yield:false 且标量签名任何图 / 宿主
可调用业务函数yield:false 且带 EntitySet 签名挂载与 InvokeFunc
ActionLib（可挂起动作）yield:true仅 hostAllowed 列出的宿主

目录之争由行为列消解：作者从不选「放哪个目录」，只声明签名与 yield。纯度由签名推导，不设调用侧 Pure/WithEffects 开关。

08. 集合 · 唯一写点与生命周期切2/切4

  • key 空间：集合 key 在 EntityCollectionStore 的 key registry 注册，命名带 mod 前缀（case_e.box_hover、selected 为跨 mod 公共 key）。
  • owner = rep 实体。同一 key 不同 owner 互不干扰。
  • 唯一写点 CollectionApplier（由 EventKeyedCollectionWriter 内核转正）：装载时吃挂载声明，运行时被宿主调用。全引擎没有第二个集合写入口。
  • 容量 fail-loud：候选装载（CollectionRef 读取）与输出物质化超 capacity 一律抛错点名 key 与数量。退役 Math.Min 静默截断路径（切4）。
  • 成员事件：EntityCollectionMemberAdded / Removed，按集合内容签名差分发布——集合没变不重发。
  • owner 死亡：L3 按 owner→key 索引清空其全部集合并发成员移除事件（teardown 是正常路径，不抛错）。表现层的环随成员事件熄灭，无孤儿。

  • 事件只做纯通知：载荷 schema 在 EventSchemaRegistry 声明，缺键、未声明 id → 装载/派发即拒。
  • 退役 集合运输：collection_event_writers.json 删除，事件不再携带集合载荷——集合写只走 §08。

参数单真相ScreenRect 四角来自 AttributeBinding 读 rep 属性——与命中函数读同一份属性，矩形「写一次、两边读」
指示器硬规则一切指示器（瞄准圈 / 扇形 / 方向线 / 蓄力条 / 地面标记 / 移动路径 / 选中与悬停环）必须是 presenter 定义 + 规则订阅 + 参数绑定。表现域零计算：不得调用瞄准、几何或判定内核，只读图写好的同一份黑板 / 集合参数。架构守卫与「模拟不得读视觉」守卫成对存在

12. 出界引用：从选中集合到下令接口已落地；引擎特权键进入拆除排期

该字段已退役（v2）：意图自带成员集——提交图自己装载演员集（QueryFromCollection 或查询后过滤），drain 只做授权与逐成员提交；context 不再声明/路由任何集合。合同如下：

  • 基础 context 由数据挂载：实体模板的 initialInteractionContext（spawn 时挂，不覆盖已有实例）或启动数据声明。引擎不安装任何保留 profile、不注册任何默认集合键——没有"稳态锚点"这回事，只有声明。派生 context 由图的 ActivateContext 挂载并声明父级。
  • 成员自带（v2）：提交图在提交前装载演员集；空集 = rep 单体。context 链只用于仲裁 commandIntentId。
  • 提交入口是图 op：边沿图调 SubmitCommandIntent（地物点 / 可选命中实体）或 SubmitCast（技能槽语义键、瞄准载荷、蓄力档位）把意图写进预分配意图缓冲（容量走 gasRuntimeCapacity，超限抛错点名）；下令域在自己的 SystemGroup 相位 drain 路由，相位与 DispatchMapEvent 同节奏，图执行期内不路由。replicated client 上该 op 经客户端命令端口转发，context 状态以服务器为权威。
  • 直接占有是数据形态，不是内核规则：无选择中介的玩法（rep 即受控体）用 self-roster 图把 rep 写进自己 context 声明的活跃集——"谁下令"永远只是"活跃集成员"。
  • 瞄准 / 蓄力是 context + 图：技能按下图读 InteractionPref（实体组件）分支——智能施法直接 SubmitCast；非智能 ActivateContext(瞄准, parent=战斗)，瞄准 context 挂 whileActive 瞄准图（aimsource 纯函数算方向 / 地面点 / 自动目标，结果写 context 黑板），确认边沿图 SubmitCast，取消边沿图 DeactivateContext。蓄力 = press 激活蓄力 context + whileActive 按激活 tick 差累计，抬起图按档位分发不同 SubmitCast，超时由 whileActive 图比较阈值后 DeactivateContext。档位判定按固定 tick 累计，回放确定。
  • 一切指示器 presenter 化：瞄准圈 / 扇形 / 方向线 / 蓄力条 / 地面标记 / 移动路径 = presenter 定义 + 规则订阅 + 参数绑定（§10）。表现域零计算，只读图写好的同一份黑板 / 集合参数。

概念见 input-command-system.html §5–§6（去向 B）；下令侧自己的配置（意图路由、扇出、派发）见其所属文档，本宪法不重复。Case E 全链下单（提交图 QueryFromCollection(selected) + 右键提交）随退役片落地。
