### 案例1：月度脉冲的宫廷风波（CK3）
1. **机制原型**：游戏按月度或年度脉冲检查每个角色的候选事件。事件有平均发生时间，特质、关系、领地状况等修正其发生概率；满足资格后，从候选池中抽取一个事件。部分事件只发生一次，部分可重复但有冷却。
2. **玩家可观察行为**：事件不会固定在某一天弹出，而是在节奏脉冲中随机出现。每个角色各自进行判定；同一月份可能有多个角色分别收到事件。事件通常以弹层显示，选项立即产生后果，未处理的事件遵循窗口排队规则。
3. **配置思路轮廓**：用 `TriggerGraph` 订阅 `MapHeartbeat` 或 `TurnAdvanced`，为每个角色建立 scope；用 `Validation` 图检查资格，用 `WeightedPick` 从候选事件池抽取活动；通过 `recur.cooldown`、`once` 或 `always` 控制重复；选项用 `settle` 脚本结算。
4. **拷问点（核心产出）**：
   - **blocker**：`recur.cooldown` 只有固定冷却，没有“平均时间到事件”（MTTH）或按修正值变化的随机等待机制。
   - **major**：`WeightedPick` 只接受分布 id，未说明如何让每个 scope 根据特质、关系等动态改变候选权重。
   - **major**：`TriggerGraph` 没有明确的“遍历所有角色并各自发射一份”活动的 scope fan-out 合同。
   - **major**：同一脉冲内多个活动的抽取顺序、随机流隔离和确定性重放规则未定义。

### 案例2：满足条件后的连续抉择（CK3）
1. **机制原型**：某个事实或条件刚刚成立时，角色立即收到事件。玩家选择一个选项后，下一环事件可以立刻接着弹出，也可以安排在数日后发生。选项可能改变属性、关系或资源，也可能启动后续任务。玩家不操作时，AI 根据各选项权重替玩家决定；窗口到期则执行指定默认选项。
2. **玩家可观察行为**：条件成立后几乎立即出现弹层。选项会因当前状态隐藏或锁定，并显示不可用原因。确认后可能马上出现下一环；延迟后果不会在当前窗口重复执行。超时后自动采用默认选项，AI 控制的角色不需要玩家点击。
3. **配置思路轮廓**：用 `MapVariableChanged` 阈值事件或自定义事件触发 `OfferActivity`；`when`、`show_when`、`enable_when` 分别表达资格、显示和可执行条件；选项 `settle` 脚本负责即时结算，使用 `CreateTask` 接上延迟任务，并尝试由任务或后续 `TriggerGraph` 发射下一环活动。
4. **拷问点（核心产出）**：
   - **blocker**：`Script` 图不能使用 `OfferActivity`；没有 `next_activity`、`ContinueActivity` 或同 tick 链式派发能力，无法直接表达“选完立刻续弹下一环”。
   - **blocker**：活动和选项都没有时限字段、到期时间、`timeout_option` 或默认选项合同。
   - **blocker**：没有 AI 选项权重、AI 资格判断或代表 scope 提交 `activity.confirm` 的能力。
   - **major**：`CreateTask` 只说明创建任务，没有任务完成后如何携带原活动实例、选项结果和目标 scope 的参数合同。
   - **major**：`settle` 禁止 `ApplyEffectTemplate`、`ModifyAttributeAdd`、`InvokeBuiltin`，立即修改 GAS 状态必须绕到另一条 `TriggerGraph`，但 v4 没有说明这条跨图因果链如何保证同步和只执行一次。

### 案例3：带插图的纯叙事风味弹层（CK3）
1. **机制原型**：角色在特定经历、地点或脉冲中收到以肖像、场景图和文字为主的风味事件。它可以完全不改变世界状态，只记录为已读；也可以设置为一次性、可重复或带冷却的叙事通知。单人游戏中弹层通常暂停推进，多个事件则按队列依次处理。
2. **玩家可观察行为**：弹层出现时首先看到插图和叙事文本，选项可能只是关闭或选择不同的演出分支。确认后没有属性、资源或关系变化。多个来源同时触发时，事件不会互相覆盖，而是等待前一个窗口处理。
3. **配置思路轮廓**：用 `TriggerGraph` 接收脉冲、区域进入或 UI 自定义事件；活动采用 `arrival: modal`，不配置根 `settle`，并以 `recur.once` 或冷却控制重复；选项脚本只做归档或演出调用。
4. **拷问点（核心产出）**：
   - **major**：活动 schema 没有插图、肖像、场景资源或表现层 cue 字段；`ShowPanel` 不能证明 `activity` 面板支持这些数据。
   - **major**：没有“纯演出、不得影响判定”的显式合同，空 `settle` 与无结算活动的历史语义不够清楚。
   - **major**：活动窗口的排队顺序、同 scope 合并规则、暂停与恢复时机未定义。
   - **minor**：`title`、`body` 只能是静态文本，未说明如何把角色名、地点名等运行时文本安全地注入活动投影。

### 案例4：日历锚定的国家或省份事件（EU4）
1. **机制原型**：事件可以绑定到某个日历日期或日期区间，并附带资格条件。到达日期后，符合条件的国家或省份收到事件；有些事件允许在日期窗口内偏移若干天，过了终止日期仍未满足则失效。通常每个国家或省份只触发一次。
2. **玩家可观察行为**：在指定日期附近弹出国家或省份事件窗口。若条件不成立，事件可能不出现或等待后续日期检查；若超过有效窗口则不再出现。选项可以立即改变国家状态，也可以安排之后的改革、战争或任务。
3. **配置思路轮廓**：由 `TriggerGraph` 订阅回合推进或心跳，读取地图日历值后发射 `OfferActivity`；用 `when` 做国家、省份资格判定，`recur.once` 保证每个 scope 一次；选项 `settle` 脚本记录即时结果，延迟部分交给 `CreateTask`。
4. **拷问点（核心产出）**：
   - **blocker**：v4 没有日历日期、日期区间、偏移量或终止日期字段，也没有日期比较 op。
   - **major**：`when` 为假时是“本次错过后继续等待”还是“本实例永久丢弃”，文档没有规定。
   - **major**：没有国家、行政区、省份等多层 scope 的枚举与绑定方式；`Caster=scope host` 不能单独表达省份事件。
   - **major**：没有日期事件在同一时刻与其他活动竞争时的优先级和排队顺序。

### 案例5：平均时间随机池事件（EU4）
1. **机制原型**：国家或省份持续参与随机事件池。每个候选事件有平均发生时间和修正条件，达到抽取时机后按权重选择一个可用事件。随机数由游戏的确定性随机系统产生，以保证存档、联机和回放的一致性；事件可设为一次性、可重复或有冷却。
2. **玩家可观察行为**：事件出现时间不可预测，但长期频率接近配置的平均值。相同条件下，候选事件按权重竞争；某个事件被处理后，其他事件仍可在之后的抽取中出现。玩家看到的是被选中的一个事件，而不是整个候选池。
3. **配置思路轮廓**：用 `TriggerGraph` 在固定节奏上驱动池检查；每个 scope 先运行资格 `Validation` 图，再让 `WeightedPick` 选择活动分布；活动本身使用 `arrival.pool`，并由 `recur` 控制去重、一次性和冷却。
4. **拷问点（核心产出）**：
   - **blocker**：没有 MTTH 调度器，无法表达“每个候选事件拥有独立平均发生时间”。
   - **major**：`arrival.pool` 的分布定义、候选资格过滤、动态权重和抽空后的重试规则没有 schema。
   - **major**：`WeightedPick` 的确定性随机流只提到“命名流”，未规定 seed 来源、scope 隔离、存档恢复和联机一致性。
   - **major**：没有“池抽取只选一个并消耗本次机会”的原子语义，可能在同一心跳连续派发多个活动。

### 案例6：危机进度驱动的分阶段事件链（EU4）
1. **机制原型**：国家累积某种危机进度，超过阈值后进入灾难或政治危机阶段。阶段事件反复出现，选项会增减进度、改变国家修正或触发其他系统；某些选择立刻进入下一环，某些选择在数日后引发后续事件。AI 国家按权重自动选择，玩家窗口到期则执行默认方案。
2. **玩家可观察行为**：进度跨过阈值时弹出危机开始事件。处理一个窗口后，下一阶段可能立即排队，也可能延迟出现。危机期间同一国家会持续收到相关事件，但同组事件不会无止境叠加；战争、改革等其他窗口与危机事件共同排队，单人游戏通常暂停等待处理。
3. **配置思路轮廓**：用 `MapVariableChanged` 的跨阈值过滤器启动危机；以 `mutex` 或冷却限制同组活动；`show_when`、`enable_when` 表达阶段和资源门槛；`settle` 脚本写入进度、创建延迟任务，并由任务或触发图尝试发射下一阶段。
4. **拷问点（核心产出）**：
   - **blocker**：没有活动链或后续活动引用，无法保证选项结算后按阶段、顺序和原 scope 进入下一环。
   - **blocker**：没有活动/选项超时、默认选择和 AI 自动拍板字段。
   - **major**：`CreateTask` 未定义延迟时间、取消条件、重复执行保护和到期回调载荷，不能可靠表达数日后果。
   - **major**：危机选项需要修改 GAS 状态，但 `settle` 图禁止 `ApplyEffectTemplate`、`ModifyAttributeAdd`；跨到 `TriggerGraph` 后又缺少同步、事务和因果归属合同。
   - **major**：没有跨活动队列的优先级、暂停策略和互斥组仲裁规则，无法确定危机窗口与普通国家事件谁先处理。
