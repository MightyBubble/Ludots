# TriggerGraph Dispatch Benchmark

## 概述

本报告测量地图事件从 `TriggerManager` 进入已挂载触发器的稳态派发成本。它不把 Graph VM 脚本执行、地图扫描或异步续跑混入派发数字。

## 结构

- 场景：1 张地图、16 个同事件触发器、优先级交错。
- 迭代：预热 2,048 次，测量 100,000 次。
- 指标：当前线程分配字节、总耗时、每事件微秒。
- 环境：本机 Windows/.NET 8 开发环境；结果用于回归观察，不作为 CI 硬门槛。

## 详情

| 版本 | 中位每事件 | 分配 |
| --- | ---: | ---: |
| 优化前（扫描 + 临时 List + Sort） | 3.0546 us | 1,736 bytes/event |
| 优化后（挂载期事件索引 + 同步完成快路） | 0.648 us | 0 bytes/event |

优化后 5 次运行：`0.6372 / 0.6405 / 0.6442 / 0.6551 / 0.6598 us/event`，中位数 `0.6442 us/event`；每次均为 `0` 当前线程分配字节。一次受调度抖动影响的观测为 `0.7138 us/event`，未纳入中位数序列。

## 场景

异步图或包含 `Yield/Wait` 的触发器仍按原有异步路径执行；本优化只让同步完成的事件不创建异步状态机，并把地图事件的排序成本前移到挂载/追加时。

## 边界

完整心跳事件仍会为每个事件创建独立 `ScriptContext`，这是续跑生命周期所需，不宣称整条业务链零分配。桥接系统的 fire-and-forget 生命周期也未在本次性能切片中改变。

## UAT

```gherkin
Feature: TriggerGraph 地图事件派发性能
  Scenario: 稳态事件派发不产生临时分配
    Given 一张地图挂载 16 个按优先级排列的同事件触发器
    When 连续派发 100000 次该地图事件
    Then 所有触发器都收到事件
    And 当前线程分配字节为 0
```
