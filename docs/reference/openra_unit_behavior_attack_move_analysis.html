OpenRA 用户输入动作与基础单位指令源码剖面

从玩家视角看，OpenRA 的单位控制可以归纳为几类输入动作：默认上下文点击、带修饰键点击、命令栏确认模式、即时命令、姿态切换和特殊多步输入。 屏幕上表现为光标变化、按钮高亮、目标线、语音反馈和单位动作；源码里则落到 Order、IResolveOrder 和活动树。

一句话结论 用户看到的是“点哪里、按什么键、光标怎么变、单位怎么动”。 引擎看到的是“哪个 targeter 接单、生成什么 Order、哪个 trait 排入什么 activity”。

Scope

0. 本报告范围

分析对象

本报告按玩家实际输入动作组织：选中单位后点击地面、点击敌人、点击友军或建筑、按住 Ctrl/Alt/Shift 点击、点击命令栏按钮、按热键、切换姿态，以及布雷这类多步输入。 每类输入都说明用户会看到什么，以及源码里如何变成单位行为。

源码范围

重点覆盖普通单位常见基础指令：移动、停止、散开、攻击、强攻、攻击移动、守卫、姿态、部署、采集、修理、占领、运输、停靠、布雷、爆破、空军降落与返航。 生产队列、建筑摆放、支援技能和全局玩家命令只作为边界参考。

注意许可证边界：OpenRA 是 GPL 项目，这里只做架构学习和行为拆解。Ludots 可以学习它的分层思想、数据驱动方式和调度模式，不应直接复制实现代码。

Feedback

2. 屏幕反馈：玩家看到的行为语言

OpenRA 不只生成命令，还会在命令生成前后给玩家反馈。多数反馈并不改变单位逻辑，但它们决定用户是否能理解“这个点击会做什么”。

光标

targeter 在 CanTarget 中返回 cursor。可移动、不可移动、攻击、强攻、采集、进入、修理、卸载等都会显示不同光标。

按钮高亮

命令栏按钮通过 IsHighlighted 表示当前模式，例如 attack move、guard、force move、force attack 和 queue orders。

目标线

resolver 成功排入活动后通常调用 ShowTargetLines。活动的 TargetLineNodes 决定线指向目的地、目标 actor 或子活动目标。

语音

IOrderVoice 根据命令名和目标有效性返回语音 key。无效命令通常不会播放确认语音。

单位动作

玩家最终看到的是活动树运行结果：移动、转向、停下、追击、起飞、降落、进入建筑、装载、卸载或发射武器。

失败反馈

不可部署、不可进入、不可移动会表现为 blocked cursor、通知文本、语音提示或没有订单生成；复杂检查留在 trait 内部。

Order Pipeline

3. 从输入到单位活动树

OpenRA 的关键设计是：玩家 UI、Lua 脚本和 bot 最后都走同一条 Order 通道。bot 没有私有的“瞬移式单位控制权”，它只是像玩家一样提交 AttackMove、Move、Attack、Harvest、Dock 等命令。真正的单位行为发生在 actor trait 和 activity 系统里。

1. 生成命令 UI、bot 或脚本创建 Order，可带分组选中单位或额外数据。
2. 分发订单 UnitOrders 校验订单；分组订单会拆成每个 actor 自己的订单。
3. trait 接单 Actor.ResolveOrder 遍历所有 IResolveOrder trait。
4. trait 解析 命令名命中哪个 trait，就由哪个 trait 校验目标并队列化 activity。
5. Actor.Tick 每 tick 通过 ActivityUtils.RunActivity 跑当前活动树。
6. 子系统落地 移动、索敌、攻击、武器、弹体分别由自己的 trait/activity 执行。 
伪代码视角：
Order("Move" / "Attack" / "Harvest" / "AttackMove" / ...)
  -> UnitOrders 展开分组并做订单校验
  -> Actor.ResolveOrder(order)
  -> 所有 IResolveOrder trait 逐个尝试解析
  -> 命中的 trait 调 Actor.QueueActivity(...)
  -> Actor.Tick()
  -> ActivityUtils.RunActivity(CurrentActivity)

这就是 OpenRA 的第一层分离：战略 AI 只负责“下什么命令”，单位 trait 负责“这个命令在每个 tick 怎么执行”。因此基础单位指令 同时服务玩家输入、bot 分队和脚本，不会被锁死在某个 AI 模块里。

Context Orders

5. 默认上下文点击怎么选出命令

普通右键不是固定等于移动。UnitOrderGenerator.OrderForUnit 会对当前 target 做两轮判断：先问 actor/frozen actor 上能否交互；如果没有命中，再退回 terrain cell。Ctrl、Shift、Alt 分别转成 ForceAttack、ForceQueue、ForceMove，传给每个 targeter 自行解释。

收集 target 鼠标下优先真实 actor，其次 frozen actor，最后 terrain cell。
收集 orders 从单位所有 IIssueOrder trait 取 targeter。
按优先级 高优先级如采集/卸载可压过普通移动。
修饰键 Ctrl 强攻，Alt 强制移动，Shift 队列。
生成 Order 命中的 trait 调 IssueOrder 返回具体命令名。
解析执行 网络订单回到 actor，再由 resolver 排入 activity。

为什么右键矿是采集，右键空地是移动

Harvester 暴露 HarvestOrderTargeter，优先级高于普通移动，只在已探索资源格上返回可用；资源不匹配时它不接单，Mobile 的移动 targeter 才接管。

为什么 Alt 能强制走过去

多个 targeter 会显式检查 TargetModifiers.ForceMove。攻击、爆破、采集等目标交互通常在 force move 下让位，移动 targeter 则可覆盖选择行为。

Direct Orders

6. 命令栏、热键与姿态命令

命令栏按钮不会走完整的右键 targeter 竞争，而是直接发特定订单或切换专用 OrderGenerator。例如 AttackMove、Guard 先进入确认模式， Stop、Scatter、Deploy 直接对当前选择发订单。

入口 源码位置 行为
命令栏 CommandBarLogic 绑定 attack move、force move、force attack、guard、scatter、deploy、stop、queue orders 等按钮。
部署热键 IIssueDeployOrder 各 trait 自己决定 deploy 对应什么：变形、卸载、返航补给、放雷、激活条件都可以挂上来。
姿态面板 StanceSelectorLogic 发 SetUnitStance，由 AutoTarget 设置 HoldFire/ReturnFire/Defend/AttackAnything。
强制修饰模式 ForceModifiersOrderGenerator 临时把 Ctrl/Alt/Shift 注入下一次右键，复用普通 targeter 流程。

姿态命令虽然不排移动 activity，但它会改变单位后续基础行为：idle 是否扫描、受击是否还击、attack move 是否允许追击、当前攻击活动是否因姿态收紧而取消目标。

AttackMoveActivity

7. Attack Move 的核心状态机

从玩家角度，attack move 是一个两步确认动作：先点命令栏按钮，按钮进入高亮确认模式；再点地图目的地。普通确认生成 AttackMove，按住 Ctrl 确认生成 AssaultMove。 单位会沿目标地点移动，路上发现目标就停下攻击，攻击结束后继续向目的地前进。

AttackMove.ResolveOrder 做的事很少：它确认订单是 AttackMove 或 AssaultMove，检查目标有效性和是否允许进入未探索区域，然后把目标 cell 修正成可移动 cell，最后排入 AttackMoveActivity。真正的行为循环在 AttackMoveActivity.Tick。

初始化
首次运行时，如果单位缺少 AttackMove 或 AutoTarget，活动退化成普通移动；如果具备条件，则给 actor 临时授予 AttackMoveCondition 或 AssaultMoveCondition。
移动阶段
活动通过传入的 getMove 函数创建移动子活动。普通点地 attack move 里，这个子活动来自 IMove.MoveTo(targetLocation)。 关键细节是 ChildHasPriority = false，父活动可以在移动子活动运行期间继续扫描敌人。
索敌阶段
当当前没有子活动，或正在跑移动子活动时，调用 AutoTarget.ScanForTarget。如果移动还在跑，使用标准扫描间隔；如果刚打完一个目标，则忽略间隔立即重新找目标，避免单位刚开火结束就白走一小段。
攻击阶段
找到目标后取消移动子活动，然后让每个可用 AttackBase 生成攻击子活动。攻击子活动结束后，AttackMoveActivity 不直接结束，而是重新进入索敌/移动循环。只有移动子活动完成并且没有目标时，整个 attack move 才结束。

AttackMove 和 AssaultMove 的差别

两者走同一个活动类。区别主要是 AssaultMove 会授予另一个 condition，让规则数据切换自动索敌优先级。例如 RA 规则中， assault move 可以把结构物纳入更激进的自动目标集合。

UI 层的保护

AttackMoveOrderGenerator 在选中单位没有 AutoTargetInfo 时会退出该输入模式，因为没有自动索敌的单位无法完成“边走边打”的语义。活动层仍有兜底：缺 trait 时只移动。

一个细节很重要：AttackMove 不天然等于“主动追杀全图敌人”。它把 autoTarget.AllowMove 传给索敌和攻击活动。是否允许为了目标移动追击，取决于自动索敌姿态和单位配置。

AutoTarget

8. AutoTarget 索敌层：目标选择被数据和姿态约束

AutoTarget 是 attack move 的眼睛。它不是简单地“找最近敌人”，而是带着姿态、扫描间隔、目标类型、关系、武器可用性、视野和射界一起筛选。

机制 作用 对 Attack Move 的影响
姿态 HoldFire、ReturnFire、Defend、AttackAnything。 是否允许自动移动追击由 AllowMove 决定，通常只有更激进姿态才会打开。
扫描间隔 默认在一个短随机 tick 区间内节流，减少大量单位同时扫描的性能压力。 移动中遵守间隔；刚打完目标后可立即再扫描，保持行为顺滑。
目标优先级 AutoTargetPriority 以规则数据定义目标类型、关系和优先级。 AssaultMoveCondition 可以切换优先级配置，不需要新写一套行为代码。
武器过滤 目标必须至少能被某个 armament 有效攻击，且在不允许移动时还要处在射程内。 单位不会为了打不了的目标停下来，也不会在禁止追击时选择太远目标。
视野和冻结目标 可攻击真实 actor，也可按配置考虑迷雾中的 frozen actor。 远程炮击、迷雾记忆和 bot 视野限制都收敛在目标选择层。

这层最值得 Ludots 借鉴的是：目标选择是数据策略，不是硬编码在 AttackMoveActivity 里的分支。移动行为只问“现在有没有目标”，至于目标是谁，由 AutoTarget 和规则配置决定。

Attack Traits

9. 攻击 trait 层：同一命令适配不同武器形态

AttackMoveActivity 找到目标后，不自己开火，而是把目标交给 actor 上的 AttackBase 派生 trait。这样同一个 attack move 命令可以驱动坦克炮塔、正面开火单位、全向攻击单位和更多 mod 自定义攻击方式。

类型 主要职责 行为含义
AttackBase 订单入口、武器筛选、射程计算、攻击活动工厂。 所有攻击 trait 的共同合同，attack move 只依赖这个抽象。
AttackFollow 记录请求目标和机会目标，必要时移动到射程内，目标消失时使用最后可见位置。 移动单位和炮塔单位的主力攻击活动，能追击、卡距离、保持目标。
AttackTurreted 继承 AttackFollow，攻击前让炮塔朝向目标。 坦克这类单位不用转整个车身也能开火，炮塔准备好后才发射。
AttackFrontal 要求单位面向目标，生成通用 Activities.Attack。 适合必须朝前射击的单位，活动里处理转向和范围。
AttackOmni 设置目标并持续调用攻击，不承担追击隐藏目标的复杂逻辑。 适合全向或更简单的攻击模型。

攻击活动不是只开一枪

AttackFollow.AttackActivity 会持续重算目标。如果目标还可见且在射程内，活动等待 trait tick 去发射；如果目标离开射程且允许移动，则挂 MoveWithinRange 子活动追到合适距离。

AttackMove 有独特限制

当武器耗尽弹药且单位支持补给时，普通攻击可以转去补给；但来源是 AttackSource.AttackMove 时，攻击活动直接结束，不把单位从行军任务里拉去补给。

Movement

10. 移动 activity 层：路径、阻塞、贴近和卡射程

OpenRA 的移动也不是由 attack move 手写。Mobile 提供 IMove，把不同移动意图转换成 activity：去某个 cell、靠近目标、跟随目标、移动到射程环内。

Move

寻路到目标 cell，按不同阻塞策略尝试路径。遇到临时阻塞会等待、通知阻塞者、重寻路，必要时后退让路。

MoveAdjacentTo

面向移动目标，目标移动后取消旧路径并重新规划。目标隐藏时使用最后可见位置作为退路。

MoveWithinRange

在最小射程和最大射程之间找候选格，进入正确距离就停下，是追击和卡射程的关键组件。

这层解释了为什么 AttackMoveActivity 可以很薄：它只把“走向目的地”和“进入攻击距离”表达成移动活动，实际寻路、阻塞处理、半格移动插值、actor map 更新都在移动系统内部。

Armament

11. 武器发射层：行为最终落到 projectile

当攻击 trait 判断“可以开火”后，最后一跳是 Armament.CheckFire。它检查装填、暂停、炮塔朝向、最大/最小射程和武器目标类型，然后按 burst、barrel、fire delay 创建 projectile 参数并把 projectile 加进 world。

AttackActivity 确认目标有效，距离和射界满足。
AttackBase 选择可用 armament，调用 DoAttack。
Armament 检查 reload、range、turret、target type。
FireBarrel 计算 muzzle、passive target 和 guided target。
Projectile 根据 weapon projectile 工厂创建弹体。
World.Add 弹体进入 world，之后由弹体/warhead 系统处理命中和伤害。

所以不要把 AttackMove 理解成“自动扣血”。它只是一段单位行为调度。伤害发生在更后面的 projectile 和 warhead 链路中，这让命令、行为、武器和伤害保持清晰边界。

Rules Data

12. RA 规则配置里的真实用法

OpenRA 的 RA mod 把这套行为放进规则继承链中。典型车辆基底包含 Mobile 和 AttackMove，具体单位再组合 AutoTarget、Armament、AttackTurreted 或 AttackFrontal。

配置对象 组合方式 行为效果
^Vehicle 基底 traits 中包含 Mobile、AttackMove 等。 让车辆天然可移动、可接受 attack move 命令。
^AutoTargetGroundAssaultMove 继承地面自动索敌，并让 AssaultMoveCondition 打开 assault profile。 Ctrl attack move 可以切换更激进的目标优先级。
1TNK 继承车辆和地面 assault auto target，挂炮塔、武器和 AttackTurreted。 典型坦克：边走边扫目标，遇敌停下或追击到合适距离，炮塔对准后开火。
V2RL 使用远程武器、较大扫描半径和 AttackFrontal。 典型正面远程单位：需要朝向和距离，部分配置允许打 frozen actor。
E1 步兵同样继承 auto target assault move profile。 说明这套行为不专属于车辆，而是 trait 组合出的通用单位能力。

这个配置方式很漂亮：AttackMove 只是能力入口，AutoTargetPriority 是目标政策，AttackBase 派生 trait 是攻击形态，Armament 是武器。一个单位能不能 attack move，不靠继承一个巨型 Unit 类，而靠 traits 组合。

For Ludots

13. 给 Ludots 的单位行为启发

对 Ludots 来说，OpenRA 这块最有价值的不是具体 C# 写法，而是用户输入、命令语义、单位行为调度、目标选择、移动、攻击、武器发射之间的边界。 用户看到的是简洁输入动作；系统内部必须把这些动作拆给正确的能力模块。

OpenRA 模式 Ludots 可映射方向 价值
能力 trait 暴露自己的 IIssueOrder 单位基础命令不要集中在单个巨大输入系统里；每个能力模块注册自己的 targeter 和 resolver。 新能力可以自然长出新右键语义，例如采集、运输、占领、治疗、建造，不污染移动或攻击系统。
玩家、bot、脚本共用 Order 人类输入、AI commander、脚本都提交同一种运行时命令。 避免 AI 旁路 Core 行为，也方便 replay、调试和测试。
AttackMoveActivity 是薄编排器 在 Ludots 中用 per-entity intent/task/activity 表达组合行为。 attack move 不吞掉导航、索敌、武器系统职责。
AutoTargetPriority 数据化 用配置定义目标类型、阵营关系、优先级、姿态条件。 不同 mod 可以调政策，不必复制行为系统。
AssaultMoveCondition 切目标 profile 用 condition/tag 切换 targeting profile，例如普通行军、突击行军、守点。 一套行为，多种战术语义。
MoveWithinRange 独立 导航层提供“进入射程环”的标准能力，而不是攻击系统自己寻路。 远程、近战、施法、采集都能复用同类距离约束。
Armament.CheckFire 独立收口 GAS/武器执行层负责冷却、射程、弹体、效果。 命令层不会直接造成伤害，战斗规则更可测。

Ludots 已经做得好的方向

  • 已有 Mod、ConfigPipeline、GAS Effect Pipeline 和 SystemGroup 概念，适合承接数据驱动单位行为。
  • 已有导航、输入、GAS、表现层等模块边界，天然适合把 attack move 拆成多个正式管线能力。
  • 六边形架构和“一切皆 Mod”的原则，和 OpenRA trait 组合思想相容。

仍然需要补的关键能力

  • 统一的单位命令合同：玩家输入、AI 和脚本共用，不允许 AI 直接改运动或战斗状态。
  • 上下文命令 targeter：按优先级决定右键是移动、攻击、采集、修理、装载还是占领。
  • 可组合的 per-entity 行为调度：能表达父任务、子任务、取消、排队、完成和继续扫描。
  • 数据化自动索敌 profile：目标类型、阵营关系、姿态、扫描间隔、优先级都应配置化。
  • 标准“进入能力范围”导航意图：移动系统负责路径和距离环，能力系统只声明需求。

最推荐的 Ludots 落地顺序：先统一命令入口，再做右键上下文 targeter，再做轻量单位行为调度，再接数据化自动索敌，最后让 attack move 只组合“移动到目的地”和“有目标时执行攻击能力”。这样不会一上来把所有逻辑塞进一个 RTS AI 系统。
