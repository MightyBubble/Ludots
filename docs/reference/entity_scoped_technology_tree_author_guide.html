Ludots 科技树作者配置指南

这页给内容作者和玩法设计用：你不需要先理解 Evaluator 或 ECS 内部结构，只要按“我要表达什么玩法”选择 scope，然后补齐几个 JSON，就能把科技、升级、英雄解锁、区域条件挂到实体上。

作者视角 Entity-scoped tech Cookbook cases 不使用 map tag 做 feature 开关
四步上手 选 Scope 常见配方 字段速查 避坑

四步上手

任何科技树 case 都可以拆成四个作者动作：定义作用域、放置作用域实体、写条件、把条件挂到按钮或效果上。

1. 声明 scope在 Technology/scopes.json 里声明作者自己的玩法作用域，例如 city、faction、region。
2. 放 host 和 memberhost 是保存科技状态的实体；member 是会使用这个科技的建筑、英雄或单位。
3. 写 requirement在 Technology/requirements.json 写“按钮何时显示/可用”的条件。
4. 挂 ability/effectAbility 用 showRequirement 或 useRequirement；升级用 CompleteTechnology effect。

最小文件清单

文件作者写什么什么时候需要
assets/Technology/scopes.json作者自定义作用域名字，例如 city、faction只要不是本体升级，都建议声明。
assets/Technology/technologies.json科技 id 和默认 scope每个科技都要有。
assets/Technology/requirements.json按钮显示、按钮可用、升级前置条件需要解锁逻辑时写。
assets/Entities/templates.jsonTechnologyScopeHost 和 TechnologyScopeBinding需要城池、势力、区域、省份等作用域时写。
assets/GAS/abilities.jsonshowRequirement / useRequirement需要控制按钮可见或可用时写。
assets/GAS/effects.jsonpresetType: CompleteTechnology需要点击、事件或脚本完成科技时写。

先选 Scope

作者最重要的决定不是“科技属于哪个 player”，而是“这个科技状态应该存在哪个实体上”。

不是硬编码：引擎只内置三种解析方式：self、explicit、named scope。city、faction、region、province 都只是作者在 Technology/scopes.json 里注册出来的 named scope，换成 kingdom、armyGroup、tradeRoute 也可以。
玩法需求推荐 scope科技状态放在哪里作者提示
建筑自己升级自己self建筑实体自己给建筑模板加 TechnologyStateBuffer: {}，不需要 hostKey。
一个城池控制城内建筑可造什么兵city城池 scope host城池是 host，兵营是 member，兵营绑定到该城池。
势力全局科技faction势力 scope host势力 host 可以是真实君主/主城，也可以是不可见数据实体。
区域内有某英雄才解锁region区域 scope host英雄和建筑都绑定到同一个 region；英雄 tag 可由模板、effect 或 runtime 授予。
省份、岛屿、战区共享科技province 或任意作者 key该区域的 scope host按玩法语言命名，不要拿 map tag 临时切功能。
升级效果由外部 UI 指定目标explicitTargetContext 指向的实体只有当调用方能明确传入目标 scope host 时使用。
经验法则：能用 named scope 就优先用 named scope。示例里用了 city、faction、region，项目里可以换成自己的领域词。explicit 很强，但作者必须保证 ability/effect 执行时真的带了 TargetContext。

常见配方

Case 1：城池科技解锁兵营训练

目标：长安城完成“练兵”科技后，长安兵营的“训练民兵”按钮可用。

1. 声明 city scope 和科技

// Technology/scopes.json
[
  { "id": "city" }
]

// Technology/technologies.json
[
  { "id": "Tech.City.Drill", "scope": "city" }
]

2. 城池做 host，兵营绑定到城池

// Entities/templates.json
{
  "id": "city_chang_an_scope",
  "components": {
    "Name": { "Value": "Chang An City Scope" },
    "TechnologyScopeHost": { "scope": "city", "hostKey": "chang_an" }
  }
}

{
  "id": "chang_an_barracks",
  "components": {
    "Name": { "Value": "Chang An Barracks" },
    "AbilityStateBuffer": { "abilityIds": ["Ability.TrainMilitia"] },
    "TechnologyScopeBinding": { "scope": "city", "hostKey": "chang_an" }
  }
}

3. 兵营按钮要求 city scope 已完成该科技

// Technology/requirements.json
[
  {
    "id": "Req.City.Drill.Done",
    "root": {
      "kind": "TechCompleted",
      "technology": "Tech.City.Drill",
      "scope": "city",
      "entitySource": "ScopeHost"
    }
  }
]

// GAS/abilities.json
[
  {
    "id": "Ability.TrainMilitia",
    "useRequirement": "Req.City.Drill.Done",
    "exec": { "clockId": "FixedFrame", "items": [{ "kind": "End", "tick": 0 }] },
    "presentation": { "displayName": "Train Militia", "iconGlyph": "MI" }
  }
]

按钮会显示，但科技未完成时不可用。想完全隐藏按钮，把 useRequirement 改成 showRequirement。

Case 3：同一区域有谋士英雄才解锁计略

目标：荆州区域内有带 Hero.Strategist tag 的英雄时，该区域建筑可以使用“区域计略”。

{
  "id": "strategist_hero",
  "components": {
    "Name": { "Value": "Strategist Hero" },
    "GameplayTagContainer": {},
    "TagCountContainer": {},
    "TechnologyScopeBinding": { "scope": "region", "hostKey": "jing" }

[
  {
    "id": "Req.Region.HasStrategist",

      "count": 1,

[

Case 5：建筑本体升级

目标：某个铁匠铺自己升到 2 级后，解锁高级打造按钮。这个 case 不需要城市、势力或区域 host。

// Technology/technologies.json
[
  { "id": "Tech.Blacksmith.ForgeLevel", "scope": "self" }
]

// Entities/templates.json
{
  "id": "blacksmith",
  "components": {
    "Name": { "Value": "Blacksmith" },
    "TechnologyStateBuffer": {},
    "AbilityStateBuffer": {
      "abilityIds": ["Ability.AdvancedForge"]
    }
  }
}
// Technology/requirements.json
[
  {
    "id": "Req.Blacksmith.ForgeLevel2",
    "root": {
      "kind": "TechLevelAtLeast",
      "technology": "Tech.Blacksmith.ForgeLevel",
      "scope": "self",
      "level": 2,
      "entitySource": "Subject"
    }
  }
]

// GAS/abilities.json
[
  {
    "id": "Ability.AdvancedForge",
    "useRequirement": "Req.Blacksmith.ForgeLevel2",
    "exec": { "clockId": "FixedFrame", "items": [{ "kind": "End", "tick": 0 }] },
    "presentation": { "displayName": "Advanced Forge", "iconGlyph": "AF" }
  }
]

如果 effect 要提升这个建筑自己的科技等级，用 technology.scope: "self"，并确保 effect 的 target 或 subject 就是该建筑。

Case 6：点击研究按钮完成科技

目标：研究完成时，把科技写到某个 scope host 上。这里演示 effect 片段，按钮或触发器如何发出 effect 由具体 feature 决定。

// GAS/effects.json
[
  {
    "id": "Effect.CompleteCityDrill",
    "tags": ["Effect.Tech"],
    "presetType": "CompleteTechnology",
    "lifetime": "Instant",
    "participatesInResponse": false,
    "technology": {
      "id": "Tech.City.Drill",
      "scope": "explicit",
      "level": 1
    }
  }
]

这里的 explicit 表示 effect 执行时必须把目标城池 host 作为 TargetContext 传进来。没有这个上下文时，不要用 explicit。

// 如果研究按钮就在绑定了 city 的建筑上，也可以让 effect 用 named scope。
{
  "id": "Effect.CompleteCityDrillFromBarracks",
  "tags": ["Effect.Tech"],
  "presetType": "CompleteTechnology",
  "lifetime": "Instant",
  "participatesInResponse": false,
  "technology": {
    "id": "Tech.City.Drill",
    "scope": "city",
    "level": 1
  }
}

Case 7：多个条件同时满足

目标：需要“城池练兵科技完成”并且“区域内有谋士”才允许使用大计略。

// Technology/requirements.json
[
  {
    "id": "Req.GrandPlan.Use",
    "root": {
      "kind": "All",
      "children": [
        {
          "kind": "TechCompleted",
          "technology": "Tech.City.Drill",
          "scope": "city",
          "entitySource": "ScopeHost"
        },
        {
          "kind": "EntityCount",
          "scope": "region",
          "entitySource": "ScopeMembers",
          "count": 1,
          "tags": ["Hero.Strategist"]
        }
      ]
    }
  }
]

如果是“满足任意一个条件即可”，把 kind 从 All 改成 Any。如果要反向条件，用 Not 加一个 child。

字段速查

TechnologyScopeHost

写在保存科技状态的实体上。支持单项 { "scope": "...", "hostKey": "..." }，也支持 entries 数组。

TechnologyScopeBinding

写在要使用某个 scope 的实体上。一个建筑可以同时绑定多个作者声明的 named scope，例如 city、faction、region、province。

showRequirement

控制按钮是否出现。失败时玩家看不到该按钮。

useRequirement

控制按钮能否使用。失败时按钮可以显示，但不可用或执行失败。

Requirement 节点

kind常用字段作者用途
TechCompletedtechnology、scope某科技已完成。
TechLevelAtLeasttechnology、scope、level某科技达到指定等级。
EntityCountscope、count、tags同一 scope 内有多少个满足 tag 的实体。
TagAllentitySource、tagsactor、subject 或 scope host 拥有全部 tag。

GraphValidationgraph复杂条件交给已有 condition func graph。

entitySource 怎么选

entitySource检查谁典型用途
ScopeMembers同一 scope 里的成员实体区域内有没有英雄、城内有没有建筑。
ScopeHostscope host 实体城池本体、势力本体、省份本体是否有科技或 tag。
Actor发起 ability/effect 的实体施法者、按钮所属实体。
Subject被检查或被作用的目标实体目标单位、当前选择对象。

避坑清单

  • 不要用 map tag 当 feature 开关。一个 feature 一个 mod，一个 showcase 一个 map；map tag 只表达地图分类。
  • 不要再建 player 科技表。科技状态应该落在 entity 上：城池、势力、区域、建筑本体都可以是实体。
  • 不要把示例 scope 当内置概念。city、faction、region、province 都来自配置声明，不是 C# 硬编码枚举。
  • 不要随手用 explicit。只有调用方能提供 TargetContext 时才用 explicit；否则优先使用 named scope。
  • hostKey 要稳定。city:chang_an、faction:shu 这类 key 是配置身份，不要因为显示名变化而改。
  • member 必须绑定到它要读取的 scope。兵营要读 city 科技，就要有 city binding；要读 faction 科技，就再加 faction binding。
  • 科技完成 effect 必须是 Instant。CompleteTechnology 要配 lifetime: "Instant"，并显式写 participatesInResponse。
  • 多级升级用 level 或 delta，不要同时写。technology.level 和 technology.delta 互斥。
  • 复杂条件先看是否能组合。能用 All/Any/EntityCount/TechLevelAtLeast 表达就不要上 graph；需要跨系统判断时再用 GraphValidation。
