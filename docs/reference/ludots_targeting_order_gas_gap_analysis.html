Ludots Gap Report

Ludots 索敌、警戒、炮台与 Order/GAS 映射缺口分析

这份报告按 OpenRA 的基础单位战斗模型反查 Ludots。结论不绕：Ludots 已有 Order、GAS、Team、TargetResolver、 Projectile、Navigation2D 的关键基础设施，但缺少一个可复用的单位级自动索敌模块，也缺少把 attack-move、guard、脱战、 炮台朝向纳入 Order/GAS 的正式合同。

直接结论 现有 FireballDuel 是 showcase-local 目标派发，不是通用 auto-target。 GAS Search 是效果命中 fan-out，不等于单位 idle 扫描和目标选择。 Order 管线足够承载结果，但还没有 attackMove / guard / stance 的标准 order 语义。 炮台目前主要停在表现和动画原型，没有 gameplay-authoritative turret state。

Scope

1. 分析口径

这里不评价 Ludots 是否“有战斗系统”。Ludots 已经有 GAS、Effect、Projectile、Search、Team 关系、OrderQueue。 问题是：能不能像 OpenRA 一样，让任意 RTS 单位在 idle、被打、attack-move、guard、炮塔开火场景下，用同一套可配置规则完成自动战斗。

当前答案是不能。现有模块能执行“已知目标的能力释放”和“效果命中后的目标分发”，但没有生产级的“单位自行找目标并决定是否把能力释放 order 提交出去”的模块。

Existing Infrastructure

2. 现有可复用模块

OrderQueue / OrderBuffer

OrderQueue 是跨系统入口；OrderBufferSystem 写 active/queued/pending，并把空间、实体、int 参数写进 blackboard。

CompositeOrderPlanner

已支持范围外 castAbility 拆成 moveTo + continuation cast，说明“移动到施法点再放技能”的基础已经存在。

MoveTo + Navigation2D

MoveToWorldCmOrderSystem 已能把 moveTo 转成 NavGoal2D，不是直接改速度或位置。

AbilityExecSystem

从 OrderBuffer 与 blackboard 读取 slot、target entity、target position，创建 AbilityExecInstance，再发布 EffectRequest。

GAS Search / TargetResolver

TargetResolverFanOutHelper 支持空间查询、关系过滤、layer filter、max targets 和 payload effect fan-out。

Team / RelationshipFilter

TeamManager 与 RelationshipFilter 已能表达 Friendly、Hostile、Neutral、NotFriendly、NotHostile。

False Positives

3. 不能误判为已具备

已有东西 为什么不等于 OpenRA 的能力
TargetSelector 它描述 ability target shape、relationship filter、range、radius，不保存单位当前目标、扫描间隔、警戒半径、last-seen、stance 或 priority profile。
GAS Search 它发生在 effect resolve/apply 期间，用于“技能命中谁”。OpenRA 的 AutoTarget 发生在能力释放之前，用于“单位要不要提交攻击 order”。
CapabilityStandardFireballDuelSystem 它按固定红蓝队、anchor 和 wave cursor 提交 castAbility，目标是固定 anchor，不扫描周围敌人，不处理 stance、警戒、脱战、target priority。
RtsRelationRuntimeSystem 它处理施工挂接、出驻、亲子关系和选择可用性，不是战斗索敌或威胁系统。
AbilityExecAimSyncSystem 它是本地输入侧持续刷新瞄准点并可同步整机 FacingDirection，不是多炮塔 gameplay ready 检查。
Raylib tank turret rendering RaylibPrimitiveRenderer 里有 turret yaw 和 recoil 绘制，但动画验收文档明确说 tank turret yaw/recoil 仍在 adapter prototype layer，不是 gameplay authority。
Gap Table

4. 缺口表

能力 当前状态 缺口
单位自动索敌 缺失 没有通用 TargetingState / scan system / scan interval / priority profile。现有 showcase 自己决定目标。
目标优先级 缺失 没有等价 AutoTargetPriority 的数据合同，无法按关系、target tag/layer、priority、条件切换 profile。
姿态 缺失 没有 entity-level HoldFire / ReturnFire / Defend / AttackAnything 语义，也没有 setCombatStance order。
被打反击 缺失 Effect/Gameplay event 有基础，但没有“受到敌对伤害后，如果 idle 且 stance 允许，则反击或重新扫描高优先级目标”的系统。
AttackMove 部分具备基础 移动与 cast continuation 已有，但缺少“移动过程中插入攻击，攻击结束恢复同一 attackMove 目标”的 active-order runtime。
Guard 缺失 没有 guard order、GuardAnchor、跟随半径、保护目标失效策略、守卫中插入攻击后恢复跟随。
脱战/放弃 缺失 没有 last-seen target、leash radius、target invalidation、target memory TTL、combat exit tag 或 idle transition。
炮台 gameplay 表现层有原型 没有 TurretState、turn speed、desired yaw、ready check、muzzle offset、ability activation 前的 turret gate。
GAS 发射与伤害 可复用 这块不应该重写。自动索敌只应提交 castAbility，伤害、投射物、Search fan-out 继续走 GAS。
Order Mapping

5. 映射到 Order

OpenRA 的单位行为落到 Ludots，不应该让 targeting system 直接调用 GAS 内部实现，也不应该直接写 NavDesiredVelocity2D。 它应该把结果表达为标准 order 或 active-order runtime 状态。

OpenRA 概念 Ludots Order 映射 必要规则
SetUnitStance 新增 setCombatStance order；写入 CombatStance 或同等组件。 不能只作为 UI 状态。姿态必须参与 target scan、反击、attackMove profile 切换。
Idle auto-target Targeting system 在单位 idle 且 stance 允许时提交 castAbility 或写入 auto-attack intent。 优先走 OrderQueue / CompositeOrderPlanner，让现有 blackboard 和 ability activation 接管。
AttackMove 新增 attackMove order，payload 使用 OrderSpatialKind.WorldCm 目标点，runtime 持有 authored destination。 移动子过程写 NavGoal2D；发现目标时提交/激活攻击；攻击结束后恢复同一个 attackMove destination。
Guard 新增 guard order，payload 使用 Target entity 和 guard radius。 目标失效时 order 完成或取消；守卫移动仍通过 NavGoal2D，不直接改位置。
Stop 复用 StopOrderSystem 与 OrderSubmitter.CancelAll/CancelCurrent。 Stop 必须清理 current target、guard anchor、attackMove runtime、turret aim desire。
被打反击 伤害事件转换为 retaliate intent；只有 idle 或可中断 order 才提交 castAbility。 不能在 damage effect 里直接开火，否则会绕过 Order/GAS 分层。
GAS Mapping

6. 映射到 GAS

GAS 负责“能力释放之后发生什么”，Targeting/Order 负责“什么时候释放什么能力、朝谁释放”。这条线要分清，否则会把单位 AI 写进 effect phase。

Targeting Scan 扫描 candidate，按 profile 选出 target entity 或 target point。
OrderQueue 提交 castAbility，携带 slot、target entity、target position。
OrderBufferSystem 把目标写进 Cast_TargetEntity / Cast_TargetPosition blackboard。
AbilityExecSystem 读取 blackboard，创建 AbilityExecInstance，执行 block tag 和 precondition。
EffectRequest 能力 timeline 发布 LaunchProjectile、InstantDamage 或其他 effect。
Effect Processing Search / TargetResolver 做命中 fan-out，关系过滤与 payload dispatch 在这里发生。
Runtime Spawn 投射物继续走 RuntimeEntitySpawnQueue 与 ProjectileRuntimeSystem。

不要把 OpenRA 的 ChooseTarget 直接塞进 GAS Search。Search 是 effect 内部“命中谁”的解析； auto-target 是 effect 之前“谁值得被释放能力”的解析。两者都用空间查询和关系过滤，但生命周期和输出完全不同。

Targeting Module

7. Targeting 模块形状

这里需要的是 Core 或可复用 capability 级模块，不是某个 showcase 里临时扫描。至少需要以下运行时状态与 authoring 配置。

运行时组件

  • CombatStance：HoldFire、ReturnFire、Defend、AttackAnything。
  • TargetingProfileRef：实体使用哪套索敌配置。
  • TargetingState：next scan tick、current target、source、reason。
  • TargetMemory：last seen position、last valid tick、target owner/team snapshot。
  • AttackMoveState：authored destination、当前是否被攻击子行为打断。
  • GuardAnchor：被保护 entity、follow radius、leash policy。
  • CombatLeash：最大追击距离、超出后放弃并返回原 order。

配置字段

  • scanRadiusCm、scanIntervalMin/MaxTicks。
  • validRelationship，复用 RelationshipFilter。
  • validTags、invalidTags、layerMask。
  • priority，高优先级先于距离。
  • requiresTags 或 condition，用于 stance / attackMove profile 切换。
  • abilitySlot 或 attack ability id，用来提交 castAbility。
  • allowMove、allowTurn、leashRadiusCm。

这里的缺口不是“缺一个函数”。缺的是一条 pipeline：空间候选、关系/tag/layer 过滤、priority 排序、距离 tie-break、 target memory、order 提交、order 完成后恢复。把这些散写在 AI showcase 里，会很快复制出多套不一致的自动攻击。

Turret Gap

8. 炮台缺口

Ludots 已有 FacingDirection、AbilityExecAimSync、动画 AimYawOffset、Raylib tank turret 绘制。 这些不足以支撑 OpenRA 式炮台，因为它们没有决定“能不能开火”。

需要补的 gameplay 合同 原因 映射点
TurretState 保存当前 yaw、desired yaw、turn speed、ready tolerance、realign delay、turret name。 放在 gameplay ECS，不放在 Raylib renderer。
WeaponMount / ability mount 能力或武器需要知道自己绑定哪个 turret，以及 muzzle offset。 可挂在 ability authoring 或 entity equipment/mount 配置上。
Turret Aim System 根据 current target 或 active cast target 逐 tick 转向，写 ready flag。 在 AbilityActivation 前运行，保证是否 ready 可被 order/ability 检查。
Ability precondition 炮塔未对准时，自动攻击不能直接释放 projectile。 走 AbilityActivationPrecondition 或新增标准 precondition，不绕过 AbilityExecSystem。
Muzzle resolve 投射物起点应来自炮塔/炮管 offset，而不是总从 actor 中心发射。 LaunchProjectile caller params 或 spawn request 需要接收 resolved muzzle。
Presentation bridge 表现应消费 gameplay turret yaw/recoil，而不是自己推导一个并影响不了开火。 Animator / performer 读取 TurretState 快照，Raylib/UE5/Unity 都同源。
System Phase

9. 系统相位

目标选择应该在 Order 和 Ability 之前完成，但不要写进输入系统。建议拆成两个系统层次。

Intent 生成

AutoTargetAcquisitionSystem 在 InputCollection 或紧邻 order intake 前运行，扫描并提交 OrderQueue。

Order runtime

AttackMoveOrderSystem / GuardOrderSystem 维护 active order 的恢复、跟随、完成、取消。

Navigation sink

需要移动时只写 NavGoal2D，不直接写 NavDesiredVelocity2D、ForceInput2D 或位置。

Ability gate

炮塔 ready、silence/disarm/stun、射程预条件进入 AbilityActivation，失败则 cancel/promote order。

Effect

伤害、Search、投射物、on-hit 继续放在 EffectProcessing。不要让 targeting system 私算伤害。

Cleanup

Stop、死亡、目标失效、team 改变时清理 target memory、guard anchor、turret desired aim 和 continuation。

Acceptance

10. 验收测试

测试 必须证明什么
priority 高于距离 高优先级远目标压过低优先级近目标；同优先级才选最近。
stance gate HoldFire 不扫，ReturnFire 只反击，Defend 不主动追，AttackAnything 可追击。
attackMove 恢复 单位移动途中发现敌人，攻击结束后继续原 attackMove destination。
guard 跟随 守卫单位保持 guard radius；插入攻击后回到保护目标；保护目标死亡后 order 清理。
last-seen 脱战 目标失效或离视野后追到最后位置；超时或到达后放弃。
炮塔 ready 目标在射程内但炮塔未转到位时不产生 LaunchProjectile；转到位后才释放。
Order/GAS 合同 自动索敌只能通过 OrderQueue(castAbility) 进入 AbilityExecSystem，不能直接发布 effect 或 spawn projectile。
Implementation Sequence

11. 建议顺序

优先级 切片 理由
P0 Target identity 与 profile 先定义 CombatStance、TargetingProfile、TargetingState，否则 attackMove/guard 都会各写一套。
P0 AutoTargetAcquisitionSystem 实现空间候选、关系/tag/layer 过滤、priority、scan interval，并提交 castAbility。
P1 attackMove active order runtime 复用 moveTo / NavGoal2D，补“攻击插入后恢复移动”的运行时状态。
P1 guard runtime 在 attackMove runtime 上增加 protected target 和 follow radius，不独立造一套战斗循环。
P1 disengage / leash 补 last-seen、TTL、leash、target invalidation，避免单位无限追杀或目标失效后卡 active order。
P1 gameplay turret 炮台一旦影响开火，就必须先有 authoritative state，再接表现。
P2 UI 与 debug overlay 显示 stance、current target、scan radius、guard link、turret ready，用来调试但不能先于核心语义。
