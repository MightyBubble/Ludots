OpenRA Source Report

索敌优先级、脱战警戒与炮台机制源码剖面

OpenRA 的基础战斗行为不是一个集中式 AI 子系统，而是单位 trait 与 activity 的组合： AutoTarget 负责发现目标，AttackFollow 负责追击与放弃， Guard 复用 attack-move 跟随保护，Turreted 以 gameplay 状态约束开火。

核心结论 优先级先于距离；距离只在同优先级目标之间做 tie-break。 警戒范围分两层：索敌扫描范围与 Guard 跟随范围不是同一个概念。 炮台不是纯动画；炮塔未转到目标方向时，武器不会发射。 所谓脱战主要是 activity 结束、目标清理、回到移动或 idle，没有独立 combat-state manager。

Scope

1. 范围与源码

本报告只分析 OpenRA 基础单位行为中的自动索敌、目标优先级、脱战、警戒范围与炮台开火链路。 它不分析 skirmish bot 的战略层，因为这里讨论的是任意单位在收到命令或处于 idle 时如何自行开火。

关键文件包括 AutoTarget.cs、AutoTargetPriority.cs、 AttackFollow.cs、AttackMoveActivity.cs、Guard.cs、 Turreted.cs、AttackTurreted.cs、Armament.cs， 以及 RA mod 的 defaults.yaml、vehicles.yaml、structures.yaml、ships.yaml。

Runtime Chain

2. 运行链路

OpenRA 的索敌和攻击链路是分层的，但不是以“AI 管理器”命名。单位身上的 trait 在 tick、idle、damage、order resolver 等入口被调用，每一层只做自己的事。

Idle / Damage / Order 单位 idle、受到伤害、收到 AttackMove/Guard/Attack 命令时进入战斗链路。
AutoTarget 按姿态、扫描间隔、武器与目标类型选择候选目标。
ChooseTarget 关系、可见性、target type、priority、距离、射界逐层过滤。
AttackBase 把目标包装成 attack activity，并选择可用 armament。
AttackFollow 追击、靠近、记忆最后可见位置、决定何时放弃。
AttackTurreted 如果有炮塔，先让炮塔转向；至少一个炮塔 ready 才允许开火。
Armament 检查 reload、range、min range、turret facing，然后生成弹体。
Visible Behavior

3. 玩家会看到什么

场景 屏幕表现 源码路径
单位原地待命 如果姿态允许，单位会按随机间隔扫周围目标；发现目标后攻击。默认人类玩家姿态是 Defend，通常只攻击武器范围内目标。 INotifyIdle.TickIdle 调 ScanAndAttack。
单位被攻击 姿态至少为 ReturnFire 时，空闲单位会反击攻击者；如果姿态更主动，还会先重新扫描更高优先级目标。 INotifyDamage.Damaged，随后 Attack(Target.FromActor(Aggressor))。
Attack Move 单位沿目标点移动；途中发现目标会停下攻击；攻击活动结束后继续走原路线。Ctrl 触发的 AssaultMove 会切换 priority profile，通常把建筑也纳入自动攻击。 AttackMove.ResolveOrder 进入 AttackMoveActivity。
Guard 单位跟随被保护目标，在保护范围内移动；途中发现敌人则和 attack-move 一样插入攻击活动，结束后继续跟随。 Guard.GuardTarget 创建 AttackMoveActivity，移动子活动是 MoveFollow。
炮塔单位开火 车体或建筑可以不立刻转身，炮塔先转向目标；炮塔没转到位时不出弹。攻击结束后炮塔可按 RealignDelay 回正。 AttackTurreted.CanAttack 与 Armament.CanFire 双重约束。
Stance Gates

4. 姿态与移动门控

UnitStance 有四档：HoldFire、ReturnFire、Defend、AttackAnything。 它不只是 UI 下拉框，而是直接改变自动攻击入口和追击权限。

HoldFire

自动索敌基本关闭。强制攻击命令仍由 attack trait 处理，但 idle scan 不会启动。

ReturnFire

不会主动扫描，但受到伤害且空闲时会反击。治疗类负伤害不会触发反击。

Defend

空闲时扫描并攻击，但 AllowMove 为 false，通常不会为了自动目标主动追出武器范围。

AttackAnything

AllowMove 变为 true，单位可以为了自动目标移动追击；RA 数据也会切到包含 Structure 的优先级 profile。

AI 默认值

bot 或不可玩 owner 默认 InitialStanceAI = AttackAnything，人类默认 InitialStance = Defend。

条件联动

姿态可授予 condition，例如 stance-attackanything，YAML 用它启停不同 AutoTargetPriority。

AttackMove 本身不会无条件打开追击。它会在移动途中扫描目标，但是否允许移动追击仍看 autoTarget.AllowMove。 RA 的 AssaultMove 主要通过 assault-move condition 切换 priority profile，例如让建筑也成为自动目标。

Priority Algorithm

5. 优先级算法

AutoTargetPriorityInfo 的字段很少：ValidTargets、InvalidTargets、 ValidRelationships、Priority。真正的行为来自 AutoTarget.ChooseTarget 的过滤顺序。

1. 候选范围 ScanRadius 大于 0 时使用它；否则使用 attack trait 的最大武器射程。
2. 空间查询 World.FindActorsInCircle 找真实 actor；允许移动或允许冻雾目标时再加入 frozen actor。
3. 基础可打性 跳过友军优化、不可见目标、禁止被自动索敌的目标、失效 frozen actor。
4. Priority Profile 按 Priority 降序缓存；关系与 target type 必须匹配，invalid target type 优先否决。
5. 武器检查 ChooseArmamentsForTarget 必须能选出可用武器；不能移动时还要求当前距离可开火。
6. 射界检查 不能转向时必须已在 firing arc 内；能转向时之后交给 attack activity 或炮塔处理。
7. 最终选择 更高 Priority 压过距离；同优先级才选最近。

结论很具体：OpenRA 的自动索敌不是“最近敌人优先”。它是“最高有效 priority 优先，同 priority 最近”。 如果数据没有显式拉开 Priority，看起来才会像最近目标优先。

YAML Profiles

6. 数据配置画像

RA mod 的默认配置显示，OpenRA 把“什么目标值得自动打”交给 YAML profile，不写死在 C# 里。

Profile 默认行为 切换条件
^AutoTargetGround 默认自动打 Infantry、Vehicle、Ship、Underwater、Defense、Mine；不打 NoAutoTarget。 stance-attackanything 时切到包含 Structure 的 profile。
^AutoTargetGroundAssaultMove 继承 ground profile，但 AssaultMove 时也启用 attack-anything profile。 RequiresCondition: stance-attackanything || assault-move。
^AutoTargetAir 只自动打 AirborneActor，用于防空炮、SAM 等。 无额外 stance condition。
^AutoTargetAll 默认包含地面、水面、水下、空中与防御类，attack-anything 时包含 Structure。 用于能对多域目标开火的单位。
单位局部覆盖 例如 V2RL 设置 AutoTarget.ScanRadius: 10，潜艇重写 target types，巡洋舰配置多炮塔。 每个 actor YAML 可覆盖 inherited trait。
Disengage

7. 脱战与放弃

OpenRA 没有一个全局的“脱战系统”。脱战来自 activity 的结束条件、target 失效、姿态变化和 stop order。 单位从攻击活动退出来后，要么继续原本的移动/guard 子活动，要么回到 idle，再由 AutoTarget 决定是否下一次扫描。

攻击活动什么时候结束

  • 目标死亡、隐藏或失效，且没有可用 last-visible fallback。
  • 已经走到最后可见位置或射程附近，但目标仍不可见。
  • 没有可用武器，或武器 min/max range 不成立。
  • 需要移动进射程，但当前攻击不允许移动。
  • AttackMove 来源下出现补给需求时，不去补给，直接结束这段攻击活动。

目标什么时候被清理

  • OnStopOrder 会取消当前 activity，清空 requested/opportunity target。
  • owner 改变会清空目标。
  • 姿态变得更保守时，如果当前 opportunity target 不再符合 priority profile，会被丢弃。
  • AttackActivity.OnLastRun 调 ClearRequestedTarget；若 PersistentTargeting 为 true，会转成 opportunity target。

AttackFollow 的 last-visible target 是脱战的关键：它让单位在目标短暂进雾或离开视野时向最后位置靠近， 但到达后仍找不到目标就结束。这里没有无限追杀的默认保证。

Guard And Alert Range

8. 警戒与保护

OpenRA 至少有三种“范围”，不能混在一起。

范围 来源 含义
索敌扫描范围 AutoTargetInfo.ScanRadius 或 AttackBase.GetMaximumRange() 决定自动索敌能看多远。默认不单独配置时，基本等于武器最大射程。
Guard 跟随范围 GuardableInfo.Range，默认 2 cells；建筑常见 3 cells。 守卫单位与被保护目标保持的最大跟随距离，不等于警戒发现距离。
攻击进退范围 武器 MinRange/MaxRange 与 AttackFollowInfo.RangeMargin 追击时移动到能开火的距离环；目标移动时用 margin 减少抖动。

Guard 的实现非常短：目标必须是 actor，并且目标 actor 的规则里必须有 GuardableInfo。 然后它创建一个 AttackMoveActivity，移动子活动是 move.MoveFollow(self, target, WDist.Zero, range)。 所以 Guard 不是单独战斗 AI；它是“跟随目标 + attack-move 插入攻击”的复合活动。

Turret

9. 炮台实现

OpenRA 的炮塔由三层协作：Turreted 保存炮塔朝向和偏移，AttackTurreted 在攻击前让炮塔转向， Armament 绑定具体武器到某个 turret，并在开火前再次检查炮塔是否已经就位。

TurretedInfo

数据包括 Turret 名称、TurnSpeed、InitialFacing、RealignDelay、Offset。

AttackTurreted

CanAttack 遍历所有匹配炮塔，调用 FaceTarget。循环不会提前 break，因为多个炮塔都要转向。

Armament

ArmamentInfo.Turret 指向炮塔名；CanFire 中如果 turret.HasAchievedDesiredFacing 为 false，直接拒绝发射。

表现层

WithSpriteTurret、WithSpriteBarrel、WithTurretAttackAnimation 等读取同一 turret/armament 名称做渲染。

多炮塔

巡洋舰等单位可以有 Turreted@PRIMARY 与 Turreted@SECONDARY，AttackTurreted.Turrets 同时列出。

回正

不攻击时，Turreted.Tick 根据 RealignDelay 决定是否回到初始角度；-1 关闭回正。

炮塔 ready 是 gameplay 条件，不是渲染建议。即使 AttackTurreted.CanAttack 允许攻击， Armament.CanFire 仍会二次拦截未对准炮塔。这个设计避免表现和命中判定脱节。

Takeaways

10. 设计要点

要点 具体含义
索敌是单位能力，不是 bot 特权 AutoTarget 挂在 actor trait 上，人类单位、AI 单位、脚本单位都能复用。
目标优先级必须数据驱动 C# 只提供关系、target type、priority、condition 的筛选框架；具体哪些目标自动打由规则数据决定。
AttackMove 是可恢复 activity 它不是“移动 order + 攻击 order”简单排队，而是在一个 activity 内暂停移动、攻击、再恢复移动。
Guard 是复合移动，不是独立战斗系统 它把 follow target 当移动子活动，把战斗插入交给 AttackMoveActivity。
炮塔需要 gameplay authority 炮塔朝向、转速、ready 状态、muzzle 偏移会影响能否开火和弹体生成位置。
