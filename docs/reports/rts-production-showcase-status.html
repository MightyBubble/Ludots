Ludots RTS Production Showcase 汇报

现在这版到底在表达什么

这版 Red Alert/C&C 风格 showcase 的目标很简单：不用假数据，不另起一套 2D 世界， 让场景里的真实实体、真实选中、真实命令面板、真实生产队列串起来。 画面里的单位和建筑现在用基础几何体拼出来，点击和框选走 CoreInput，Web HUD 只负责显示和发正式命令。

场景实体：primitive child performer 点选：CoreInput 正式选中 Web 命令：走 GAS 命令面板 队列：OrderBuffer 有回归测试 C&C 生产模型：还不是 Core 一等能力

一句话结论

把最容易误会的几件事先说清楚。

当前状态
  • 场景里不是图片白点了。Red Alert 建筑和载具现在由 cube/sphere 等基础 mesh 的子 performer 组合出来。
  • 点选没反应的根因不是鼠标打不中，而是正式选中链路会检查“玩家是否看得见这个实体”。Red Alert showcase 之前没有喂这份可见性记录，现在补上了。
  • 框选盒是 CoreInput 的 Skia/屏幕覆盖层，不是 Web 层。Web 不应该也不会画第二个框选盒。
  • Web 面板不是 mock 数据。实体列表、选中对象、技能按钮、进度条和队列都从引擎快照读。
  • C&C 建造现在表达的是“先读条扣钱，完成后按钮变成放置”。但“钱不够就暂停、取消返款、多生产栏库存”等还需要 Core 扩建。

实体来自地图和模板，不来自 Web 假列表。

点击场景实体为什么现在能选中

这里没有绕过 CoreInput，也没有让 Web 直接“指定一个假选中”。

正式链路
1

鼠标点到场景

Raylib 把屏幕鼠标和地面点交给 CoreInput，场景实体本身带 VisualTransform、CullState 和 3D 盒子范围。

2

CoreInput 做命中判断

CurrentSelectionApplySystem 用实体的空间盒子判断鼠标是否点中，不看 Web 面板。

3

可见性通过正式服务

选中系统会问“本地玩家是否看得见这个实体”。Red Alert showcase 现在把可选中的地图实体写进正式可见性服务。

4

写入正式选中

点中后写入 SelectionRuntime 的 live primary selection，Web 面板、选中圈、命令卡都读这一份。

这里还有一块不是纯数据驱动。 Red Alert 当前是一个 showcase 系统把“本图所有可选实体都对本地玩家可见”写进去。 这不是旁路，但以后应该抽成 Core/通用 Mod 的配置，例如“这张 showcase 地图默认全图可见”。

框选盒到底是哪一层

只保留一个来源。

CoreInput
  • 框选盒来自 CoreInputMod 的 SelectionBoxOverlaySystem。
  • 它读本地玩家身上的 SelectionDragState，画到屏幕覆盖层。
  • Web HUD 不画框选盒，Web 点击只发 UI 命令。
  • 修正点：当鼠标按下时进入 Web UI 捕获，CoreInput 会清掉活跃拖拽状态，但不会清掉已经选中的实体。

Web 面板拿的是什么数据

Web 是 HUD，不是第二套战场。

正式数据
  • 实体列表读引擎里的 Name、队伍、位置、血量和当前选中状态。
  • Selection 面板读 SelectionRuntime 当前主选中。
  • 技能按钮读共享命令面板来源 gas.ability-slots。
  • Queue 面板读命令面板暴露的 active status 和 queued items。
  • 点击实体列表会写正式选中；点击技能会走共享命令面板激活，不直接改世界。
唯一容易误会的点： Web 代码里有一个空白初始 state，那只是等引擎第一包快照前用的空壳，不是 gameplay mock 数据。 但 Web HUD 里的头像/按钮小图标现在仍用了仓库已有 bitmap 做提示，场景实体本身没有用这些图。

C&C 式建造现在怎么跑

当前已经不是“点了马上放置”，但也还没到完整 C&C 生产建筑系统。

半成品模型
1

选中 Construction Yard

ConYard 模板上配置了 Build Power Plant、Build Refinery、Build War Factory 这些能力。

2

点 Build 按钮

Web HUD 激活共享命令按钮，正式订单进入 ConYard 的生产队列，不进入放置 ghost。

3

读条期间扣钱

能力时间轴每隔一段 tick 发一次扣钱效果。Power Plant 是 120 tick，Refinery 是 150 tick，War Factory 是 180 tick。

4

完成后存一个 Ready 标记

读条完成给 ConYard 加 State.Rts.RedAlert.Ready.*。命令面板看到这个标记后，把 Build 按钮换成 Place 按钮。

5

再点 Place，才进入放置

Place 按钮进入 CoreInput 的正式放置状态，鼠标确认地面点后，GAS CreateUnit 生成建筑。

已经做到 还没做到
建造先读条，完成后变成待放置按钮。 资源不足时暂停读条、资源够了继续。
读条期间有真实进度，Queue 面板能显示。 取消、返款、多个生产栏、按建筑类型堆库存。
第二个 Build 指令能留在 ConYard 队列里，不会立刻丢。 完整 C&C 建筑栏规则还不是 Core 的统一模型。

War Factory 训练坦克

不是只能点一下等一下。

有测试
  • War Factory 的第 3 个格子是 Train Rhino。
  • 点击后通过共享命令面板提交正式订单。
  • 订单进入 War Factory 自己的 OrderBuffer。
  • 当前回归测试覆盖了连续点两次：一个 active，一个 queued，最后产出两个 Rhino。
  • Rhino 完成时走 CreateUnit，不是 Web 直接塞一个坦克到列表。

哪些是干净 Mod

Red Alert showcase 不依赖 RtsDemoMod。

已隔离
  • Red Alert 地图、模板、能力、效果、表现都在 mods/showcases/rts_red_alert_like。
  • Browser HUD 在 mods/showcases/browser_rts_production，只通过 WebUI DataPlane 和正式命令入口沟通。
  • 共享能力来自 LudotsCoreMod、CoreInputMod、EntityCommandPanelMod。
  • RtsDemoMod 不再作为 Red Alert showcase 的基础。

还不是纯数据驱动的部分

这些现在能跑，但继续做 production 版最好进 Core 或通用 Mod。

需要扩建
现在怎么做 问题 建议扩建
Red Alert C# 系统把本图可选实体全部标成可见。 这是正式服务，不是旁路；但规则写死在 showcase 代码里。 Core/通用 Mod 加“地图默认可见性策略”配置。
选中圈由 Red Alert C# presentation system 画。 换一个 showcase 又要写一次类似代码。 Core Presentation 增加“选中反馈 overlay/performer 规则”配置。
C&C 建造用 GAS 时间轴和 tag 拼出读条与待放置。 资源不足暂停、取消返款、库存、多个生产栏都不是一等能力。 Core 增加正式 Production/Stockpile 模型，GAS 只负责触发和效果。
Web HUD 对队伍名、实体 kind、某些图标有代码里的判断。 换派系或换游戏味道时要改 C#/JS。 把 UI 展示名、分类、图标映射做成 mod 配置。
Queue 面板读 command panel 暴露的 status/queue。 够展示 active + queued，但没有通用“生产建筑面板”的领域语义。 Core 命令面板增加生产队列专用视图模型。
