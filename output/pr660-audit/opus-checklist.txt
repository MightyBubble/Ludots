 ### 1.2 统一零分配断言写法（消除 16 个稳定假红）

 文件：散布在 Association/Vision/GasCore/Presentation 等 62 个文件
 问题：46 处用硬 Assert.That(allocated, Is.EqualTo(0))，9 处用 LessThanOrEqualTo(64/512/1024)
 修法选项 A（推荐）：统一改为预算容差

 ```csharp
   // 替换所有 Is.EqualTo(0) 为：
   const int AllocationBudget = 64; // 单次调用理论上界
   Assert.That(allocated, Is.LessThanOrEqualTo(AllocationBudget),
       $"Hot path should allocate ≤{AllocationBudget} bytes, got {allocated}");
 ```

 修法选项 B：标注隔离

 ```csharp
   [Test, Category("Allocation")] // 从主门禁排除
   public void SomeHotPath_AllocatesZeroAfterWarmup() { /* ... */ }
 ```

 然后 CI 主门禁用 --filter "Category!=Allocation"，单开一条容忍失败的 Allocation 泳道。

 为何修：当前 ScopeResolver/FogField/KnowledgeProjection 等 16 个测试在 .NET 10 SDK + Release 下稳定失败（实测分配 24–512 字节），但这些分配来自 JIT/GC 后台活动，不是被测代码。硬零断言让真实回归（如意外装箱、闭包逃逸）淹没在噪声里。
 游戏情景：玩家在战争迷雾（FogField）中移动单位，系统每帧要查询 10×10 区块的可见性并更新脏标记。FogField_ReadWriteHotPathAllocatesZeroAfterWarmup 测的是"这个循环不该产生 GC 压力"——但因为断言太严（0 字节），SDK 升级、PGO 策略变化都会让它红，掩盖真正的性能倒退（比如有人改了查询逻
 辑意外触发 LINQ ToArray()）。改成 ≤64 字节后，噪声消失，真倒退才会触发。

 ### 2.2 收敛源码扫描 guard 到 ArchitectureTests

 文件：32 个文件含 File.ReadAllText + 禁词检查
 问题：如 AiShowcaseHardcodingGuardTests 扫描 .cs 查"hardcoded coordinates"
 修法：删除功能测试里的扫描，统一到：

 ```csharp
   // src/Tests/ArchitectureTests/Governance/ShowcaseDataDrivenGuard.cs
   [Test]
   public void AllShowcaseMods_BehaviorFromDataFiles_NotHardcoded()
   {
       foreach (var modDir in GetShowcaseMods())
       {
           var sourceFiles = Directory.GetFiles(modDir, "*.cs", Recursive);
           var dataFiles = Directory.GetFiles(modDir, "*.json", Recursive);
           Assert.That(dataFiles, Is.Not.Empty, $"{modDir} must have data files");
           // 运行时验证：加载 mod，检查行为来自 Registry 而非常量
           var registry = LoadModBehaviorRegistry(modDir);
           Assert.That(registry.IsDataDriven, Is.True);
       }
   }
 ```

 从验证"文件里没出现字符串"变为"运行时行为来自 Registry"。

 为何修：源码扫描脆且信号低。PR #660 已删过 3 个 Navigation 禁词测试（会误伤文档和断言文本），但 GasTests 残留 32 个同类。
 游戏情景：AI showcase 要求"敌人巡逻路径从 JSON 读，不能硬编码坐标"。当前 AiShowcaseHardcodingGuardTests 扫描 .cs 查 new Vector3(100, 200)。某次重构把坐标改成字符串拼接 $"({x},{y})" 就绕过了检查。改成运行时断言"巡逻点数 == JSON 文件定义的数量"后，才能真正锁住契约。

 ### 3.1 补 DEBUG 配置 CI 泳道

 问题：冲突检测等只在 DEBUG 生效，Release 下测试直接 Assert.Pass
 修法：.github/workflows/solution-verify.yml 加一条：

 ```yaml
   - name: Run GasTests (Debug for conflict detection)
     run: dotnet test src/Tests/GasTests -c Debug --filter "ConflictDetection"
 ```

 为何修：PR #660 的全部证据是 Release，意味着 ModRegistrationConflictTests 的 3 个测试根本没跑，合并时冲突检测契约完全没被验证。
 游戏情景：两个 mod 都注册了函数 "onUnitDeath"，后加载的会覆盖前者。冲突检测在 DEBUG 下会记录 ConflictReport（触发警告面板），但 Release 直接静默覆盖。如果 CI 只跑 Release，团队永远不知道这个保护机制坏了——直到玩家报 bug"装了 ModA+ModB 后 ModA 的单位死亡事件失效"。
