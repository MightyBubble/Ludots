# cfg-01 editor spec · mod 数据

> 编辑器实现任务书。编辑器需求见 [cfg-01 UXD](../uxd/cfg-01-mod-manifest.md)；引擎侧实现见 [cfg-01 runtime spec](../spec-runtime/cfg-01-mod-manifest.md)；第一性需求见 [cfg-01 PRD](../prd/cfg-01-mod-manifest.md)。

## 1. 概述

编辑器对 mod 数据的全部实现：清单表单、规范化保存、多 mod 工作区、依赖图、新建向导。目标是用一套字段元数据驱动表单与校验，保存复用引擎的规范化序列化，不重写解析。

## 2. 设计

### 表单模型

- 字段元数据单一来源：字段集合、类型、必填、分组、校验规则（含"未知字段不可能产生"的白名单约束）由元数据定义，表单渲染与校验都消费它；清单 schema 变更只改元数据。
- 身份字段（name、version、dependencies、main）单独分组，标注重启级生效。

### 保存管线

- 写回走引擎规范化序列化（往返无损：解析 → 序列化 → 再解析结果一致），字段序与缩进稳定。
- 保存前跑同一份解析校验：未知字段、类型不符、空值在编辑器内报出，与启动错误同源。

### 工作区模型

- 工作区 = 多个已打开 mod 的集合；按清单 name 建索引，重名在打开与新建时即时检出。
- 身份变更（改名/改依赖）触发工作区级广播：依赖图、资产浏览器、运行预设刷新。

### 依赖图

- 数据源为工作区内全部清单的 dependencies；渲染 DAG，检测环、缺失依赖、版本范围不满足，错误定位到边。
- 点节点跳转对应 mod 项目。

### 新建向导

- 产物模板：目录骨架（默认配置根）+ 最小合法清单 + 可选代码骨架（空入口类型）。
- 产物必须一次通过解析校验（与保存管线同一校验器）。

## 3. 精确语义与不变量

- 往返无损：任何经编辑器保存的清单，再解析得到相同数据。
- 封闭字段集：表单与向导不可能产出白名单之外的字段。
- 重名、环、缺失依赖的编辑器判定与引擎启动判定同源（同一套校验规则），不允许两套规则各自漂移。
- 身份字段修改保存后标记"待重启"，并列出工作区内受影响的运行配置。

## 4. 依赖的引擎接口与验收

- 消费：清单严格解析、规范化序列化、版本范围语法（复用，不重实现）。
- 验收：向导产物可直接被引擎加载启动；随机编辑-保存循环 N 次后清单 diff 仅含用户改动；注入环与重名在图上正确标出。
