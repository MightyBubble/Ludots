# ord-01 · 订单类型

> 第一性需求 · 已冻结。配置写法见 [配置说明](../config/ord-01-types.md)；编辑器需求见 [UXD](../uxd/ord-01-types.md)；引擎实现见 [runtime spec](../spec-runtime/ord-01-types.md)；editor spec 见 [editor spec](../spec-editor/ord-01-types.md)；现状见 [reference](../reference/ord-01-types.md)。

## 1. 定位

订单类型是命令的物种表：每种可下给实体的命令（施法、移动、攻击目标、停止）在此声明排队与执行参数；订单系统的其余一切表都以这里的类型 key 为词汇。

## 2. 产品承诺

- **三段一体**：黑板键、类型、规则三段同居一份表；可空段必须显式存在，缺席即失败。
- **语义编号自动分配**：类型编号可写整数，也可写与条目 key 逐字相同的语义串，按字典序从 1 取最小空闲编号——语义串是声明手段，不是别名机制。
- **必备类型有底线**：施法、移动、攻击目标、停止四类的编号由游戏配置常量定义，装配期缺失即失败；mod 扩充物种，不能掏空底座。
- **参数即合同**：排队策略、满队策略、打断许可、黑板落点、瞬时完成——类型参数决定一份订单在实体缓冲中的完整命运。

## 3. 运行行为

每次加载先清空两注册表再重建：注册黑板键 → 两遍式编号分配（先整数后语义）→ 注册类型 → 注册规则；字段名严格区分大小写，未知字段拒绝。

## 4. 异常承诺

编号重复或越界、语义串与条目 key 不一致、三键组引用未注册黑板键、重声明内置键、键段值非真、瞬时完成缺存储目标键组——一律启动失败并指明条目与位置。
