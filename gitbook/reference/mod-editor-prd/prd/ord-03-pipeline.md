# ord-03 · 订单流水

> 第一性需求 · 已冻结。配置写法见 [配置说明](../config/ord-03-pipeline.md)；编辑器需求见 [UXD](../uxd/ord-03-pipeline.md)；引擎实现见 [runtime spec](../spec-runtime/ord-03-pipeline.md)；editor spec 见 [editor spec](../spec-editor/ord-03-pipeline.md)；现状见 [reference](../reference/ord-03-pipeline.md)。

## 1. 定位

订单流水是从"一次提交"到"一个终态"的全链路：全局队列准入 → 实体缓冲排队 → 激活执行 → 终态发布。规则与类型（ord-01/02）决定裁决，本篇决定裁决结果如何流动。

## 2. 产品承诺

- **单笔四步、批量原子**：一次提交走"预留、校验、入队、确认"，任一步失败即整体未发生；批量三形态（逐条独立、整批共享单号、按命令源聚类）要么整批入队要么整批不变。
- **双代结果可见**：准入结果按逻辑步换代；未配对的已接受结果跨代前向携带，不静默丢失。
- **实体缓冲秩序**：固定数量的类型队列按优先级降序、同序先来先到；一个待定槽后写覆盖；一个活动单。
- **终态发布有账本**：完成不带原因、失败必带原因；终态化统一完成清黑板、释放载荷、释放延续、发布快照。
- **溢出宁可停机**：容量拒绝进独立拒绝区；拒绝区也满则进入终端故障，绝不静默丢单。

## 3. 运行行为

每个逻辑步：换代并前向携带 → 实体摄入期提交与消费 → 摄入收尾 → 逻辑步收尾；主队列与响应链队列共用同一份准入结果缓冲。

## 4. 异常承诺

容量不足的提交被拒并记录拒绝原因；两级缓冲全满进终端故障；终态与原因组合非法即拒绝终态化——全部可观察。
