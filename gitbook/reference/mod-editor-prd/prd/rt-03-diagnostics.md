# rt-03 · 诊断与错误码

> 第一性需求 · 已冻结。配置写法见 [配置说明](../config/rt-03-diagnostics.md)；编辑器需求见 [UXD](../uxd/rt-03-diagnostics.md)；引擎实现见 [runtime spec](../spec-runtime/rt-03-diagnostics.md)；编辑器实现见 [editor spec](../spec-editor/rt-03-diagnostics.md)；现状见 [reference](../reference/rt-03-diagnostics.md)。

## 1. 定位

诊断通道是运行时自我报告的唯一结构化出口：哪个系统丢了什么、容量多少、发生了几次，逐帧成事件。错误码是异常的命名法——一个码一处含义，可被检索与统计。

## 2. 产品承诺

- **九域全覆盖**：响应链、效果提案、效果生命周期、tag 容器、活动效果容器、相位监听、事件总线、订单准入、效果应用——每个丢弃/溢出事件都归属其一。
- **四要素事件**：帧号、系统、指标、容量与计数——诊断数据可聚合可回放，不是日志散文。
- **只报非零**：零计数的指标不发布，通道里每条都是实事。
- **诊断自身 fail-fast**：诊断缓冲满即抛错——报告通道自己不许丢自己的事件。
- **指标编号以枚举为准**：编号存在保留空号，数量以命名值为准，工具不按连续编号假设。

## 3. 运行行为

帧首诊断缓冲清零；各系统与帧末报告系统按 System×Metric 发布非零计数；消费者（编辑器/工具）逐帧镜像与聚合。

## 4. 异常承诺

诊断缓冲溢出抛错并带容量与帧号；订单溢出计数回退发布专用诊断错误。错误码字面量唯一归属一个抛出点，码格式稳定不改义。
