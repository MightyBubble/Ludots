# rt-04 · 表现事件

> 第一性需求 · 已冻结。配置写法见 [配置说明](../config/rt-04-presentation.md)；编辑器需求见 [UXD](../uxd/rt-04-presentation.md)；引擎实现见 [runtime spec](../spec-runtime/rt-04-presentation.md)；editor spec 见 [editor spec](../spec-editor/rt-04-presentation.md)；现状见 [reference](../reference/rt-04-presentation.md)。

## 1. 定位

表现事件是逻辑层发给表现层的单向回执：施法与效果的关键转折各成一种事件，动画、音效、UI 只消费这张回执，不读逻辑内部状态。

## 2. 产品承诺

- **九种事件覆盖两端**：施法五种（开始/失败/提交/完成/打断）与效果四种（应用/激活/过期/取消）——表现层需要的每个转折都有对应事件，无"凑合用别的"。
- **失败原因结构化**：施法失败带七值枚举（冷却/tag 拦截/无目标/槽无效/未存活/前置失败），不解析文本。
- **负载自足**：每事件带施法者、目标、槽位、技能/模板/属性 id 与增量——消费方不回查逻辑态也能播。
- **溢出是配置错误**：缓冲满即抛错，不丢事件——事件量不该超过容量，超了改容量而不是忍丢。
- **事务可回滚**：效果事务失败时，本事务已写的表现事件一并撤销——表现层不会播一个被回滚的命中。

## 3. 运行行为

固定 tick 内逻辑系统写入每 tick 缓冲；表现投影系统在表现标志清除组消费并把事实投给表现流；容量来自游戏配置的 presentation 块，启动期装配。

## 4. 异常承诺

缓冲容量非法（≤0）启动失败；缓冲满抛错并指明容量与事件种类——这是配置错误，修复路径只有改容量或减事件量。
