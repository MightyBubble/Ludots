# cfg-01 · mod 数据

> 第一性需求 · 已冻结。配置写法见 [cfg-01 配置说明](../config/cfg-01-mod-manifest.md)；编辑器需求见 [cfg-01 UXD](../uxd/cfg-01-mod-manifest.md)；runtime spec 见 [cfg-01 spec](../spec-runtime/cfg-01-mod-manifest.md)；现状见 [cfg-01 reference](../reference/cfg-01-mod-manifest.md)。

## 1. 定位

mod 是引擎的可装配数据单元——一切内容（配置、资产、代码）的容器。本篇只回答第一性问题：一个 mod **是**什么、产品**承诺**什么。字段怎么写、入口代码怎么挂，见配置说明。

## 2. 产品承诺

- **身份唯一**。每个 mod 有全局唯一的名字；这个名字同时是它全部文件的地址前缀与挂载点名。重名即拒绝启动。
- **声明依赖即获得覆盖权**。依赖先加载、依赖者后加载，后者写的配置字段覆盖前者；依赖关系是有向无环图，成环即拒绝。
- **版本是依赖关系的输入**。三段版本号；被依赖时按声明范围校验，不符即拒绝。
- **代码可选**。mod 可以是纯数据；带代码时拥有一个入口，入口只在加载窗口运行——可注册扩展、挂系统，不能在窗口外改世界。
- **字段集合封闭**。身份数据不接受未知字段——想表达新东西，走治理扩展，不走私加字段。
- **位置自由**。mod 目录可放磁盘任何位置；只要发现根（启动器扫描根、启动计划、调试直启的显式路径）指向它。

## 3. 运行行为

- 装配顺序由启动计划唯一决定（cfg-03），身份数据里的排序字段不影响正常启动顺序。
- **装配先于配置编译**：入口代码注册的扩展，供随后的配置编译引用（cfg-04、cfg-08）。
- 启动完成后身份数据不可变；改身份是重启级操作。

## 4. 异常承诺

缺失必填字段、未知字段、类型不符、依赖缺失、版本不符、重名、成环——一律启动失败，并指出具体文件与位置。
