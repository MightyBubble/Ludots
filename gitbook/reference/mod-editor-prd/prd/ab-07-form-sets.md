# ab-07 · 形态路由

> 第一性需求 · 已冻结。配置写法见 [配置说明](../config/ab-07-form-sets.md)；编辑器需求见 [UXD](../uxd/ab-07-form-sets.md)；引擎实现见 [runtime spec](../spec-runtime/ab-07-form-sets.md)；editor spec 见 [editor spec](../spec-editor/ab-07-form-sets.md)；现状见 [reference](../reference/ab-07-form-sets.md)。

## 1. 定位

形态路由是"状态换技能组"的机制：单位带着什么状态 tag，八个槽位就整组换上哪套技能——锤形态一套、炮形态一套。一张路由表声明全部形态。

## 2. 产品承诺

- **路由即规则**：每条路由 = 状态条件（须全在场 + 任一禁在场）+ 优先级 + 一组槽位覆盖；匹配即占槽。
- **优先级定胜负**：多条路由同时匹配时，优先级严格更高者胜；不高不低时先者保持。
- **每帧实时**：状态进、技能组进；状态出、技能组退——形态切换无残余。
- **声明即校验**：路由表在启动期全量校验（槽号范围、引用已注册技能、路由结构），错表不进游戏。
- **只动形态层**：路由只写槽位的形态层，不碰底座与物品槽——三来源可叠加共存。

## 3. 运行行为

每帧对持有形态槽缓冲的单位：清空形态层 → 依序评估全部路由 → 匹配者按优先级竞争 → 胜者槽位覆盖写入。路由表加载后冻结。

## 4. 异常承诺

路由空槽覆盖、优先级缺失、槽号越界、同路由重复槽号、引用未注册技能、根级路由为空——启动失败并指明表项。
