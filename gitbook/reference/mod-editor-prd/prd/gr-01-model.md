# gr-00 · 图编程模型

> 第一性需求 · 已冻结。配置写法见 [配置说明](../config/gr-01-model.md)；编辑器需求见 [UXD](../uxd/gr-01-model.md)；引擎实现见 [runtime spec](../spec-runtime/gr-01-model.md)；编辑器实现见 [editor spec](../spec-editor/gr-01-model.md)；现状见 [reference](../reference/gr-01-model.md)。

## 1. 定位

Graph 是贯穿效果、技能、AI 的可编程面：一张 JSON 文档编译成定长指令序列，在一台零堆分配的寄存器机上执行；效果相位、能力前置、AI 打分等八个挂接点消费同一种程序形态（gr-07）。

## 2. 产品承诺

- **一种文档一种机器**：六种创作 kind（gr-02）共用同一文档格式（gr-01）与同一编译器（gr-03），差别只在返回槽与节点白名单。
- **编译确定**：同一文档必然编译出同一指令序列；字符串符号在装载期解析为整数 id 并回写，运行期零字符串查找。
- **预算封顶**：寄存器、目标数、调用深度、单次执行指令数全部有硬上限，超限即失败——不存在无界执行。
- **注册即终态**：程序注册后不可原地改写，替换走显式边界；装载末尾注册表冻结，冻结后不再接受注册。
- **挂起是一等状态**：执行游标可跨帧挂起并恢复；是否允许挂起由宿主政策决定（gr-04）。

## 3. 运行行为

装载顺序 graphs → func_lib → action_lib，末尾冻结；执行时三个预设实体寄存器由宿主绑定；指令预算由整棵跨图调用树共享。

## 4. 异常承诺

编译诊断不通过拒绝装载并指明图与节点；执行期预算耗尽、调用深度超限、在不允许挂起处挂起——一律失败并指明图。
