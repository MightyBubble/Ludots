# cfg-04 · 配置表体系

> 第一性需求 · 已冻结。配置写法见 [配置说明](../config/cfg-04-config-tables.md)；编辑器需求见 [UXD](../uxd/cfg-04-config-tables.md)；引擎实现见 [runtime spec](../spec-runtime/cfg-04-config-tables.md)；编辑器实现见 [editor spec](../spec-editor/cfg-04-config-tables.md)；现状见 [reference](../reference/cfg-04-config-tables.md)。

## 1. 定位

引擎的全部玩法数据放在一张张配置表里。本篇定义表体系的规则：有哪些表、表怎么声明与加载、JSON 怎么写、怎么新增一张表。

## 2. 产品承诺

- **户口本原则**：没在配置目录登记的 JSON 不是配置——配置世界的边界由目录划定。
- **五步加载链**：登记 → 收集 → 合并 → 编译 → 注册；编译通过的条目进注册表（名字换 id），此后按 id 引用。
- **加载顺序 = 注册顺序 = 引用许可**：同表内可前向引用，跨表只能引用已加载表。
- **注册后冻结**：启动完成后注册表只读；运行期改值走工作台热通道。
- **书写严格**：未知字段即错、枚举精确匹配、大小写敏感——没有宽容解析。
- **分片合法**：登记了分片目录的表可以一条一个文件，与主文件汇入同一合并管线。
- **扩展优先于新表**：新图节点、效果处理器、表现扩展走代码注册面；新增配置 schema 是最后手段，须过治理审批。

## 3. 运行行为

目录先于一切表加载；扩展枢纽冻结后配置才编译（配置可引用代码注册的扩展键）；每张表一次编译定形，失败即启动失败。

## 4. 异常承诺

登记缺字段、策略拼错、未知字段、枚举拼错、条目缺 id、引用未注册 id——一律启动失败并指明位置。
