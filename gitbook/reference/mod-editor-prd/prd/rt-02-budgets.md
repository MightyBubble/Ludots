# rt-02 · 预算与容量

> 第一性需求 · 已冻结。配置写法见 [配置说明](../config/rt-02-budgets.md)；编辑器需求见 [UXD](../uxd/rt-02-budgets.md)；引擎实现见 [runtime spec](../spec-runtime/rt-02-budgets.md)；editor spec 见 [editor spec](../spec-editor/rt-02-budgets.md)；现状见 [reference](../reference/rt-02-budgets.md)。

## 1. 定位

预算是"这一帧允许发生多少事"的合同：帧计数器记账、单根扇出上限拦爆、容量上限定缓冲大小。三层各管一件事：容量是"碗多大"、单根上限是"一个根最多舀几勺"、帧计数是"这碗装了多少"。

## 2. 产品承诺

- **每帧记账清零**：帧开始复位全部预算计数器，帧号自增——计数器永远只描述当前帧。
- **单根扇出上限**：一个根效果单帧创建数有上限（见事实页），超限拒绝该次创建并计数，不是崩溃也不是静默。
- **无根不记账**：根 id 为 0 的创建不参与单根记账，恒放行。
- **溢出可见**：九类丢弃计数（创建/深度/步预算/队列溢出/tag 容器/活动效果容器/监听注册/监听派发/事件总线）逐类累加，帧末进诊断通道（见 rt-03），按系统与指标发布。
- **订单准入水位可见**：backlog、高水位、溢出与拒绝原因按帧发布；溢出计数只增不减，回退即报异常。
- **表容量与单根上限分离**：记账表能容纳多少个不同根（容量）与每个根最多创建多少（上限）是两个数，互不推导。

## 3. 运行行为

帧首预算复位系统清零计数器；效果处理与订单准入内联消费预算（单根表开放寻址、戳记换帧 O(1)，事务内可打检查点、提交或回滚）；帧末报告系统把非零指标发布到诊断缓冲。

## 4. 异常承诺

预算超限不抛错——拒绝操作、计数、继续。事务误用（检查点重入、回滚容量超限、对失效检查点回滚）抛错并带错误码。订单溢出计数回退抛诊断错误。
