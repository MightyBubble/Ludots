# rel-01 · 关系目录

> 第一性需求 · 已冻结。配置写法见 [配置说明](../config/rel-01-catalog.md)；编辑器需求见 [UXD](../uxd/rel-01-catalog.md)；引擎实现见 [runtime spec](../spec-runtime/rel-01-catalog.md)；editor spec 见 [editor spec](../spec-editor/rel-01-catalog.md)；现状见 [reference](../reference/rel-01-catalog.md)。

## 1. 定位

关系目录是关系系统的词表：`catalog.json` 声明类型、度量、旗标三块，`projection.json` 声明知识授予。图的关系节点族、技能 / AI / 命令 / 表现的敌我筛选都引用这里的 id。

## 2. 产品承诺

- **四块各司其职**：类型定关系的形状（对称与否、要不要物化成带组件的实体），度量和旗标是边上的数值与开关，知识授予定沿哪种边分享哪些情报。敌我不单独成块：`Hostile`、`Friendly` 这类名字就是普通关系类型，谁对谁敌对由地图里队伍代表之间的边决定。
- **只声明有人读的词**：每个类型都要有功能读取它；"有关系就行"的占位类型不进目录。
- **声明一次全局引用**：目录 id 是关系域的命名空间；图节点、筛选、关系操作全部按 id 引用，装载期解析。
- **跨 mod 覆盖合并**：各块按 id 合并，mod 只写自己要新增或覆盖的条目。
- **没连边就没关系**：没有声明、也没有连边的两队互不识别为敌人或盟友。

## 3. 运行行为

目录在关系系统装配前加载（DeepObject 合并）；图节点和各类筛选里的关系类型名在此解析。

## 4. 异常承诺

未知块、未知字段、缺 id、放错文件的块、引用不存在的目录 id——装载失败并指明片段与条目。
