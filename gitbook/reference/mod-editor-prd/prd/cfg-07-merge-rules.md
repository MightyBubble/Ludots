# cfg-07 · 合并规则案例集

> 产品承诺 · 已冻结。理想实现见 [cfg-07 spec](../spec-runtime/cfg-07-merge-rules.md)；现状见 [cfg-07 reference](../reference/cfg-07-merge-rules.md)。

## 1. 定位

"我想改对方的一个字段 / 加一条内容 / 屏蔽一个条目——怎么写？结果是什么？"这一篇把跨 mod 合并的全部情况收敛成十种案例，每种给**意图 → 写法 → 结果**，并标出会踩坑的危险字段。规则本体见 cfg-05。

## 2. 案例与行为

| # | 意图 | 写法 | 结果与坑 |
|---|---|---|---|
| 1 | 新增内容 | 新 id 条目 | 整条加入；结果顺序 = id 首次出现序 |
| 2 | 改对方一个标量 | 同 id + 只写该字段 | 你赢该字段，其余保留 |
| 3 | 扩展对方的对象 | 同 id + 只写对象子路径 | 递归合并，可只写一片叶子（如 `phaseGraphs.OnPeriod.post`） |
| 4 | 改对方数组里的一个元素 | **做不到** | 数组整体替换：必须整组重写（见危险清单） |
| 5 | 追加数组元素 | 仅当字段在目录登记为可追加 | 当前没有任何字段如此登记，对作者即"不存在追加" |
| 6 | 屏蔽对方条目 | 同 id + `"__delete": true` | 时序删除：只删此前出现的该 id；之后加载的 mod 写同名会复活 |
| 7 | 删除自己拥有的行 | 物理删除本 mod 文件里的行 | 与 `__delete` 是两种语义，不要混用 |
| 8 | 整文件级配置 | 时钟、订单类型、属性约束、游戏配置这类文件 | 对象深合并：对象递归，标量与数组后到者覆盖 |
| 9 | mod 内两位置并存 | `assets/` 与 `assets/Configs/` 同名 | Configs 后到、生效；合法但建议固定一种放法 |
| 10 | 大小写 | 一律敏感 | 路径、策略名、去重字段名、id 全部区分大小写 |

危险数组清单——以下字段覆盖即**整组替换**，改一项须重写整组：

- 技能：执行时间轴 `items`、`blockTags` 两组、`interruptAny`、`callerParams` 各组、`toggleSpec.activeEffects`
- 效果：`modifiers`、`grantedTags`、`phaseListeners`、`tags`
- Tag 规则：六组规则数组
- 订单类型：`blockedActiveOrderTypeKeys`、`interruptsActiveOrderTypeKeys`
- 形态路由 `routes`、上下文组 `candidates`
- AI 各表：考虑项、任务、决策、决策者、过滤操作、标签

## 3. 文件结构

案例本身不产生新文件——写法落在 cfg-05 描述的两个合法位置之一；登记了分片目录的表，也可一条一个分片文件（见 cfg-04）。

## 4. 预期反馈

- **启动期**：全部裁决一次定形，运行期不再变化。
- **运行期**：两个无依赖关系的 mod 覆盖同一字段时，胜负由启动计划顺序决定（cfg-03），可直接从计划文件读出。
- **编辑器内**：合并预览按本篇案例分类展示差异，危险数组字段给"将替换对方 N 项"警示。

## 5. 异常处理

| 异常情形 | 系统响应 |
|---|---|
| 删除标记想屏蔽"之后"加载的条目 | 不生效——屏蔽只作用于此前片段，需由更晚的 mod 再写一次 |
| 数组字段只写了部分元素 | 不是追加而是整组替换——对方的其余元素消失，编辑器会预警 |

## 6. 编辑器要点

- 合并预览按案例分类渲染差异：新增 / 覆盖标量 / 扩展对象 / 整组替换（警示替换 N 项）/ 删除。
- 危险数组清单由字段元数据驱动，不手抄维护。
- 删除操作区分物理删除与屏蔽两义。
- 热应用级别：合并结果为重启级。

## 7. 实例

改对方一个标量（案例 2）：

```json
[ { "id": "Effect.Example.Income", "modifiers": [ { "attribute": "Gold", "op": "Add", "value": 8 } ] } ]
```

屏蔽（案例 6）：

```json
[ { "id": "Effect.SomeMod.Something", "__delete": true } ]
```
