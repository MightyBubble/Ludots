# ord-02 · 订单规则与打断

> 第一性需求 · 已冻结。配置写法见 [配置说明](../config/ord-02-rules.md)；编辑器需求见 [UXD](../uxd/ord-02-rules.md)；引擎实现见 [runtime spec](../spec-runtime/ord-02-rules.md)；编辑器实现见 [editor spec](../spec-editor/ord-02-rules.md)；现状见 [reference](../reference/ord-02-rules.md)。

## 1. 定位

订单规则是命令之间的交通法：一份新单能否被在场的其他命令拦下、能否顶掉正在执行的命令——阻止与打断两张判定表，配合类型自带的排队策略构成完整裁决。

## 2. 产品承诺

- **一类型一规则**：每个类型一条规则，声明它被哪些在场命令阻止、它能打断哪些活动命令；数组可空但字段必填。
- **打断默认不可**：跨类型打断必须显式声明；查表无规则即不可打断。同型打断只看类型自身的打断许可。
- **打断是原子链**：打断发生时先为被顶订单落终态，再激活新单，一步之内完成，无中间可见状态。
- **顶不掉就排队**：不可打断的新单退化为同型策略裁决——排队、挤掉同类或丢弃，由类型参数决定（见 ord-01）。

## 3. 运行行为

提交先分派排队态或即时态；即时单三步裁决：阻止判定（在场命令命中阻止表即拒收）→ 打断判定 → 打断链或排队退化；打断链按"预写参数、终态化旧单、按需清队、激活新单"顺序完成。

## 4. 异常承诺

规则引用未注册类型、同条规则重复引用、单张表超过容量——一律启动失败并指明规则与位置。
