# cfg-05 · 配置管线与跨 mod 合并

> 第一性需求 · 已冻结。配置写法见 [配置说明](../config/cfg-05-config-pipeline.md)；编辑器需求见 [UXD](../uxd/cfg-05-config-pipeline.md)；引擎实现见 [runtime spec](../spec-runtime/cfg-05-config-pipeline.md)；编辑器实现见 [editor spec](../spec-editor/cfg-05-config-pipeline.md)；现状见 [reference](../reference/cfg-05-config-pipeline.md)。

## 1. 定位

各来源的同名表合并成一份的裁决规则。谁生效、怎么覆盖、怎么屏蔽——合并语义的合同本体；案例速查见 cfg-07。

## 2. 产品承诺

- **一份真相**：任一表在任一时刻只有一份合并结果，运行期消费的永远是它。
- **后到者赢，且只赢写到的字段**：同 id 深合并——字段级覆盖、对象递归、数组整组替换。
- **顺序唯一事实来源是启动计划**：覆盖胜负在生成期确定，可从计划直接读出；无运行期决胜。
- **覆盖持久**：下游写过的字段持续压住上游同字段的后续修改——上游升级不等于覆盖让位。
- **删除有时序**：屏蔽标记只删此前加载的同名条目，不延续到更晚的 mod。
- **命名空间全局扁平**：所有配置 id 跨 mod 共享，靠前缀分层。
- **一次定形**：合并只在启动期发生（重载为预留接口）；重进地图不重新合并。

## 3. 运行行为

收集（含分片）→ 合并 → 编译 → 注册一次走完；失败即启动失败。

## 4. 异常承诺

文件缺失静默跳过；语法错误、条目缺 id、未登记路径、引用不存在——启动失败并指明位置。
