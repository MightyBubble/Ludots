# rt-05 · 事件总线与帧延迟

> 第一性需求 · 已冻结。配置写法见 [配置说明](../config/rt-05-events.md)；编辑器需求见 [UXD](../uxd/rt-05-events.md)；引擎实现见 [runtime spec](../spec-runtime/rt-05-events.md)；编辑器实现见 [editor spec](../spec-editor/rt-05-events.md)；现状见 [reference](../reference/rt-05-events.md)。

## 1. 定位

玩法事件总线是分拍管道：本帧发布、帧末交换、下一帧消费。一拍延迟不是性能妥协，是时序合同——所有跨系统反应都在同一拍边界上对齐。

## 2. 产品承诺

- **恒定一拍延迟**：本帧发布的事件，跨帧消费者最早下一拍看见——事件序确定性可回放。
- **双缓冲读写隔离**：发布写次缓冲，消费读当前缓冲，读写永不相交；交换在帧末一次完成。
- **发布满即抛**：单帧事件数超容量是设计错误，fail-fast 报错，不丢事件。
- **写事务可回滚**：效果事务失败时，本事务已发布的事件随事务撤销——下一拍不会有幽灵事件。
- **同帧等待者例外**：同帧内显式等待者按现状语义读当前缓冲（tag-03 同帧可见）。
- **遥测是旁路不是主道**：响应链遥测缓冲记录窗口生命周期六事件与六种结果，供编辑器观测；其溢出语义独立于主总线（见异常承诺）。

## 3. 运行行为

发布发生在技能激活与效果处理组（写次缓冲）→ 帧末事件分发组交换双缓冲并结算丢弃计数 → 下一拍消费者（反应系统、技能执行、延迟触发处理）读当前缓冲。组序恒定：技能激活 → 效果处理 → 事件分发。

## 4. 异常承诺

主总线发布满抛错并带容量与事件 tag。响应链遥测缓冲溢出现状为计数丢弃（静默）——与主道 fail-fast 不同，该不一致已入治理（见 spec-runtime）。
