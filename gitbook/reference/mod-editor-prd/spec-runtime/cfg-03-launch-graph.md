# cfg-03 spec · 启动计划

> 理想技术实现。现状见 [cfg-03 reference](../reference/cfg-03-launch-graph.md)；产品承诺见 [cfg-03 prd](../prd/cfg-03-launch-graph.md)。

## 1. 概述

启动计划的生成与校验链路保持"顺序与指纹在生成期锁定"的合同；编辑器侧的组合预览与启动入口直接复用计划生成服务，不另造组合推导。

## 2. 设计

### 生成合同

- 输入：选择器（支持绑定别名与预设递归展开）+ 根 mod 集合；输出：依赖闭包拓扑序 + 计划指纹 + 计划文件与锚文件。
- 指纹覆盖：适配器、构建模式、选择器、mod 集合与顺序、产物路径、浏览器运行时配置——任一变化即指纹变化。
- 计划产物自指：计划文件内的产物路径必须指向自身与配套锚文件，防陈旧复用。

### 启动校验合同（三重）

1. 产物自指校验：计划声明的产物路径与实际文件一致。
2. 锚-计划核对：锚文件记录的选择器、根 mod、顺序、指纹与计划逐项相等。
3. 适配器/浏览器运行时一致性：不一致即拒绝启动。

### 编辑器集成

- 组合预览调用生成服务做"只算不写"（dry-run）：返回闭包与顺序供 DAG 渲染，不落计划文件。
- 启动入口调用完整生成并启动，编辑器内运行与外部运行共用同一产物。
- 预设持久化为选择器 + 根 mod 集合，不含推导结果。

## 3. 精确语义与不变量

- mod 顺序唯一决定因素：依赖闭包解析（DFS 后序、依赖按键名字母序访问），生成期烘焙；无运行期平局决胜，priority 不参与。
- 计划为只读消费：引擎侧不修改计划，只按序加载；任何组合变更必须重新生成。
- 同一目录同时只允许一个活动计划产物集合（并发生成以最后一次为准，部署侧串行化）。

## 4. 迁移与治理

1. 生成服务暴露 dry-run 与完整生成两个入口（现状只有完整生成）。
2. 编辑器组合预览与启动入口接入。
3. 验收：dry-run 结果与完整生成的顺序一致；编辑器启动产物与命令行启动产物指纹一致。

风险：dry-run 为纯新增入口；指纹算法不动，无兼容问题。
