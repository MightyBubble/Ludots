# cfg-06 spec · 游戏配置

> 引擎实现任务书。第一性需求见 [cfg-06 PRD](../prd/cfg-06-game-config.md)；配置说明见 [cfg-06 配置说明](../config/cfg-06-game-config.md)；现状见 [cfg-06 reference](../reference/cfg-06-game-config.md)。

## 1. 概述

消除 game.json 的管线特例：将其纳入配置目录统一走 DeepObject 条目，合并实现收敛为一条路径；容量交叉校验保持为启动期硬校验。

## 2. 设计

### 特例收敛

- `game.json` 在配置目录登记为 `DeepObject` 策略条目，删除专用的合并入口与专用调用分支。
- 合并产物反序列化为运行配置对象的语义不变；必填项校验（presentation）从引擎装配处保留。

### 校验分层

- 结构校验（字段类型、必填）在反序列化阶段；语义校验（容量为正、交叉约束）保持在专用校验器，错误消息带字段路径。
- 交叉约束集合：容量各项为正且有限；订单准入结果容量 ≥ 订单队列容量 × 2；订单准入拒绝容量 ≥ 订单队列容量。

### 编辑器合同

- 项目设置表单以字段元数据（分组、类型、默认、约束）驱动渲染，元数据与运行配置对象单一来源生成，避免双写。

## 3. 精确语义与不变量

- 深合并语义：对象递归合并；标量与数组后到者覆盖——与目录 DeepObject 策略一致。
- 合并顺序：引擎默认 → 各 mod 按加载顺序，后到者覆盖。
- 常量表五张字典键值均为字符串到标量的映射，键冲突后到者覆盖。

## 4. 迁移与治理

1. 目录登记 game.json 条目，切换通用路径，删除专用合并入口。
2. 字段元数据生成器落地，编辑器表单接元数据。
3. 验收：合并结果与现行输出逐字段一致（快照对比）；专用入口代码删除。

风险：纯管线收敛，行为以快照对比保障；无产品面变化。
