# cfg-08 spec · mod 代码扩展面

> 引擎实现任务书。第一性需求见 [cfg-08 PRD](../prd/cfg-08-mod-extensions.md)；配置说明见 [cfg-08 配置说明](../config/cfg-08-mod-extensions.md)；现状见 [cfg-08 reference](../reference/cfg-08-mod-extensions.md)。

## 1. 概述

扩展枢纽（startup-only extension hub）作为唯一注册通道：mod 在加载窗口经门面接口注册语义键，枢纽在配置编译前冻结，注册结果供编译期解析与运行期执行。

## 2. 设计

### 枢纽与门面

- `IModContext.Extensions` 只暴露只注册的门面 `IModExtensionRegistration`（Gas / Presentation 两组）；可变枢纽对 mod 不可见。
- 每个注册面返回注册表 id；注册转发到对应运行时注册表（内建处理器、图 op 表、表现命令、表现行为）。
- 冻结点在"全部 mod 装配完成、配置编译开始前"；冻结后任何注册调用抛错。

### 键语义

- 语义键处于全局扁平命名空间，与配置 id 同域；单主声明——同一 mod 二次注册同名键抛错，不同 mod 撞名同样抛错。
- 注册不提供注销；生命周期即进程生命周期。

### 元数据合同

- 内建处理器注册必须携带操作元数据：操作类别（纯 / 事务 / 委派内建等）与原子域；效果执行计划的编译校验按元数据裁决该处理器可出现的相位窗口（纯相位只准纯操作等）。
- 图 op 注册的输入输出类型进入图编译器类型检查；可选固定寄存器分配保留循环携带场景。

### 编辑器合同

- 扩展键投影：向编辑器暴露"进程内已注册键清单"（按注册面分组、含来源 mod），驱动节点面板与处理器选择器动态生成。
- 配置中扩展键引用的编辑期存在性校验，消费同一投影。

## 3. 精确语义与不变量

- 注册窗口唯一：`IMod.OnLoad` 期间；冻结后注册即启动失败。
- 编译顺序不变量：枢纽冻结先于任何配置 loader 的编译调用。
- fail-fast 集合：重复键、配置引用未注册键、缺目录登记、缺分片、缺处理器表全部启动失败。
- 注册面封闭：新增注册面属于引擎扩展面治理变更，不走 mod 侧约定。

## 4. 迁移与治理

现状实现已交付（合入 main）；本篇约束后续演进：新增注册面须同步更新门面、投影与合同测试。验收基线为 ModExtensionRegistrationTests（注册窗口、冻结、重复键、撞名）。
