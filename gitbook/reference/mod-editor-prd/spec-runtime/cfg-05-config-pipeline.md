# cfg-05 spec · 配置管线与跨 mod 合并

> 理想技术实现。现状见 [cfg-05 reference](../reference/cfg-05-config-pipeline.md)；产品承诺见 [cfg-05 prd](../prd/cfg-05-config-pipeline.md)。

## 1. 概述

配置来源由声明驱动：配置根约定收敛为一处引擎级 SSOT，mod 清单可选声明覆盖，管线与全部消费方读同一 SSOT。工程目标是消除路径约定知识在多处硬编码造成的漂移；默认根表与现行收集顺序逐字一致，作为行为不变量列入第 3 节。

## 2. 设计

### 配置根 SSOT

- 引擎级定义一份**配置根表**（有序）：`["assets/", "assets/Configs/"]`，按此顺序收集片段——与现行收集顺序逐字一致。
- 该 SSOT 是唯一的约定知识来源；新增或调整根只改这一处。

### mod 级自由声明

- mod 清单可选字段 `configRoots`：字符串数组，声明后该 mod 的片段只从声明的根按序收集。
- 未声明 = 使用引擎默认根表。声明空数组非法。
- 声明值必须是 mod 内相对路径段（禁 `..` 与绝对路径），启动期校验。

### 消费方统一

- 配置管线片段收集改为"逐 mod 取其生效根表 → 构造 URI"，删除分散的固定双候选构造。
- 编辑器与实时技能工作台的保存路径解析：沿用"跟随 mod 已有布局、新文件走默认"策略，但策略输入改为生效根表（按声明或默认），删除各自维护的本地路径常量对。
- 合并预览、文档投影源等编辑器侧工具从同一 SSOT 取根，保证预览与收集一致。

### 兼容代码清除清单

| 现状 | 处置 |
|---|---|
| 管线侧固定双候选构造（两处硬编码方法） | 改为消费 SSOT，方法退役 |
| 实时技能工作台保存服务内嵌的路径常量对 | 改为读生效根表，常量删除 |
| 各处文档口径引用固定路径 | 改为"引擎默认根 + 可声明"表述 |

### 字段级冲突溯源

冲突报告在现有 id 级赢家之上增加**字段级胜出记录**：合并时对每个被覆盖的标量字段记录最后写入片段。编辑器合并预览的字段级提示改消费该记录，不再自行比对片段。此项可与主体分离交付。

## 3. 精确语义与不变量

以下为实现验收标准，行为与现行语义保持一致：

- 五种合并策略集合：Replace / DeepObject / ArrayReplace / ArrayAppend / ArrayById；策略名与路径、id 比较全部 Ordinal 大小写敏感。
- 同 id 深合并：字段级覆盖（对象递归、标量后写赢、数组整体替换），`ArrayAppendFields` 列名字段追加；结果条目顺序 = id 首次出现顺序。
- 删除标记 `__delete` / `Disabled` 接受布尔与可解析字符串；编辑器一律生成规范布尔。
- 收集顺序不变量：引擎默认根表 → 各 mod 按**启动计划的有序清单**（依赖闭包在生成期烘焙，见 cfg-03 spec）依次加载，各自生效根表按序；同 mod 内后到的根覆盖先到的根。
- 失败模式不变量：文件缺失静默跳过；JSON 解析错误启动失败；条目缺 id / 未登记路径 / 依赖缺失或版本不符启动失败。
- ArrayById 校验：根必须为数组、元素为对象、id 为非空字符串。
- game.json 保持特例：不走 catalog，恒深合并为单一配置对象。

## 4. 迁移与治理

1. 引入配置根 SSOT 与 mod 级 `configRoots`（可选，默认行为逐字不变）。
2. 管线、工作台保存、编辑器工具切换为 SSOT 消费方；删除清单内硬编码。
3. 字段级冲突溯源按需跟进。
4. 验收：默认行为回归全量通过；声明 `configRoots` 的 mod 片段只来自声明根；SSOT 外无第二处路径约定知识。

风险：默认行为逐字不变，纯内部收敛；`configRoots` 为纯新增可选能力，无迁移负担。
