# cfg-04 spec · 配置目录

> 引擎实现任务书。第一性需求见 [cfg-04 PRD](../prd/cfg-04-config-tables.md)；配置说明见 [cfg-04 配置说明](../config/cfg-04-config-tables.md)；现状见 [cfg-04 reference](../reference/cfg-04-config-tables.md)。

## 1. 概述

目录条目保持六字段封闭 schema（含分片两字段）与严格校验；新增"登记必须绑定消费方"约束，消灭无加载器消费的死条目；编辑器侧提供目录投影与新类型审批流的数据合同。

## 2. 设计

### 死条目防护

- 目录登记新增**消费方声明**：每条目在引擎侧注册加载器时显式认领路径；启动期对账——存在无人认领的条目即启动失败。
- 反向同样成立：加载器查询未登记路径启动失败（现状已有）。双向对账保证目录与加载器一一对应。

### 目录自身的合并

- 目录文件自身按 `Path` 字段做同 id 深合并（现状不变），mod 追加条目即扩展。
- 合并后对 Path 集合做唯一性校验：同一路径两行视为配置错误。

### 编辑器数据合同

- **目录投影**：向编辑器暴露全部条目（路径、策略、id 字段、来源片段、认领的加载器），作为"我能配什么"的数据源。
- **新类型审批流产物**：一条目录条目 + 加载器挂接声明 + 策略选择（默认 ArrayById）；三者同一次治理提交交付。

### 新表接入合同

- 加载器消费合并产物，职责四件：未知字段校验（严格反序列化）、逐条目语义校验（类型、互斥、枚举精确匹配）、引用解析（目标必须已在先序注册表）、名字到 id 的注册。
- 错误报告带条目定位（文件、条目 id、字段路径）；单文件多条错误聚合为一次异常，一次启动报全。
- 对未登记路径 fail-closed（沿用目录查询语义）。
- 加载链挂接顺序在引擎初始化处显式声明，新表必须排在它引用的表之后。

### 分片目录合同

- 目录条目字段扩为六个：Path / Policy / IdField / ArrayAppendFields / ShardDirectories / AllowEmpty；白名单校验同步扩展。
- 收集不变量：每个来源（引擎默认两根、各 mod 两槽）先加载主文件，再按稳定枚举序加载各分片目录下全部 json；分片与主文件走同一条合并管线，无特殊裁决。
- `AllowEmpty` 语义唯一：整张表零片段（主文件与分片全缺）时豁免启动失败，用于有意留空的扩展点；主文件缺失但分片存在不触发它。
- 分片 schema 与主文件条目完全一致，禁止"分片专用字段"。
- 编辑器要求：新建条目默认落分片文件（一文件一条，文件名取 id 尾段）；表浏览与合并预览显示分片来源；保存可回写分片而非强制改大文件。

### id 与注册表统一约定

现状为五套名字→id 机制并存、InvalidId 多种约定、比较器同域分裂（Tag 区分大小写而技能三表不区分）、Freeze 半覆盖、个别运行期字符串热路径。收敛任务（完整调查与证据见 artifacts/id-system-survey.md 与仓库 issue #989）：

- 统一注册基建并全部显式 `StringComparer.Ordinal`；统一 `InvalidId = 0` 且 `id > 0` 有效（存量 -1 表带迁移）。
- 生产装载尾真正执行统一冻结；封死运行期 Register——实体集合键、交互上下文、图输出键三条链改为装载期解析或整数入口。
- 存档指纹表覆盖补全；关系域 byte 容量改显式校验。

## 3. 精确语义与不变量

- 条目字段白名单：Path / Policy / IdField / ArrayAppendFields；白名单外字段启动失败。
- Policy 合法值封闭集合五种，Ordinal 精确匹配；IdField 缺省 `id`。
- ArrayAppendFields 元素必须非空字符串。
- 目录必须合并为 JSON 数组，元素必须是对象。

## 4. 迁移与治理

1. 引入消费方认领与启动期对账（先对存量条目做一次认领盘点，逐条挂接）。
2. 编辑器目录投影与审批流按合同实现。
3. 验收：存量 71 条全部被认领；注入死条目与未登记查询均启动失败；投影数据与目录一致。

风险：存量认领盘点是一次性人工核对，条目数量可控（71 条）。
