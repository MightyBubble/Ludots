# ord-03 runtime spec · 订单流水

> 引擎实现任务书。第一性需求见 [ord-03 PRD](../prd/ord-03-pipeline.md)；现状见 [reference](../reference/ord-03-pipeline.md)。

## 1. 概述
流水线合同：单笔四步提交、三形态原子批量、双代准入结果、实体缓冲排序、终态账本。

## 2. 设计
- 单笔路径保持"预留→校验→入队→确认"；三批量形态（独立/共享单号/按源聚类）保持整批原子与连续性校验；终态化保持统一出口（结果校验 → 清黑板+释放载荷 → 释放延续 → 发布 → 预备单提升）。
- 双代缓冲保持：换代时未配对的已接受结果前向携带；摄入/逻辑步双收尾时序强制保持。
- **治理项**：空间 payload 所有权硬守卫（所有清理路径必须先 Release）正确但易踩——补调试期断言/诊断（O3）。
- **治理项**：提交结果到失败原因的映射对"接受态"输入抛异常，调用方须先排除——改为接受态返回显式哨兵或拆分接口（O4）。

## 3. 精确语义与不变量
- 批量失败零残留：整批要么全部入队，要么队列与结果区无痕。
- 拒绝区满即终端故障（宁可停机）；结果区容量交叉约束启动期校验。
- 实体队列序 =（Priority 降，InsertStep 升）；pending 后写覆盖；活动单唯一。

## 4. 迁移与治理
现状即基线；O3 诊断增强、O4 接口收紧均为代码级，不动数据格式。
