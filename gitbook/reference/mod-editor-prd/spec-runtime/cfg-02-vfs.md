# cfg-02 spec · 虚拟文件系统

> 理想技术实现。现状见 [cfg-02 reference](../reference/cfg-02-vfs.md)；产品承诺见 [cfg-02 prd](../prd/cfg-02-vfs.md)。

## 1. 概述

VFS 保持"挂载点 + 相对路径"的单一寻址模型；编辑器与工具一律通过解析 API 落磁盘，不自行拼接物理路径。

## 2. 设计

- 接口合同：挂载 / 卸载 / 取流 / URI 到物理路径解析四个操作；挂载点名字 = mod 清单 name。
- 安全校验：相对路径做逃逸前缀校验，越界、未挂载、文件缺失分别抛对应异常类型，供工具区分提示。
- 编辑器合同：保存、合并预览、资产浏览器全部经解析 API 取物理路径；解析失败按异常类型给出"未挂载 / 文件不存在 / 路径越界"三种作者语言提示。

## 3. 精确语义与不变量

- URI 按第一个冒号切分；其后整体为相对路径（允许再含冒号）。
- 挂载点唯一性由 mod 名全局唯一保证；重名 mod 在清单解析阶段即失败，VFS 不做二次防御。
- 逃逸判定以前缀规范化校验实现，符号链接不追认。

## 4. 迁移与治理

现状实现已符合本合同；本篇主要约束编辑器侧不绕过解析 API。验收：编辑器内保存的文件与引擎加载的文件物理一致。

风险：无引擎侧变更。
