# cfg-07 spec · 合并规则案例集

> 理想技术实现。现状见 [cfg-07 reference](../reference/cfg-07-merge-rules.md)；产品承诺见 [cfg-07 prd](../prd/cfg-07-merge-rules.md)。

## 1. 概述

十种合并情况作为编辑器合并预览的分类框架落地；危险数组清单从各配置类型的字段 schema 投射生成，不手抄维护。

## 2. 设计

### 合并预览分类

- 每个被覆盖字段归入五类差异：新增条目、覆盖标量、扩展对象、整组替换数组、删除条目。
- 整组替换类展示"将替换对方 N 项"计数；删除条目展示删除标记来源。
- 分类数据源为字段级胜出记录（与 cfg-05 spec 的字段级冲突溯源同一任务，依赖其交付）。

### 危险字段元数据

- "数组且覆盖即替换"的字段集合由各 loader 的字段 schema 投射生成（字段类型 + 所在合并策略），清单随 schema 演进自动更新。
- 编辑器警示、文档危险清单、校验提示共用同一元数据，禁止三处手抄。

### 删除时序

- 删除标记在遍历到时即时生效、不延续到后续片段——保持现状语义，编辑器在屏蔽操作时提示"更晚加载的 mod 可复活该条目"。

## 3. 精确语义与不变量

- 十种情况的裁决语义以 cfg-05 spec 的合并不变量为准；本篇不新增合并规则。
- 危险判定标准唯一：字段值类型为数组且未登记为可追加。

## 4. 迁移与治理

1. 字段级胜出记录交付（cfg-05 spec 项）后，合并预览按五类差异渲染。
2. 危险字段元数据生成器落地，替换手抄清单。
3. 验收：对任一配置文件，预览分类与手动合并 diff 完全一致。

风险：依赖字段级溯源先行；纯编辑器侧工作。
