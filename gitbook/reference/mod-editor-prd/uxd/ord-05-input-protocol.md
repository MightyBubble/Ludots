# ord-05 UXD · 输入协议的编辑器需求

> ord-05 的编辑器需求（高保真规格）。第一性需求见 [ord-05 PRD](../prd/ord-05-input-protocol.md)；配置写法见 [ord-05 配置说明](../config/ord-05-input-protocol.md)；编辑器实现见 [editor spec](../spec-editor/ord-05-input-protocol.md)。

## 1. 界面定位

门等待视图：时间轴上每扇门的实时状态——在等谁、等到没有、还剩多久——输入协议的排障中心。

## 2. 布局线框

```text
┌─ 门等待视图：CataclysmRing #e17 ────────────────────────────────────┐
├─ 时间轴带门标记 ─────────────────────────────────────────────────────┤
│ TagClip ▮▮▮ EffectSignal ◆ [EventGate ⏳] ── End                     │
├─ 选中门：EventGate #180 ───────────────────────────────────────────┤
│ 等待标记 [Event.Catalyst.Confirm #180]  状态 [等待中 · 第 3 帧]      │
│ 截止 [12 帧后 ▓▓▓▓░░]   命中后动作 [放行 → End]                     │
│ ▶模拟命中   ▶模拟超时                                               │
└──────────────────────────────────────────────────────────────────────┘
```

## 3. 控件与数据源

| 控件 | 数据源与取值 | 行为 |
|---|---|---|
| 时间轴带 | 能力 exec items + 运行期门状态 | 门节点三态色：未到/等待/已放行 |
| 等待详情 | 门等待态快照（请求号/等待标记/截止） | 请求号与响应流配对高亮 |
| 模拟按钮 | 输入注入接口 | 开发期伪造命中/超时，验证门后时间轴 |
| 请求号标注 | item 的 payloadA | 编辑态直接在时间轴节点上标注 |

## 4. 关键交互流：给技能加确认步骤

1. 能力编辑器时间轴在 EffectSignal 后插入 EventGate。
2. payloadA 选择事件标记（从 tag 总账选）。
3. 门等待视图▶模拟命中 → 时间轴预览放行到 End。
4. 保存 → 能力表落盘；InputGate 若漏 payloadA 保存期即红条。

## 5. 状态设计

| 状态 | 触发 | 呈现 |
|---|---|---|
| 等待中 | 门开启且未配对 | ⏳ + 已等待帧数 |
| 已放行 | 命中或超时 | ✔（注明命中/超时） |
| 缺请求号 | InputGate 无 payloadA | 节点红框 + 保存阻断 |

## 6. 易用性验收口径

- 任一门的"声明+实时状态"≤ 2 跳可达。
- 模拟命中/超时不需要真实输入设备。
