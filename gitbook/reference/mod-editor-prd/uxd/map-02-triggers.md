# map-02 UXD · 地图触发器的编辑器需求

> map-02 的编辑器需求（高保真规格）。第一性需求见 [map-02 PRD](../prd/map-02-triggers.md)；配置写法见 [map-02 配置说明](../config/map-02-triggers.md)；编辑器实现见 [editor spec](../spec-editor/map-02-triggers.md)。

## 1. 界面定位

让作者不写代码也能理解与配置触发器：启用了什么、什么事件驱动、参考实现是什么样。

## 2. 布局线框

```text
┌─ 地图编辑器 ▸ 触发器页 ────────────────────────────────────────┐
├─ 左：可用触发器类型 ─────────┬─ 右：本地图启用详情 ────────────┤
│ ▸ 扫描工作区代码得到的类型清单│ ✔ AuditScopedMapLoadedTrigger    │
│   [来源 mod] [事件签名]      │   来源：底座片段 / 难度修正片段  │
│ ☑ 勾选即启用                 │   事件：MapLoaded               │
│ ▸ 搜索…                      │   参考实现：[查看代码]           │
├─ 底部：并集提示 [底座 2 个 + 难度修正 1 个 = 共 3 个] ──────────┤
└────────────────────────────────────────────────────────────────┘
```

## 3. 控件与数据源

| 控件 | 数据源与取值 | 行为 |
|---|---|---|
| 可用类型清单 | 工作区代码扫描（继承触发器基类的类型 + 事件签名） | 勾选写本 mod 片段的 TriggerTypes |
| 启用详情 | 合并结果 + 逐片段来源 | 显示并集构成；非本 mod 来源只读 |
| 参考实现 | 类型源码定位 | 打开对应代码文件（只读预览） |

## 4. 关键交互流：给战役加胜负判定

1. 触发器页搜索 `victory` → 类型清单显示底座提供的胜负触发器。
2. 勾选 → 写入本 mod 地图片段（TriggerTypes 追加一项）。
3. 底部并集提示更新"底座 2 + 本 mod 1"。
4. 试玩验证：达成条件时对局结束。

## 5. 状态设计

| 状态 | 触发 | 呈现 |
|---|---|---|
| 类型缺失 | 清单引用的类型已从代码移除 | 红条 + 类型名 + "扫描工作区"按钮 |
| 无可用类型 | 工作区无任何触发器类 | 引导卡：链接 cfg-08 扩展面与代码骨架模板 |
| 冲突启用 | 两片段启用同名类型 | 并集去重提示（同类型只注册一次） |

## 6. 易用性验收口径

- 勾选到保存 ≤ 2 次交互；并集构成始终可见。
- 每个启用项可溯源到来源 mod 与代码文件。
