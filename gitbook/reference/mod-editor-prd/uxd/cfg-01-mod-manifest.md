# cfg-01 UXD · mod 数据的编辑器需求

> cfg-01 的编辑器需求：编辑器如何让作者创建与维护 mod 数据。第一性需求见 [cfg-01 PRD](../prd/cfg-01-mod-manifest.md)；配置写法见 [cfg-01 配置说明](../config/cfg-01-mod-manifest.md)。

## 1. 界面定位

作者在编辑器里对 mod 数据的全部操作：新建 mod、编辑身份字段、维护依赖。用户的第一个动作（"新建一个 mod"）从这里开始，演示场景的每一段也从这里起步——底座从新建向导长出来，皮肤与玩法 mod 逐个加入工作区。

## 2. 界面功能

- **新建 mod 向导**：输入名字（即时校验全局唯一）→ 选依赖（从工作区已打开的 mod 里勾选）→ 可选代码骨架（含空入口类型）→ 生成目录骨架 + 最小合法清单 + 默认配置根。产物必须一次通过解析合同，向导结束即可启动。
- **项目设置区**：身份字段（name、version、dependencies、main）集中编辑，与内容编辑完全分区；每个字段旁标注生效级别（身份字段一律重启级）。
- **依赖图**：整个工作区的依赖 DAG，实时渲染。环、缺失依赖、版本不满足三种问题在图上直接标红并定位到边；点节点跳转对应 mod 项目。
- **多 mod 并存**：底座 + 皮肤 + 玩法 mod 同时打开（演示场景的常态），资产浏览器与运行预设跨 mod 聚合。

## 3. 数据存储

- mod.json 写回走**规范化序列化**：字段序与格式稳定，保存不产生无意义 diff。
- 向导与表单只产生合同内字段；未知字段既进不来也写不出（封闭字段集在 UI 层即兑现）。
- 依赖范围的增删同步写 dependencies 对象，保持键名字母序。

## 4. 易用性设计

- **命名即挂载点**：向导在命名时就解释"这个名字将成为它所有文件地址的前缀"，重名冲突即时提示，不等启动报错。
- **覆盖权可视化**：勾选依赖时明示"你将可以覆盖它的配置"——把依赖的合并语义翻译成用户语言。
- **重启级操作不打哑谜**：修改身份字段保存时，明确提示"重启后生效"并列出受影响的运行中实例。
- 新手路径：向导默认值即合法最小集，一路下一步得到能启动的空 mod，第一分钟就有正反馈。

## 5. 相关

演示场景对照：底座（新建向导全流程）、皮肤 mod（向导 + 依赖勾选）、War3 换皮（社区 mod 导入工作区）。
