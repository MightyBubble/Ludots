# cfg-05 UXD · 合并管线的编辑器需求

> cfg-05 的编辑器需求。第一性需求见 [cfg-05 PRD](../prd/cfg-05-config-pipeline.md)；配置写法见 [cfg-05 配置说明](../config/cfg-05-config-pipeline.md)；编辑器实现见 [editor spec](../spec-editor/cfg-05-config-pipeline.md)。

## 1. 界面定位

"为什么我的值没生效"的第一诊断入口；也是上游作者感知"我的字段被谁压住了"的地方。

## 2. 界面功能

- **合并预览**：任一表展示参与片段链（来源地址列表）、每个条目的最终赢家、每个字段的胜出来源。
- **最终生效顺序**：直接展示启动计划顺序——胜负可解释。
- **被下游覆盖提示**：浏览上游条目时标出被下游改写的字段及来源。
- **依赖更新覆盖审计**：升级上游依赖前 diff 下游覆盖点（哪些字段会被顶住），类似包管理器 why / outdated。
- **删除两义分开**：删自己拥有的行 = 物理删除；屏蔽他方 = 写删除标记，并提示"更晚加载的 mod 可复活"。

## 3. 数据存储

预览为只读投影，不落副本；审计结果可导出为报告文件。

## 4. 易用性设计

- 差异按案例分类着色（新增/覆盖标量/扩展对象/整组替换/删除），危险数组字段替换给"将替换对方 N 项"预警。
- 位置自由：保存跟随该 mod 已有放法；无配置时给默认位置。
