## 一·补三 · 「目标是什么」这个轴（本轮开的口子）

图鉴原来 191 条的目标只有五种，全在具体空间里：**地面一点 / 场上一个单位 /
一个方向 / 自己 / 界面槽位**。回合制、战棋、大战略引入的是完全不同的目标类型，
本轮补了三族 16 条把这个轴撑开：

| 目标类型 | 例子 | Order 过滤后 |
|----------|------|--------------|
| 离散格子 | 可达格 / 占格冲突 / 控制区停步 | UX-189、191、192 ✅（朝向伤害、高低掩体已省略） |
| 顺序里的位置 | 插队、延后、确认前撤销 | UX-185、186、188 ✅（纯看行动条 HUD 已省略） |
| 行政区域 | 派间谍到某省 | UX-194 ✅ |
| 两方之间的关系（边） | 结盟 / 联姻 / 宣战 | UX-195 ✅ |
| 抽象集合（无位置） | 游说某个派系 | UX-196 ✅ |
| 规则本身 | 颁布法令 | UX-197 ✅ |
| 抽象代价池 | 威望 / 影响力 | 并入 UX-137 资源拒令，不单开 |
| 行政层级作为范围 | 省 → 公国 → 全国 | UX-199 ✅ |

**这个轴还没覆盖到的（下一轮候选）**：

- **时间点作为目标**：把一个效果预约到第 N 回合、给未来某回合挂事件（和 UX-199 的层级同理，只是换成时间维度）
- **头衔 / 宣称作为目标**：对一个头衔提出宣称，目标是一条法理而不是一块地
- **人物字段作为目标**：给某人加特质、改忠诚、指派职位
- **贸易路线 / 补给线作为目标**：目标是一条带流量的边，和「关系」不同（它有方向和吞吐）
- **科技或研究项作为目标**：目标是一棵树上的节点，有前置依赖
- **概率本身作为目标**：花代价把某件事的成功率从 40% 提到 60%（玩家操作的是分布）
- **回合制的「同时结算」**：双方都下完令再一起演（战术回合 / 我的世界式指令队列）
- **塔防造塔与路径**：目标是「路上的一格」，且会改变敌人的寻路
- **卡牌对战的场地与牌堆**：目标是牌堆、弃牌堆、或场上一条线（炉石式）

## 二、该合并成同一编号的重复动作

多路评审独立指出的重复，按共识强度排序。改编号会牵动 `player_action_ux_action_index.py`
的编号体系，建议单独一轮做，并同步更新 CHECKPOINT。

1. **右键语境指令一族**：UX-007（RA2 右键随兵种）、UX-009（SC2 右键随选中）、
   UX-038（右键地面对比对象）、UX-039（右键敌人下令攻击）、UX-040（右键智能指令）
   —— 五条讲的是同一件事：右键没有固定含义，结果由「选中了谁 × 点到了什么」决定。
   建议保留一条总纲，RA2 / SC2 作为同一编号下的复刻目标示例。
2. **临时追加技能键一族**：UX-159（限时叠加）、UX-162（饰品主动）、UX-163（骑乘技）、
   UX-023（偷来/复制）—— 都是「条件成立→技能栏多几颗键→用掉→收回」。
   注意「替换整栏」（UX-034 变身、UX-146 载具）是另一种心智，不要并进来。
3. **上车 / 上炮位一族**：UX-013（上车变载具手感）、UX-146（座位整套替换）、
   UX-161（靠近载具解锁上车）—— 同一个流程被切成三段，应合成一条四拍流程：
   靠近解锁 → 不可上（满员/走远）→ 上车换套 → 下车还原。
4. **近战攻击与衔接窗一族**：UX-144（轻攻击连段）、UX-147（近战点一下）、
   UX-145（轻重混按分支）、UX-158（闪避后接攻击）、UX-091（按住/连点连段）
   —— 同一个操作模型，应合成：单发 → 连段推进 → 重击分支 → 闪避派生 → 错过窗口中断。
5. **技能瞄准流程**：UX-148（进入技能瞄准）+ UX-116（瞄准中取消）
   —— 各自拿走了同一流程的一半，合起来才是「进入 / 调整 / 确认 / 取消」四拍。
6. **目标不合法拒绝**：UX-139（超距遮挡）T1 + UX-160（雾中/类型不对）
   —— 同一体验，区别只是拒绝原因的文字。UX-137（资源不足）讲自身状态，保持独立。
7. **智能施法**：UX-103（智能施法打准星下单位）并入 UX-102（智能施法 vs 先瞄后放）T1。
8. **按住持续开火**：UX-092（按住扫射/喷火）作为 UX-107（枪械点射/扫射）的主机变体。

## 五·补二 · 符号一符一义（本轮收口）

图鉴最伤人的一类问题不是「缺元件」，而是**同一个图形被拿去表示好几件事**。
第五批评审把这一点点透了：红色锁定圈曾同时表示锁定目标、命中挨打、准星扩散、
可处决窗，甚至「我自己被控住了」——一个图形五种意思，玩家只能学到混乱。

本轮收口后的约定（改数据前先读）：

| 图形 | 只表示这一件事 |
|------|----------------|
| `ring(kind=select)` 橙圈 | 这个单位被我选中了 |
| `ring(kind=lock)` 红圈 | 这是当前锁定/当前目标（只剩 7 处，全部是此义） |
| `ring(kind=finisher)` 金虚线圈 | 这个目标现在可以被终结（处决/背刺/反击窗） |
| `ring(kind=buff)` 蓝圈 | 身上/脚下有增益或范围效果 |
| `circle(ok=True/False)` 绿红虚线圈 | 落点或范围**预览**，还没发生 |
| `impact` 橙色爆点 | 已经打中了、已经炸开了 |
| `crosshair(spread=)` | 准星本身的张开度（开镜收拢 / 扫射扩散） |
| `deny` 红圈斜杠 | 这一下被系统挡住了 |
| `building` 灰方块 | 真的是建筑 |
| `prop(kind=...)` 带标签物件 | 矿脉 / 果子 / 宝箱 / 门 / 矮墙 / 掩体 / 神龛 |

配套的防回归规则已进硬闸：说「打中/挨打/砸中」必须有爆点，说「扩散/收拢」必须用
准星张开度，说「处决/背刺/暗杀」必须用终结圈或键帽点明，不许再复用锁定圈。
