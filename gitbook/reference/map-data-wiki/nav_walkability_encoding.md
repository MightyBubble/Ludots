# 像素怎么编码：颜色、透明、哪一行是北

走性图不是好看的概念图，是一张和世界厘米一一对应的栅格。作者改错行方向或透明度，地上的颜色会整体南北对调，或者整片海变成实心色块。

## 作者写法

| 项 | 值 |
|----|----|
| 格式 | PNG，每像素 RGBA 8 位（旁路 JSON 写 `encoding.format = RGBA8`） |
| 第 0 行 | 北沿，世界 `maxZcm`（旁路写 `encoding.row0 = maxZcm`） |
| 列 0 | 西沿，世界 `minXcm` |
| 可走陆地 | alpha = 255；红绿蓝由三角形地类编号算出，同一编号永远同一颜色 |
| 没盖到 / 不能走 | alpha = 0（默认不涂阻断水面时） |
| 陆上阻断水面（可选） | alpha = 220，固定红 `(200, 32, 32)`；只填还是透明的像素 |

旁路 JSON 和 PNG 必须成对。东亚那份写明：4096×2341，框 `(-3199616,-1828352)-(3199616,1828352)`，`contentHash` 对整文件做 sha256。验收测会核对宽高、框和哈希，对不上就红。

地类调色（确定性，禁止另写一套）：

```text
R = 48 + ((areaId *  67 +  31) % 176)
G = 48 + ((areaId *  97 +  89) % 176)
B = 48 + ((areaId * 131 + 151) % 176)
```

## 这条链路怎么走

栅格化时，像素中心落回世界厘米：

```text
worldX = minXcm + (x + 0.5) * 框宽 / 像素宽
worldZ = maxZcm - (y + 0.5) * 框高 / 像素高
```

点在某个导航三角形里，就用该三角形的地类编号上色，alpha 置 255。后画的三角形覆盖先画的——瓦片按路径排序，同一像素最后落到的三角形说了算。

画的时候，着色器把地形点的世界厘米（米 × 100）除以同一组框，再把纵向 UV 翻一次：

```text
uv.x = (worldX - minX) / (maxX - minX)
uv.y = 1 - (worldZ - minZ) / (maxZ - minZ)
```

这一翻和「第 0 行是北」对齐。作者自己做工具时必须同一套，不能按「第 0 行是南」存图。

可选的阻断水面底涂：只检查还是透明的像素。采样逻辑地形格，格是阻断或带水，才涂那层红。可走陆地保持地类色，不会被海色顶掉。

旁路 JSON 的 `encoding` 字段是给人看的说明，运行时认的是 PNG 字节和 `boundsCm`。改了编码却不重导 PNG，地上会对不齐。

## 边界与更多用法

- 没有「差不多也能画」。贴图文件缺失、URI 解不出、框宽高不是正的，开 `T` 直接失败。
- 有旁路 JSON 时，框只认旁路，不认地图里那份备份框。旁路坏了或不是对象，失败。没有旁路，才读地图元数据里的框。
- 这张图是检查用的走性投影，不是寻路本身。单位走路仍读导航瓦片。
- 导出命令见 [导出一张和棋盘对齐的走性图](nav_walkability_export.md)；挂到地图见 [地图上怎么挂这张走性图](nav_walkability_config.md)。

## 怎么跑

导出后看旁路 JSON 的 `encoding` 是否仍是「第 0 行 = maxZcm、可走 alpha=255」。再进调试预设按 `T`：陆地有地类色，海应是空的（或你显式涂过的阻断红），整图不能南北颠倒。
