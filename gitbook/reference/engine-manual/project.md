# 工程是什么

一个"工程"就是一个普通文件夹，里面放着一个迷你引擎需要的全部内容。拿 Unity 类比：Unity 有 Assets 文件夹和工程设置，这里有 `projects/engine_gallery/`。播放器是引擎本身（可执行文件），工程是内容——**一个播放器可以打开任何工程**，换工程不用重新编译。

## 目录里都有什么

以仓库自带的画廊工程为例：

```text
projects/engine_gallery/
  project.json     工程身份证：叫什么名字、场景清单在哪个文件、组件库是哪一个
  catalog.json     场景清单：一行一个场景，写"场景 id + 场景文件名"
  scenes/          场景文件（关卡），一个场景一个 JSON
  materials/       材质：一种表面长什么样（颜色、粗糙度、贴图）
  Models/          模型：带骨骼动画的 GLB 文件
  textures/        贴图：材质用的图片
```

## 每个文件干什么

**project.json** 是入口。播放器打开工程先读它：`name` 是显示在窗口标题上的名字；`scenes` 指向场景清单；`contentAssembly` 声明这个工程用哪套组件库（工程可以自带组件，跟 Unity 工程自带脚本一个道理）。

**catalog.json** 只登记两样：场景 id 和它的文件名。菜单里列出的场景、验收命令能点名的场景，都来自这里。给工程加场景 = 在 scenes/ 放一个新文件 + 在这里加一行。

**scenes/** 里每个文件描述"这一关长什么样"：摆什么东西、在哪、相机从哪看、天光如何。这是你最常改的文件夹，下一页专门讲。

**materials/** 与 **textures/** 管外表。材质决定一块石头是青苔斑驳还是光滑金属，贴图是材质引用的图片。两套手册见[材质手册](materials.md)。

**Models/** 放 GLB 模型文件。模型、骨骼、动画都打包在这一个文件里，场景和动画组件按文件名引用它。

## 改动怎么生效

改任何 JSON 保存后，重新跑播放器命令就是新内容——没有编译、没有导出步骤。这个"所见即文件"的循环就是这套引擎的日常工作流。
