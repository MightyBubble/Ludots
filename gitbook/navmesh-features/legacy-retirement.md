# 旧类型与重复入口清理

> [功能目录](README.md) · [体系总合同](../navmesh-ssot.md)
>
> 第 1–6 节定义目标产品与设计验收；当前可用范围、分支成果和剩余工作只看第 7 节。本文不新增第二套数据或运行管线。

## 1. 概述

清理工作的目标是让 NavMesh 只有一条可解释的生产链：正式 source、正式 bake service、`.ntil` 产物和正式 query service。旧类型可以保留在迁移前的历史分支里，但不能继续作为隐藏旁路。

关联 issue：[#1349](https://github.com/MightyBubble/Ludots/issues/1349)、[#1129](https://github.com/MightyBubble/Ludots/issues/1129)。

## 2. 结构

消费方清单 → 迁移 source/bake/query/presentation → 重烘焙当前产物 → 冷启动验收 → 删除旧入口。报告只记录本次迁移证据，长期能力状态仍归总合同。

## 3. 详情

### 3.1 编辑器功能

- 编辑器只编辑当前 source、board、semantic 和 obstacle 合同，不再保存 `.ltrn` 或旧 payload 作为导航真相。
- 旧入口打开时显示迁移动作和影响范围，不能默默转换后继续保存。
- 面板中的 bake、query、overlay 按钮都指向同一 Core service。
- 旧字段、未知字段和重复 source 直接报错，便于作者清理资产。

### 3.2 工具功能

- 工具先扫描消费方和资产，再删除旧类型；没有消费方迁移证据时不得删文件。
- 退役顺序：迁移 source → 迁移 bake → 迁移 query/presentation → 重新烘焙 → 冷启动验证 → 删除旧入口。
- 不保留双格式兼容读取器，不维护第二套 `bake` 命令或第二套 editor loop。
- 清理报告列出删除的类型、替代路径、重烘焙资产和未处理引用。

### 3.3 Runtime 功能

- Runtime 只接受当前 manifest、`.ntil`、source revision 和 build hash。
- 旧 CDT、旧 `.ltrn` 或陈旧 payload 被拒载，并指向正式重烘焙入口。
- Query、overlay 和 MassNavigation 都消费同一 NavTileStore；没有隐藏 fallback。
- 退役后的代码路径必须有架构测试证明不会被反射、注册表或 Mod 入口重新拉起。

## 4. 场景与 Showcase 设计

### 一句话与目标用户

旧地图迁移后，只走一条正式导航链。

面向地图作者和首次体验该能力的玩家。作者管线：选择旧地图引用、执行检查和迁移后重新生成，观察阻塞引用变为可加载产物。

### 主循环

0–15 秒：扫描一张旧地图，显示具体引用位置。15–35 秒：选择已迁移 source 的对照样例，使用统一工具重烘焙。35–60 秒：冷启动后查询并显示消费链。惊喜时刻：关掉旧编辑器也能从磁盘加载并移动。

### 消融对照

旧引用样例与迁移后的样例并排加载；旧样例明确拒绝并列出替代路径，新样例使用当前 source/产物。对照不执行历史算法。

### 解释层

未迁移红色、已迁移待重烘焙黄色、验证通过绿色；面板显示引用文件、替代入口、产物指纹和冷启动结果。

### 旋钮清单

以下为目标演示中可在同一会话操作的控件；取值由场景配置或正式 API 约束。需要重烘焙的几何变更明确展示任务过程，不能伪装成立即生效。

| 运行中操作 | 范围 | 玩家能看懂什么 |
|---|---|---|
| 样例地图 | 隔离的迁移前 / 后 | 比较加载结果 |
| 引用范围 | source / bake / query / editor | 定位消费方 |
| 问题筛选 | 全部 / 阻塞 / 已处理 | 检查迁移进度 |
| 板范围 | 样例声明的 board | 选择重烘焙对象 |
| 验证动作 | 扫描 / 烘焙 / 冷启动 | 追踪同一正式链 |

### 场景结构

主演示旧地图到当前产物；子场景：旧 CDT 注册、重复编辑器 payload、遗漏 Mod 引用。首屏：“扫描地图，先处理红色引用，再生成并重开。”

### 门户资产

以主循环的惊喜时刻截取真实画面，并保留操作前后状态。入口、配置和媒体由 `showcase.registry.json` 关联；预览消费场景配置与正式产物，禁止另写一份数值。尚未实现的媒体显示待制作，不挂不存在的图片链接。

### 反向 API 审计

## 5. 边界

不整支合并包含旧 CDT、旧持久模型的历史分支。旧导航产物与旧地形源分开处理；删除前确认真实注册、反射与 Mod 消费方均已迁移。展示用过期副本放隔离样例，不恢复兼容读取链。

## 6. UAT

```gherkin
Feature: 旧导航资产不会静默进入生产运行时

  Scenario: 旧产物被拒载
    Given 地图仍引用旧格式的导航产物
    When 玩家启动地图
    Then Runtime 显示格式或版本不匹配
    And 给出正式重烘焙入口
    And 不生成替代路径

  Scenario: 清理后冷启动
    Given 作者已经迁移 source 并重新烘焙 `.ntil`
    When 作者关闭并重新启动地图
    Then 查询和 overlay 都使用新产物
    And 旧入口不会再次被调用
```

这些场景描述目标验收，不是已通过的测试记录。
