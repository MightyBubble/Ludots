# 水面导航语义

> [功能目录](README.md) · [体系总合同](../navmesh-ssot.md)
>
> 第 1–6 节定义目标产品与设计验收；当前可用范围、分支成果和剩余工作只看第 7 节。本文不新增第二套数据或运行管线。

## 1. 概述

水面导航定义船或水上单位在哪里能走，以及吃水、船宽和水深如何影响结果。水面美术颜色不是导航数据，蓝色贴图也不是船可走性的证明。

## 2. 结构

水深/航道/禁航区域源 + ship profile 的 DraftCm/BeamCm/Layer → 水面可行产物 → water 查询。水面高度、海底高度和吃水单位要在源合同中对齐。

## 3. 详情

### 3.1 编辑器功能

- Water 面板显示 water layer、深度来源、航道区域、禁航区域和绑定 profile。
- 作者能分别查看水面几何、深度不足和与陆地的边界；缺深度数据时显示缺失。
- 地面和水面视图可以并排，但不能把一个 layer 的可走面覆盖到另一个 layer。

### 3.2 工具功能

- water sidecar/adapter 将水深、航道和禁航语义加入统一 bake snapshot。
- `DraftCm`、`BeamCm`、layer 和水深阈值都进入 profile/build hash。
- 工具输出水深缺失、吃水不足、层冲突等独立诊断；不会根据美术材质猜水域。

### 3.3 Runtime 功能

- 船查询必须指定 water layer 和 ship profile；ground query 不会自动转成 water query。
- 水深或水域语义 revision 改变时，受影响 tile 需要重新发布。
- 陆水之间只有显式连接能力才可跨层；layer 字段本身不能表达桥上桥下的立体表面。

## 4. 场景与 Showcase 设计

### 一句话与目标用户

浅滩小船能过，大船得绕行。

面向地图作者和首次体验该能力的玩家。空间能力：切换吃水和船宽不同的船型，观察浅滩与窄航道造成的路径差异。

### 主循环

0–15 秒：派浅吃水小船直穿浅滩到港。15–35 秒：派大船去同一港口，走深水航道。35–60 秒：选择窄航道的另一个目标，比较船宽约束。惊喜时刻：大船航程更长却安全到港。

### 消融对照

并排比较只差吃水要求的两种已烘焙船型：浅吃水船过浅滩，深吃水船走航道；再用相同吃水对照恢复相同路线。船宽、区域代价和起终点保持一致。水深剖面是辅助解释；缺水深另作明确拒绝场景。

### 解释层

水深采用连续色阶，禁航区红斜线；HUD 显示水深、吃水、船宽、航道宽（cm）以及查询结果。

## 5. 边界

水深是水面与底面的距离；美术颜色不能替代。潮汐或水深变化需要版本化几何/语义更新，不能只改 UI 数字。水陆之间换层动作归 Link。

## 6. UAT

```gherkin
Feature: 水面语义约束船只路径

  Scenario: 吃水不足
    Given 船的吃水大于浅滩水深
    When 玩家查询穿过浅滩的港口路线
    Then 查询显示水深不足
    And 路径改走深水航道或返回不可达

  Scenario: 没有水深数据
    Given 水面只有美术材质而没有水深 sidecar
    When 玩家查询船只路线
    Then 系统显示水深数据缺失
    And 不把蓝色区域当作可走面
```

这些场景描述目标验收，不是已通过的测试记录。
