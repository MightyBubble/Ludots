# 查询结果与失败诊断

> [功能目录](README.md) · [体系总合同](../navmesh-ssot.md)
>
> 第 1–6 节定义目标产品与设计验收；当前可用范围、分支成果和剩余工作只看第 7 节。本文不新增第二套数据或运行管线。

## 1. 概述

查询诊断把“为什么没有路径”拆成用户能处理的原因：输入无效、缺瓦片、产物过期、profile/layer 不匹配、不可达、容量不足和系统错误。它只定义结果合同，不负责缓存或烘焙。

证据入口：`src/Core/Navigation/NavMesh/NavQueryService.cs`、`src/Core/Navigation/Pathing/PathTypes.cs`、`src/Core/Navigation/NavMesh/DetourNavQueryEngine.cs`。

## 2. 结构

PathRequest → 正式查询服务 → PathResult 与诊断 → 用户提示/执行决策。当前 PathStatus 为 Found、NoPath、BudgetExceeded、NotReady、InvalidRequest、Error；目标在现有结果上增加可追踪原因，避免新建平行状态体系。

## 3. 详情

### 3.1 编辑器功能

- Query 面板显示起点终点、map/board/layer/profile、status、路径点数、cost、tile revisions 和修复动作。
- 每种失败状态使用固定文案和颜色；不可达不显示一条直线。
- 诊断可复制为结构化记录，供 issue、UAT 和 Agent Bridge 使用。

### 3.2 工具功能

- CLI/Bridge 对输入、artifact 和 capacity 做前置校验，并保留 Detour 原因到 Core status 的映射。
- 路径输出不截断；固定容量不足时返回容量错误与建议预算。
- 工具统计成功/失败计数，但不把失败改写成 warning 后继续。

### 3.3 Runtime 功能

沿用现有 PathStatus（Found、NoPath、BudgetExceeded、NotReady、InvalidRequest、Error），通过 ErrorCode 与诊断上下文区分输入无效、缺瓦片、过期、profile/layer 不匹配、不可达、容量不足和系统错误。目标结果携带产物身份与版本；MassNavigation 只执行成功且仍有效的路径。

## 4. 场景与 Showcase 设计

### 一句话与目标用户

没有路径，也能知道下一步该做什么。

面向地图作者和首次体验该能力的玩家。诊断能力：在一条真实查询链中改变输入/可用产物，用户根据提示修复后得到路径。

### 主循环

0–15 秒：点击缺瓦片区域，看到缺少哪块。15–35 秒：在隔离样例中加载该产物并重试。35–60 秒：改点隔墙后的孤岛，明确看到“不可达”而不是“缺瓦片”。惊喜时刻：修复输入后错误消失，单位开始移动。

### 消融对照

详细解释开/关，始终保留粗状态；开启后显示原因和操作建议。消融只比较信息可读性，不改查询结果。

### 解释层

成功绿色、不可达红色、待加载黄色；HUD 显示原因、下一步、路径点数、容量、使用产物与版本。

### 旋钮清单

以下为目标演示中可在同一会话操作的控件；取值由场景配置或正式 API 约束。需要重烘焙的几何变更明确展示任务过程，不能伪装成立即生效。

| 运行中操作 | 范围 | 玩家能看懂什么 |
|---|---|---|
| 故障样例 | 无效输入 / 缺瓦片 / 不可达 | 验证不同反馈 |
| 查询单位 | 已声明 profile | 验证匹配 |
| 起终点 | 样例有效范围 | 修复请求 |
| 查询预算 | 合法 points/expanded 预设 | 观察容量失败 |
| 详细解释 | 开 / 关 | 比较错误可读性 |

### 场景结构

主演示缺瓦片修复和不可达对照；子场景：过期、profile 不匹配、容量和显式系统错误。首屏：“点击灰色区域，按提示补齐数据，再点红色孤岛。”

### 门户资产

以主循环的惊喜时刻截取真实画面，并保留操作前后状态。入口、配置和媒体由 `showcase.registry.json` 关联；预览消费场景配置与正式产物，禁止另写一份数值。尚未实现的媒体显示待制作，不挂不存在的图片链接。

### 反向 API 审计

| 所需接口 | 归属 | 现状与缺口 |
|---|---|---|
| 结构化原因 | Query / Pathing | 复用 PathStatus/ErrorCode，待原因与上下文 |
| 修复动作映射 | Tools / Editor | 消费稳定原因，不用字符串猜测 |
| 固定容量结果 | Query | 待显式溢出和缓冲复用 |

这些缺口属于对应功能的后续实现范围；本次文档设计不实现 API。阻塞主循环的接口补齐前，不能把演示标为可玩。

### 交付边界与完成判据

本页 Showcase 状态：设计完成；所述完整演示尚未实现，不可玩。已有底层代码或零散场景不代表本页演示完成。 实现阶段必须提供真实 launcher/Mod/地图入口，按 [统一 Showcase 交付合同](showcase-delivery.md) 验证操作、消融、解释层和故障反馈；本页功能判据见第 6 节。

## 5. 边界

区分粗粒度执行状态与细粒度原因：缺 tile、过期、profile/layer 不匹配、不可达、容量不足、系统错误。不能从普通 NoPath 猜出坡度或半径失败，必须有具体证据。

## 6. UAT

```gherkin
Feature: 查询失败原因可操作

  Scenario: 缺少瓦片
    Given 目标区域没有加载对应 NavTile
    When 玩家请求路径
    Then 面板显示缺瓦片
    And 提供加载或重新烘焙动作
    And 不执行单位移动

  Scenario: 起点终点不可达
    Given 起点和终点属于没有连接的区域
    When 玩家请求路径
    Then 面板显示不可达
    And 不返回直线替代结果

  Scenario Outline: 不同失败给出不同的下一步
    Given 作者打开 <问题> 样例
    When 作者在面板请求前往营地
    Then 面板显示 <原因>
    And 提供 <动作>
    And 单位不会执行无效路径

    Examples:
      | 问题             | 原因                 | 动作                 |
      | 地图外起点       | 起点不在有效范围     | 重新选择起点         |
      | 源已修改未重烘焙 | 导航产物过期         | 重新烘焙             |
      | 单位与产物不匹配 | 缺少对应体型或层产物 | 选择或生成匹配产物   |
      | 路径容量不足     | 所需容量超过限制     | 查看容量并调整预算   |
      | 查询服务显式异常 | 查询系统错误         | 查看错误记录并修复服务 |
```

这些场景描述目标验收，不是已通过的测试记录。
