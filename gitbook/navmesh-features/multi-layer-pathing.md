# 多层寻路

> [功能目录](README.md) · [体系总合同](../navmesh-ssot.md)
>
> 第 1–6 节定义目标产品与设计验收；当前可用范围、分支成果和剩余工作只看第 7 节。本文不新增第二套数据或运行管线。

## 1. 概述

多层寻路只定义 ground、water 等通行层如何隔离查询，以及层之间何时允许路由。`layer` 字段存在不等于桥上桥下已经形成独立的立体表面；非连续表面连接见 [NavMesh Link](navmesh-links.md)。

证据入口：`src/Core/Navigation/NavMesh/Config/NavMeshBakeConfig.cs`、`src/Core/Navigation/Pathing/NavMeshPathServiceAdapter.cs`、`src/Core/Navigation/Pathing/AutoPathService.cs`。

## 2. 结构

区分两条轴：通行层（地面/水面）决定单位能用哪套规则；空间表面（桥面/桥下）决定起终点实际处在哪个高度。路径端点需要可追溯的表面身份，不能只用同一平面坐标。

## 3. 详情

### 3.1 编辑器功能

- Layer 面板列出 layer id、绑定 board、允许的 profile 和语义。
- 视图只显示当前 layer 的 NavTile、障碍和路径；切换层不会复用上一层的绿色面。
- ground/water 以及桥上/桥下分别显示数据状态；没有显式连接时显示“不可跨层”。
- layer 缺失、profile 不允许或语义冲突时阻止查询。

### 3.2 工具功能

- 每个 layer 单独计算 tile targets、输入 hash、产物 identity 和 manifest。
- `NavMeshBakeConfigLoader` 严格读取 layer 与 profile 关系；同坐标不同 layer 不能覆盖产物。
- 跨层连接只有在 Link 数据存在时才写入；工具不根据空间相邻自动补边。

### 3.3 Runtime 功能

- registry 至少按 layer/profile 选择 NavTileStore；board identity 由 [每板寻址](board-addressing.md) 共同约束。
- ground 与 water 不共享可通行面；`AutoPathService` 只能在明确规则下路由。
- bridge 上下属于不同表面连接问题，当前不能因为 `layer` 配置存在就宣称已支持。
- 缺 layer、语义缺失和不可达分别返回诊断。

## 4. 场景与 Showcase 设计

### 一句话与目标用户

桥上和桥下，单位走自己那一层。

面向地图作者和首次体验该能力的玩家。空间能力：在重叠位置选不同楼层的目标，观察路线仍留在正确表面；另一个子场景单独比较地面与水面通行层。

### 主循环

0–15 秒：在桥上、桥下各选一队。15–35 秒：点击俯视图中同一位置，分别指定桥面和桥下终点。35–60 秒：旋转视角查看两条路线，再让桥上队伍尝试没有坡道连接的桥下目标。惊喜时刻：屏幕上看似相同的点得到两条高度不同的路，而无连接的换层请求明确失败。

### 消融对照

对照场景从同一地图生成“只提供桥下表面”和“提供桥上桥下两个表面”的两份独立合法输入。仅单表面时，桥上目标显示缺少对应表面；双表面时两队各自寻路。两边都走正式烘焙/查询，不将高层目标错误投影到低层。俯视/剖视只承担解释，不作为能力消融。

### 解释层

桥面用紫色、桥下用青色，路径附表面标签；HUD 显示通行层、目标表面、终点高度（cm）、路径状态。没有几何数据的层显示灰色“无数据”。

### 旋钮清单

以下为目标演示中可在同一会话操作的控件；取值由场景配置或正式 API 约束。需要重烘焙的几何变更明确展示任务过程，不能伪装成立即生效。

| 运行中操作 | 范围 | 玩家能看懂什么 |
|---|---|---|
| 选中队伍 | 桥上 / 桥下 | 观察所属表面 |
| 终点表面 | 地图声明的表面 | 同平面位置选择不同高度 |
| 目标位置 | 所选表面范围 | 改变路径 |
| 剖视间距 | 场景显示预设范围 | 展开重叠路径，仅改变显示 |
| 通行层视图 | 地面 / 水面 | 查看独立的通行规则 |

### 场景结构

主演示：桥上桥下的两个连续通路；子场景：同层断路、显式转层连接、陆海分层。首屏：“分别选两支队伍，点击桥中央，再打开剖视图。”

### 门户资产

以主循环的惊喜时刻截取真实画面，并保留操作前后状态。入口、配置和媒体由 `showcase.registry.json` 关联；预览消费场景配置与正式产物，禁止另写一份数值。尚未实现的媒体显示待制作，不挂不存在的图片链接。

## 5. 边界

本页管层和表面选择。水深规则见 [水面语义](water-semantics.md)，连接边与动作见 [NavMesh Link](navmesh-links.md)。一座连续可走的桥不必额外声明 Link；只有离散转接才需要 Link。

## 6. UAT

```gherkin
Feature: 单位只能在允许的导航层行走

  Scenario: 步兵与船查询同一目标
    Given 地图声明 ground 和 water 两个 layer
    When 玩家分别用步兵和船查询目标
    Then 步兵只使用 ground
    And 船只使用 water
    And 两次查询显示各自 layer

  Scenario: 桥上下没有显式连接
    Given 地图有桥上和桥下表面但没有 Link
    When 玩家查询跨越两层的目标
    Then 查询显示没有合法连接
    And 不返回跨层直线路径
```

这些场景描述目标验收，不是已通过的测试记录。
