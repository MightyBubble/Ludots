## 1. 概述

NavMesh Link 表达连续可行走面之外的合法连接，例如跳台、门槛、桥、梯子、传送点或 board 之间的入口。Link 是路径图上的正式边，不是查询失败后的直线补救。

当前主线已有 tile border portal，用于相邻 tile 拼接；本页的跨表面 Link 是更高一级的产品能力，尚无独立 Runtime 实现。

## 2. 结构

作者声明端点、方向、允许 profile/layer、代价与动作引用 → 绑定实际可行面 → 查询输出 Link 路径段 → 移动/动作系统执行并报告完成。现有 NavBorderPortal 只拼接相邻瓦片。

## 3. 详情

### 3.1 编辑器功能

- Link 面板显示起点、终点、方向、允许 profile、layer、代价、触发条件和动作引用。
- 起终点必须投影到有效 NavTile；投影失败时阻止保存。
- 编辑器显示单向/双向箭头和 Link 对路径的影响。
- Link 与结构障碍分开编辑：门的物理几何变化触发 dirty；连接启停只更新可用性。

### 3.2 工具功能

- Link 进入 manifest，与 board、layer、profile 和 build hash 一起校验。
- bake 输出 Link identity、端点、几何容差、允许 profile 和成本。
- 工具验证端点可达、方向合法、引用的 layer 存在；不能自动把坏 Link 降级为直线。
- Link 数据必须被 CLI、Editor Bridge 和 Runtime 读取同一份源。

### 3.3 Runtime 功能

- Query service 在 NavMesh path 和 Link graph 之间建立明确边界。
- Link 可用性按 profile、layer、方向和运行时状态过滤。
- Link 关闭时使引用它的路径失效；端点改变时重新绑定可行面。只有附带真实结构几何变化时才提交 dirty。
- 查询结果记录经过的 Link identity，MassNavigation 负责执行动作，不由 NavMesh 直接移动实体。

## 4. 场景与 Showcase 设计

### 一句话与目标用户

跳过断口，需要一条可执行的连接。

面向地图作者和首次体验该能力的玩家。空间与动作能力：开关单向跳台连接、改变允许单位，观察路径段及实际跨越。

### 主循环

0–15 秒：选择跳跃单位，点击对岸。15–35 秒：关闭 Link，重发命令并看到不可达。35–60 秒：打开 Link，再用不具备动作的重装单位尝试。惊喜时刻：跳跃单位真实执行动作落地，重装单位得到明确限制。

### 消融对照

同场景开启/关闭 authored Link，保留两侧可行面。关闭时请求不能凭空跨空隙；途中关闭要按动作执行合同完成或中止，随后重新规划。

### 解释层

单向箭头、禁用灰线、路径上的 Link 段橙色；HUD 显示 Link 身份、方向、条件、代价、动作阶段和失败原因。

### 旋钮清单

以下为目标演示中可在同一会话操作的控件；取值由场景配置或正式 API 约束。需要重烘焙的几何变更明确展示任务过程，不能伪装成立即生效。

主演示断口跳台；子场景：单向连接、无效端点、执行中关闭。首屏：“让跳跃单位去对岸，再关掉橙色连接重试。”

## 5. 边界

Link 状态切换只更新连接可用性和引用路线；单纯移动端点只重绑定，不自动重烘焙地形。只有真实结构几何变化才走脏区重烘焙。NavMesh 不承担跳跃动画或实体瞬移。

## 6. UAT

```gherkin
Feature: NavMesh Link 提供非连续连接

  Scenario: 开启跳台后单位实际跨越
    Given 玩家选中可以跳跃的单位
    And 两岸之间声明了有效跳台连接
    When 玩家开启连接并命令单位前往对岸
    Then 路径高亮跳台段
    And 单位执行跳跃并落在对岸可行面
    And 玩家看到动作完成后继续行走

  Scenario: 关闭 Link 后目标不可达
    Given 玩家关闭同一个 Link
    When 玩家再次查询路径
    Then 查询返回不可达
    And 系统不生成跨越空隙的直线路径

  Scenario: 跨越途中关闭连接
    Given 单位已经开始跳跃
    When 玩家关闭该连接
    Then 界面说明正在完成还是中止该次动作
    And 单位按动作规则落地或返回有效位置
    And 后续命令重新规划且不会瞬移过断口
```

这些场景描述目标验收，不是已通过的测试记录。
