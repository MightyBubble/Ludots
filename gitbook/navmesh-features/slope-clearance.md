# 坡度、台阶与净高

> [功能目录](README.md) · [体系总合同](../navmesh-ssot.md)
>
> 第 1–6 节定义目标产品与设计验收；当前可用范围、分支成果和剩余工作只看第 7 节。本文不新增第二套数据或运行管线。

## 1. 概述

这项能力决定“这类单位能不能通过这段几何”。坡度以度数表达，台阶与爬高以厘米表达，净高描述单位顶部与上方表面的距离。它只负责几何可行性，不负责区域代价、水面语义或跨表面连接。

证据入口：`src/Core/Navigation/NavMesh/Bake/RecastNavTileBaker.cs`、`src/Core/Navigation/AgentProfiles/AgentProfileConfig.cs`。

## 2. 结构

高度源提供坡面与上下表面，profile 给出阈值，Recast 根据几何生成可行面。坡度用度；爬高、身高及净空用 cm。ClearanceCm 的既有含义应与身高净空分开核对，不能把字段名当作完整净高能力。

## 3. 详情

### 3.1 编辑器功能

- 几何约束面板按 profile 显示最大坡度、最大爬高和最小净高，并显示单位。
- 预览层用不同颜色标出平面、超坡、超台阶和净高不足；每个颜色都有图例。
- 作者点击一处失败区域时，面板显示实际坡度/高度/净高与 profile 阈值。
- 没有上方表面数据时，净高显示“数据缺失”，不能显示为可通行。

### 3.2 工具功能

- 由 agent profile 和同 Id 的 bake profile 组合几何输入；estimate 与 bake 使用同一校验，不重复定义半径、身高等字段。
- 领域和作者配置使用厘米与度；第三方 Recast 所需米制换算集中在算法适配器，不在 CLI 和编辑器重复换算。
- 工具输出受影响 tile、失败原因和需要补充的几何源；不以默认高度替代缺失的上表面。

### 3.3 Runtime 功能

- NavTile 只发布已经通过几何约束的面；查询结果不再重新猜测坡度。
- profile 变化会改变产物 hash，需要重新烘焙；运行中的实体不会静默切换到另一个 profile。
- 净高场景依赖上下表面几何。请求门廊/天花板净空判定而源仅有单层高度时，报告该场景不支持；不影响已有无上覆结构的地面导航。

## 4. 场景与 Showcase 设计

### 一句话与目标用户

坡、台阶、矮门，各有明确的通行门槛。

面向地图作者和首次体验该能力的玩家。几何能力：选择预先烘焙、只相差一个能力参数的单位，观察三种障碍的通行差异。

### 主循环

0–15 秒：选普通步兵走缓坡。15–35 秒：改选爬高能力更强的预设并走台阶。35–60 秒：在低门廊让高、矮两种单位去同一终点。惊喜时刻是高单位绕开低门廊，矮单位穿过。阈值切换消费已烘焙产物，未知组合明确要求重烘焙。

### 消融对照

并排比较只差一个阈值的两种有效 profile；只改坡度、爬高或身高之一，其余相同。两侧都走正式几何管线，不关闭碰撞来伪造通过。

### 解释层

超坡红色斜线、台阶黄色边、净高不足紫色框；HUD 显示实际值/允许值、单位、路径与到达状态。无上表面数据用灰色说明。

### 旋钮清单

以下为目标演示中可在同一会话操作的控件；取值由场景配置或正式 API 约束。需要重烘焙的几何变更明确展示任务过程，不能伪装成立即生效。

### 场景结构

主演示三段道路；每种几何有独立子场景和参数对照。首屏：“选择一种障碍，再派两个能力不同的单位通过。”

## 5. 边界

单高度场只提供一个底面高度，不能描述天花板。净高场景必须等待多表面几何接入；没有上表面时只能报告该场景不支持净高判定，不能声称整个地面导航都不可用。

## 6. UAT

```gherkin
Feature: 几何约束决定路径是否可行

  Scenario: 超过最大坡度
    Given 一段坡度高于当前 profile 的道路
    When 玩家查询穿过该道路的目标
    Then 查询显示坡度超限
    And 不返回穿越该道路的路径

  Scenario: 净高数据缺失
    Given 地图只有底面高度而没有上方表面数据
    When 玩家查询低门廊下方的目标
    Then 系统显示该门廊缺少净高判定数据
    And 不把本次净高验收标为通过

  Scenario: 爬高能力决定是否走台阶
    Given 普通步兵不能跨过场景中的高台阶
    And 另一种单位具备通过该台阶的能力
    When 玩家让两者前往台阶后的营地
    Then 普通步兵绕路到达或明确显示不可达
    And 另一种单位越过台阶并抵达营地
```

这些场景描述目标验收，不是已通过的测试记录。
