# 引擎管线宪法：六不变量与一条管线

**跨线结构正本。** 输入→下令、UI 面板、Activity 内容、呈现四条线，合同各自写域字段；跨线结构冲突时，听本页。
各线的进度与还开着的活，只认 [图能力唯一入口](graph-capability-status.md)（四条线登记在同一页）。
管线图与交互链图在门户「输入与 UI」页（`docs/input-ui.html`），图纸源文件在 `docs/diagrams/`。

---

## 1. 一条管线

一切交互与一切内容，走同一条管线：

```text
刺激收敛 → context 门控 → 图（唯一行为载体）→ 单写者落账 → 呈现订阅 → scope 清理
```

- **刺激收敛**：设备输入、时间/内容时刻表、面板事件，收敛为语义动作，归因到 seat 对应的 rep 实体。设备物理输入是玩家才有的，可以跳过——bot 从语义动作层以上任意层切入。
- **context 门控**：rep 实体上的活跃 `InteractionContextInstance` 链决定此刻哪些语义成立。本机的「键 → 语义」表是交互状态 ⊞ 控制方案的投影，不进实体、不进存档。
- **图**：激活边、条件求值、结算、意图组装全部在图里。图之外没有第二个固定执行器替谁做决定。
- **落账**：属性、集合（owner = rep）、Activity 实例。每个存储一个写者。
- **呈现**：presenter 与面板只订阅，读图写好的同一份账，零计算。
- **清理**：context 是 scope 容器——停用整组清（含子），owner 死集合清。作者不手工 push/pop。

## 2. 六不变量

各线合同都是这六条的投影。出处只标最早成文的位置；表述以本页为准。

### 不变量一：世界状态只住实体

context 实例、Activity 实例、集合、属性都在实体上——观战能读，回放能放。设备、键位、控制方案是本机投影，不进实体、不进存档。
违例判据：把「键 → 语义」表当世界状态存档；观战切 seat 读不到对方交互状态。
出处：输入概念宪法 §8（`mods/showcases/case_e_selection/CaseESelectionMod/docs/input-command-system.html`）；Activity v5 不变量一（#1394）。

### 不变量二：行为只在图里

激活边、条件求值、选项结算、意图组装都是图。声明字段要获得语义，只有两条路：通用解释图读它，或者它是机械状态机（准入、超时翻态）。禁止第三条路——对象内私有 C# 解释器。
违例判据：某声明字段只在引擎某个 C# 对象的方法里有含义；图体内出现该字段的影子逻辑。
出处：Activity v5 不变量二、三（#1394）；输入配置宪法 §03 动静分离。

### 不变量三：单写者 + 生命周期主人

集合只有 `CollectionApplier` 一个写点；面板显隐只有 `PanelActivationApi` 一个写者。每个状态有生命周期主人：context 退按声明清，owner 死整组清。不存在第二扇写门，不存在孤儿状态。
违例判据：同一事实两处可写；退出某状态后其产物残留（画面孤儿、脏集合）。
出处：输入配置宪法 §00 不变量一、二；面板显隐合同（#1014 落地形态）。

### 不变量四：呈现只订阅

面板与 presenter 读同一份账渲染，不判命中、不算集合成员、不写世界状态。一切指示器（瞄准圈、蓄力条、选中环、屏幕框）= presenter 定义 + 规则订阅 + 参数绑定。
违例判据：呈现层调用判定或几何内核；表现域出现「谁进框、何时清」的决策代码。
出处：输入配置宪法 §10；[面板视图投影](panel-view-projection.md)。

### 不变量五：输入收敛为语义动作，消费由活跃 context 决定

设备按键、面板点击、bot 决策在语义动作层汇合。语义动作之后两去向：**A 支**（一切非下单消费——对话、菜单、UI 交互、框选写集合）到图为止，不出意图不下指令；**B 支**（往世界下令/放技能）经意图缓冲进下单管线。输入归不归 UI，由活跃 context 决定，不由 UI 可见性决定。
违例判据：「UI 打开所以吃掉输入」的独立抑制开关；面板点击绕过语义动作直写世界。
出处：输入概念宪法 §4、§5；commandSystem.md 对 UiCaptured 退役的裁定。

### 不变量六：定义与实例分离

profile / 模板 / definition 是静的；激活边与使用是动的，只发生在图与运行时。激活边唯一声明点是图的 `ActivateContext(parentContext: ...)`，激活那一刻校验。定义文件里禁止出现激活边。
这条撑起三件事：设备热插拔（只换控制方案重解析绑定，交互状态不动）、确定性回放、观战。
违例判据：视图工件声明交互拓扑（面板模板指向具体 context）；定义文件里藏着「谁激活谁」。
出处：输入概念宪法 §3.3.1；输入配置宪法 §03。

**元规则**（贯穿全部合同）：fail-closed、具名拒绝、零隐式回退——没有默认键、没有静默截断、没有双认旧名。

## 3. 三条线落在管线上

| 线 | 刺激 | 门控 | 行为 | 落账 | 呈现 |
|---|---|---|---|---|---|
| Case E 选择/下令 | 设备边沿（按下/抬起） | battle / boxing profile | box_begin、box_commit、提交图 | `selected` 集合 | 环、屏幕框 presenter |
| Activity 内容 | 发射时刻表、信号 | 作用域（scopeDomain + scopeKey） | 通用解释图 / 自写图 | Activity 实例、Task | 选项面板、事件面板 |
| UI 交互（目标态，#1585/#1586） | 面板按钮、手柄焦点 | UI context profile（bindings + 指针路由） | 事件消费图（A 支） | 对话选择、设置值 | 面板按 scheme 重渲染 |

## 4. 进门费五问

任何新能力开工前必答，答案写进 issue：

1. 状态住哪个实体？
2. 行为在哪张图？
3. 谁是单写者？
4. 呈现订阅什么？
5. 输入/刺激在哪一层收敛？

有一问答「新机制」，先修本页再写代码。

## 5. 退役面

| 退役/禁令 | 状态 |
|---|---|
| `UiCaptured` / `UiWheelCaptured` 服务旗子 | 裁定退役归一为 Input Context 机制；输入归属由活跃 context + 宿主只读投影决定（#1585 待实施） |
| 视图持有交互状态、面板模板声明交互拓扑 | 禁——面板最多声明生命周期种类，scope 由实例绑定传入（#1586） |
| 第二条事件准入路（浏览器控件绕过语义动作直写） | 禁——四皮一面墙，浏览器控件汇入同一事件桥（RFC-0067 / #1494） |
| 定义文件里出现激活边 | 违宪（输入配置宪法 §03 原文），装载即拒 |
| 声明字段的私有 C# 解释器 | 禁（Activity v5 #1394 不变量三） |
