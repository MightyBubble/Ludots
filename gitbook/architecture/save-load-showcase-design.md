# 存档读档 showcase 设计

## 一句话与目标用户

退出游戏再进来，世界还能原样回来——给没读过存档代码的作者和玩家看。

## 主循环

谁改变世界：玩家挪单位、消耗资源、或点「推进世界」让场景自己动。  
用户看到什么变：单位位置、实体数、槽位列表里的 tick/字节数随存档更新；读档后绿标标出「回来了什么」。  
惊喜时刻：点「模拟冷启动读档」——不靠当前内存，从真实落盘文件把世界捞回来，落盘路径一直挂在屏幕上。

## 消融对照

同一场景一键切：
- **无存档重置**：丢掉进度，回到出厂摆位；
- **有存档恢复**：读刚写下的槽，单位还在你挪过的地方。

用户一眼看出「存档」解决的是重置痛，不是多一个按钮。

## 解释层

- HUD：当前 tick、实体数、选中槽位的 header（来自 `SaveSlotStore`，不造第二份数据）；
- 读档对比：回来了的位置/实体数 = 绿；挂了 `SaveExcludedTag` 不进档的 = 灰；
- 落盘根路径常显；
- 图例：绿=读档回来，灰=故意不进档，红=校验失败。

## 旋钮清单

| 旋钮 | 范围 | 演示什么 |
|------|------|----------|
| 槽位选择 | 多 manual 槽 | 槽位互不覆盖 |
| autosave 保留数 | 1–5 | 轮换只删自动档，manual 永不删 |
| 篡改槽位 | 一键弄坏文件 | 校验闸门 fail-fast，错误可读 |
| 排除实体 | 给演示单位挂/摘排除标记 | 什么不进档看得见 |

## 场景结构

- 主演示：RTS 岸线小场景 + 通用存档面板（`SavePanelMod`，零拷贝）；
- 子场景：冷启动读档、篡改拒读、排除实体；
- 首屏：「挪单位 → 存档 → 再挪 → 读档看绿标回来；想看冷启动就按那个按钮。」

## Cucumber UAT

```gherkin
Feature: 退出再进，世界原样回来
  Scenario: 存档后读档，单位回到存档点
    Given 我打开存档演示并挪动了单位
    When 我写入一个手动槽位并继续挪动
    And 我读回该槽位
    Then 单位回到存档点，对比里标成绿色

  Scenario: 无存档重置与有存档恢复对照
    Given 世界已被我改乱
    When 我切换到无存档重置
    Then 场景回到出厂摆位
    When 我再切回有存档恢复并读档
    Then 场景回到存档点而不是出厂

  Scenario: 弄坏槽位文件时读档失败可见
    Given 已有完整槽位
    When 我篡改该槽位文件并读档
    Then 面板用红色错误说明哈希校验失败，世界不被悄悄改写
```
