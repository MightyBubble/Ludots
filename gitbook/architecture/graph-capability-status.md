# 图能力现在走到哪

新来的人先读本页。别从旧审计、旧交接、旧票号开始猜。

写技能、写行为的规则看这两页：[图怎么分层](graph-layering-flow-and-behavior.md)、[纯计算和可挂起动作怎么分开](graph-funclib-actionlib-contract.md)。那两页是规矩。本页只说**现在做成什么样了、还剩什么、别重做哪些**。

旧审计在 `docs/audits/`。那是当时记下的证据。和本页打架，听本页的。

---

## 1. 概述

**进游戏能玩的，这轮收好了。工程分层没有拆完。总规矩仍写「修复中」，别改成做完了。**

打开启动器，每个图节点自己一间短剧，大约一百二十间。没有「属性族 / 查询族」那种大杂烩房间，也没有「已退役、进不去」的灰卡。

走进「残血的分更高」：两根木桩离队友一样远。队友按打分图选残血。字幕点名残血木桩，并写出这一刀的分。残血掉血，满血不动。

点开加减乘钳那几间：字幕说的是示意条，不是结算出来的伤。

写技能的人：一张图不能自己调自己把游戏弄没；查询图不能偷偷挂上「等一拍」的动作；写进生命的数不会过两拍自己变回去。

写行为的人：巡逻树、门岗状态机可以写在配置里。

维护工程的人：解决方案里多了两份薄的契约工程，核心工程还是原来那一大坨。展厅代码大多还能一把抓住整台引擎。分层只搭了架子，墙没砌完。

## 2. 结构

```text
玩家能看见的
  一节点一间短剧
  残血的分更高
  没有家族大杂烩，没有退役灰卡

作者能依靠的
  自己调自己会被拒绝
  查询图不能偷挂会等一拍的动作
  行为可以写在配置里

还没做完的
  工程分层只搭了架子
  Moba 护盾演示启动会红
  有一条内存门槛测不过
  有一条干净构建会打架

别去做的
  别再开一轮「先审再修再审」
  别把大杂烩房间变相加回来
  别把打分短剧再另算一遍分
  别把「修复中」改成「已落地」
```

要找具体房间，看 [能力标准展厅](capability-standard-showcases.md) 和启动器登记表 `showcase.registry.json`。  
打分短剧怎么验收，看 [残血的分更高](../acceptance/graph-score-wounded-priority.md)。  
分层以后怎么拆完，看 `docs/audits/s14_layering_physicalization_design.md`。那是施工图，不是「已经拆完」。

## 3. 详情

### 3.1 已经做好、别重做

- 每个还能运行的图节点，都有一间能看懂的短剧。
- 按家族打包的八间大杂烩已经删掉。不是「退役、卡片还在」。
- 「残血的分更高」能玩。字幕只读这一刀选人时记下的人和分，不再另跑一遍打分。
- 加减乘钳那几间，文案说清楚了：示意条，不是结算。
- 自己调自己的图，登记时就拒绝。
- 写进属性的数，不会被后面的重算偷偷改回去。
- 查询图只填一张会等一拍的动作图、不填函数名，编译失败。
- 容量到顶必须报错，不能装没看见。
- 点人、下令看的是战场上的位置，不是镜头有没有挡住。
- 覆盖表写「测过了」，就必须真跑到那个节点。
- 行为树和状态机可以写在配置里。哨兵机挂「等一拍」会在加载时失败。

这些都已经在主干上。看见旧审计还在说「门没锁 / 打分没合 / 房间只是退役」，那是过期句子，以本页为准。

### 3.2 分层停在哪

一句话：**架子有了，墙没有。**

有了：两份只放约定的薄工程；阶段先后收成一张表；登记表开始跟某一台引擎走；展厅上下文多了两个口。

没有：结算约定、展厅约定还没拆出去；核心工程没拆；展厅几乎还在拿整台引擎；开两张地图时，全进程仍认最后绑上的那一份表；所谓清空，常常只是换一张没冻过的新表。

还没做的大活：把空间、输入、画面、结算真正拆开；禁止再一把抓住整台引擎。要做就单独开活，对照施工图，别和修展厅、修 Moba 捆在一起。没做完之前，总规矩继续写「修复中」。

### 3.3 还要修的

先修玩家能撞上的：

1. **Moba 护盾演示启动会红。** 护盾图读血的入口写错了。曾经有过修复，关了没合。跟踪：[护盾读血写错](https://github.com/MightyBubble/Ludots/issues/916)。
2. **有一条「不许乱占内存」的门槛过不去。** 别为了变绿把门槛放宽。跟踪：[内存门槛](https://github.com/MightyBubble/Ludots/issues/917)。
3. **干净构建时同名文件打架。** 跟踪：[干净构建拷贝失败](https://github.com/MightyBubble/Ludots/issues/918)。

总账还开着，先别关：

- [图节点都要能写、能测、能看见](https://github.com/MightyBubble/Ludots/issues/915) — 画廊和一批门已经合了，上面三张旧债还在，总规矩仍是修复中。
- [作者只走一条边、只进一扇门](https://github.com/MightyBubble/Ludots/issues/861) — 配置写行为补了一截，总账没收工。

下面这些是早就知道、还没做的，**不要当成新发现再开一轮审查**：默认那两片「看见敌人 / 进入射程」还要有人先塞数字；图号在代码里还是普通整数；有一条事件丢弃计数永远是零；两个节点钉同一格时诊断不全。

### 3.4 别当成这轮图能力去合

- 一份已经被后来审计取代的草稿需求，还开着。卫生上该关，不是功能缺口。[草稿](https://github.com/MightyBubble/Ludots/pull/961)
- 打分预算是另一件事。打分短剧已经能玩，别和预算捆在一起。[预算](https://github.com/MightyBubble/Ludots/pull/723)
- 面板是另一条线。[面板债](https://github.com/MightyBubble/Ludots/issues/886)
- 助手工具无关。[Pi](https://github.com/MightyBubble/Ludots/pull/947)

### 3.5 两份自审别盖掉

写脚本方言拓宽时的自审正本在 `artifacts/gas-composition-gate.md`。后开的活不许拿自己的自审覆盖它。

打分短剧自己的自审在 `artifacts/gas-composition-gate-graph-score-showcase.md`。

## 4. 场景

1. 我打开启动器。我看到大约一百二十间短剧。我看不到「属性族」这种大杂烩，也看不到「已退役」灰卡。
2. 我走进「残血的分更高」。我不用点技能。我看见字幕点名残血木桩，并写出这一刀的分。残血掉血，满血不动。
3. 我点开「伤害钳在上下限里」。详情告诉我这是示意条从多少掉到多少，没有把它说成结算出来的伤。
4. 我在查询图里只填一张会等一拍的动作图，不填函数名。编译失败，游戏还在。
5. 我打开工程。我能看见两份薄的契约工程。核心工程还是一大坨。总规矩第一行仍是修复中。

---

## 5. 边界

- 本页只说进度。改规矩去那两份合同页。
- 不准把「多了两份薄工程」写成「分层做完了」。
- 不准把已经删掉的大杂烩写成「退役、进不去」。
- 不准把「残血的分更高」写成还没合。
- 旧审计不准再自称「现在怎样」。过期了就改正文。
- 有具体房间坏了、具体演示启动不了，再开活。不要为了再审一遍而再审一遍。

## 6. UAT

```gherkin
Feature: 新人先看懂现在怎样

  Scenario: 启动器里没有大杂烩
    Given 我是第一次打开启动器的人
    When 我翻展厅列表
    Then 我看到每个图节点自己一间短剧
    And 我看不到按家族打包的房间
    And 我看不到「已退役」卡片

  Scenario: 残血的分更高能看懂
    Given 我走进「残血的分更高」
    When 我站着看完第一刀
    Then 字幕点名残血木桩
    And 字幕写出这一刀的分
    And 残血木桩的血往下掉
    And 满血木桩的血不动

  Scenario: 没有人告诉我分层已经做完
    Given 我打开工程，看见多了两份薄的契约工程
    When 我去看「纯计算和可挂起动作怎么分开」的第一行
    Then 上面写的是修复中
    And 没有写成已经落地

  Scenario: 旧本子不能骗我
    Given 我翻到一份旧审计
    When 它和本页说的不一样
    Then 我按本页做
```
