# 服务器权威联机运行时

## 1. 概述

Ludots 联机的唯一正式入口是平台无关的服务器权威运行时。一个对局由一个独立权威进程和若干独立客户端进程组成；桌面、浏览器或商业引擎宿主只能提供传输和呈现适配，不能拥有玩家身份、订单裁决、迷雾披露或战局恢复规则。

本页描述 [Epic #709](https://github.com/MightyBubble/Ludots/issues/709) 已确立的运行时边界。玩法验收基线是《双人前线》：两名真人在同一权威战局中完成采集、生产、指挥、战斗、胜负和短线重连。

## 2. 结构

```text
客户端交互 -> 语义命令 -> 可靠命令通道
                            |
                            v
独立权威进程 -> 会话席位 -> 唯一 NetworkCommandIngress -> 唯一 OrderQueue
                            |
                            v
                       权威固定步提交
                            |
                            v
                 按玩家知识披露构建状态
                            |
              +-------------+-------------+
              |                           |
       可替代增量状态通道           可靠完整快照分片
              |                           |
              +-------------+-------------+
                            v
                     客户端副本世界
```

- Core：会话、席位、命令接纳、网络实体、知识披露、基线、重同步和运行时状态机。
- 传输适配器：真实连接、收发字节、通道可靠性和连接事件。
- 宿主：创建进程角色，安装对应运行时，展示玩家可理解的连接与战局状态。
- Showcase Mod：地图、单位、经济、胜负和表现；不创建第二套联机基础设施。

## 3. 详情

### 会话与命令

服务端依据已握手连接绑定玩家席位，报文不能提交可信 `PlayerId`。握手必须校验协议版本、内容指纹和会话 epoch。命令携带客户端单调序号、目标执行帧、网络实体句柄和数据驱动的订单类型；服务端校验代际、控制权、玩家知识、载荷形状、执行窗口和整批容量后，才进入唯一订单队列。

命令和回执走可靠顺序通道。大编队命令使用固定容量分片；缺片、混批、重复内容冲突或容量不足都明确失败，不能截断、部分接纳或改走本地世界。

### 状态复制

实体在网络上使用 `slot + generation`，不暴露 Arch 实体编号或表现编号。服务端为每个席位独立维护披露集合、已确认基线和快照序号。视野外敌军可以是“未知”或最后已知状态，但不能发送实时位置、生命或队列。

单包增量可以走只保留最新的状态通道。完整快照和任何分片快照必须走可靠顺序通道；基线缺失时先进入明确的 `ResyncRequired`，随后发送完整同步。

客户端复制采用严格的 Prepare / Commit 边界。每个 schema 在 Prepare 阶段必须无副作用地说明提交后的空间状态：给出世界厘米坐标，或明确声明该实体不进入空间索引。schema 只负责解释自己的载荷；当前地图边界、空间成员状态和索引生命周期仍由 Core 空间服务统一判定，不能在 Showcase Mod、宿主或适配器内重复实现。

绑定已有实体、创建、更新、隐藏、释放和整批清空必须先完成 schema 与空间预检。批次中任一实体越界、空间状态非法或 schema 无法给出完整预览时，整批在修改 ECS、空间索引、镜像槽位、知识披露和复制基线之前明确失败。禁止在提交中捕获异常后猜测回滚，也禁止跳过索引、强制可见或把对象移动到默认坐标。通过预检后的 Commit 只执行已经验证的操作；schema 或空间实现违反预览合同属于内部错误，不得降级处理。

### 生命周期与重连

传输断开后，席位进入等待重连状态，已接纳的权威玩法继续。重连凭据由服务端签发并由平台适配器原子持久化。席位过期必须先输出待释放席位，再同步清理命令入口、复制基线、披露状态和发送状态，最后才允许槽位复用。

客户端重连成功后先接收完整当前状态，再恢复输入。权威进程退出时客户端结束对局；不得切换成本地权威或自动生成电脑玩家。

### 容量与热路径

席位、命令批次、单批单位数、网络实体、结果、分片、基线和收发队列都来自版本化 networking 配置，并在启动时一次性校验和预分配。命令调度、状态投影、编码、解码与应用的稳态路径使用数组、Span 和固定容量缓冲，不在每帧扩容或创建集合。

## 4. 场景

- 两名玩家都就绪后看到 3 秒倒计时，随后进入同一张镜像地图。
- 客户端取得席位和正式战场副本后，第一帧聚焦自己的指挥核心，并能看到本方采集车和步兵；未建会话的空客户端画面不能作为联机证据。
- 玩家框选自己的步兵下达移动或攻击命令，先看到发送状态，再看到服务器接纳与实际执行结果。
- 敌军离开视野后，客户端不再收到其实时生命和位置。
- 玩家短暂断线时，对手看到离线状态；30 秒内回来后看到当前战局，旧命令不会重复执行。
- 权威进程关闭时，两个客户端都明确结束对局，不在本机继续推进战局。

## 5. 边界

- 不在 Core 引用 Socket、Raylib、浏览器或商业引擎类型。
- 不用浏览器 API 定义联机能力；浏览器只能实现与桌面相同的适配器合同。
- 不做客户端全世界权威模拟、普通 RTS 单位预测、主机迁移、匹配、账号或中继。
- 不把迷雾做成仅影响画面的遮罩。
- 不在 Mod 内创建身份表、网络队列、快照器、可见性扫描或重连状态机。
- 不用空世界、默认值、动态扩容或本地模式掩盖协议和容量错误。

## 6. UAT

```gherkin
功能: 客户端只展示完整且合法的战场复制结果

  场景: 一个越界状态不能破坏玩家当前看到的部队
    假如 玩家正在客户端中看到一辆位于战场内的采集车
    并且 该采集车仍可被选择且保持在正确位置
    当 客户端收到一份把该采集车放到地图外的状态
    那么 玩家继续在原位置看到同一辆采集车
    并且 采集车不会消失、跳到地图原点或留下不可选择的空壳
    当 客户端随后从同一已确认进度收到一份合法状态
    那么 玩家看到该采集车移动到新的合法位置

  场景: 一批状态中的坏对象不能先删除其他正常对象
    假如 玩家正在客户端中看到一组有效的战场单位
    当 下一批状态包含一个地图外对象
    那么 这一批状态整体不进入玩家世界
    并且 玩家原先看到的单位、位置和可选状态保持不变
```

```gherkin
功能: 两名玩家通过独立进程完成同一场 RTS 对局

  场景: 两名真人就绪后开始
    假如 权威对局进程已经启动
    并且 两个独立客户端已经加入同一房间
    当 两名玩家都选择就绪
    那么 两人都看到 3 秒倒计时
    并且 两人进入同一张地图
    并且 每人只能指挥自己的单位

  场景: 玩家在短暂断线后恢复当前战局
    假如 玩家正在采集并生产步兵
    当 该玩家的连接中断后在 30 秒内恢复
    那么 已开始的采集和生产继续
    并且 该玩家看到当前而不是断线前的战局
    并且 已确认的旧命令不会再次执行

功能: 玩家只能收到战场允许知道的信息

  场景: 敌军离开视野
    假如 敌军刚刚离开玩家视野
    当 敌军在视野外受伤或移动
    那么 玩家客户端不收到敌军的实时生命变化
    并且 玩家客户端不收到敌军的实时位置变化

功能: 联机失败不会伪装成本地游戏

  场景: 权威进程退出
    假如 两名玩家正在同一场对局中
    当 权威进程退出
    那么 两名玩家都看到对局已经中断
    并且 两个客户端都不再推进玩法结果
```
