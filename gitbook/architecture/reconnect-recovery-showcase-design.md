# 断线恢复 showcase 设计

## 一句话与目标用户

断线不是重开一局——给关心联机追回的作者看。本演示是**单机模拟断线**，联机专项未验收，屏幕上会写清楚。

## 主循环

谁改变世界：权威侧模拟继续走；断线后客户端冻结。  
用户看到什么变：权威 tick 与客户端 tick 分轨；重连后从权威检查点续上，恢复来源写在 HUD。  
惊喜时刻：重连一瞬间补上断线期间权威走过的进度——「错过了什么、从哪继续」一目了然。

## 消融对照

- **权威恢复**：从检查点/帧续跑，序列连续；
- **本地重置**：回到出厂，等于认输重来。

## 解释层

- 权威侧 vs 客户端侧时间线，断线区间高亮；
- 恢复来源：checkpoint tick / frame / digest；
- 故障帧：缺帧/重复/乱序/过期各自颜色与拒绝理由；
- 页眉固定：「单机模拟断线（联机专项未验收）」。

## 旋钮清单

| 旋钮 | 范围 | 演示什么 |
|------|------|----------|
| 断线时机 | 任意 tick | 随时断都能续 |
| 缺帧注入 | expected N / actual M | 缺帧拒绝可读 |
| 重复帧注入 | 同序号再塞 | 不重放 |
| 过期/乱序帧 | tick 倒流或序号跳 | 不倒流、不乱序吞 |

## 场景结构

- 主演示：在线 → 断线 → 权威仍走 → 重连续上；
- 子场景：四种故障帧拒绝；
- 首屏：「先看双侧时间线。断线后左边还在走；重连看从哪恢复。这是单机模拟。」

## 门户资产

- 封面取「重连补齐」瞬间；
- 文案必须带单机模拟声明。

## 反向 API 审计

| 缺口 | 归属 |

| CheckpointCoordinator / AuthoritativeFrame.Validate | Core 已有 |

## Cucumber UAT

```gherkin
Feature: 断线不是重置（单机模拟）
  Scenario: 断线后权威仍走，重连从检查点续上
    Given 演示页眉写明单机模拟断线
    When 我注入断线
    Then 客户端冻结而权威 tick 仍前进
    When 我重连并选择权威恢复
    Then HUD 标明恢复来源，帧序列从检查点继续而不是出厂

  Scenario: 缺帧被拒绝且理由可读
    Given 期望下一帧序号为 N
    When 我注入序号为 N+2 的帧
    Then 面板显示 expected/actual 拒绝理由，状态不被悄悄推进

  Scenario: 本地重置与权威恢复对照
    Given 断线期间权威已前进
    When 我选本地重置
    Then 回到出厂摆位
    When 我改选权威恢复
    Then 续上权威进度而不是出厂
```
